    v0.8.3 릴리스 정리와 문서 대조 기록

    기준선과 범위

    • 이전 버전: v0.8.2(3e8b0bfc80b845b2d4b2ed683994748741450a97).
    • 이번 원격 main 기준: 31c6055687d33f9ad7a92cf453a264ce13a1700d, 2026-10-13에 가져왔으며 commit은 총 282개입니다.
    • 초기 정리 브랜치: chore/release-v0.8.3-docs. 릴리스 PR 브랜치: chore/release-v0.8.3-website. 2026-10-14에 최신 github_public/main(3b3b519310721295162ea94b9fd62a92c8cab341)을 가져왔습니다. 집계 스냅숏보다 늘어난 #4278과 #4283은 기준선에 이미 있던 수정이며 이 PR의 새 코드가 아닙니다.
    • 버전 선택: 현재 0.8 시리즈를 이어 아직 쓰지 않은 다음 버전 0.8.3을 씁니다. 마이그레이션이 필요한 동작 변화가 있어 업그레이드 안내를 따로 두었습니다. 릴리스 날짜는 2026-10-14로 확정했습니다. 이 PR은 릴리스 문서와 버전 메타데이터를 갱신하며, tag와 GitHub Release는 릴리스 절차에서 만듭니다.
    • 검토 대상은 버전의 순 변경에 해당하는 사용자 문서, 설정/API 계약, 릴리스 내용입니다. 282개 commit 전체를 다시 보안 감사한 것은 아닙니다. 최종 동작은 해당 main 스냅숏의 소스 코드를 기준으로 하며, commit 제목은 전체 집계에만 씁니다.
    • 플러그인 시스템을 도입한 commit 11개는 6c83d7ab4로 철회했으며, 새 기능으로 릴리스하지 않았습니다. DeepSeek Harness 등 기존 외부 클라이언트 통합은 이 결론의 영향을 받지 않습니다.

    수정하고 보완한 내용

    주제기존의 오류나 누락소스 대조와 처리
    세션 첨부 파일파싱 시점과 읽기 시점을 구분하지 않았고 모든 첨부 파일이 24시간 후 만료된다고 했음. Agent 설명이 읽기를 샌드박스에 묶어 둠temporary_document.go, temporary_document_prompt.go, attachment/reader.go, repository의 expiredQuery. 업로드 후 백그라운드 파싱, Agent의 필요 시 읽기와 대기, Quick Answer의 스트림 시작 후 대기, 유효한 메시지 참조 유지를 정리하고 세션/Agent/API/설정 문서에 반영
    도구 선택빈 배열은 기본값으로 돌아가고, 스마트 추론은 최소 하나를 선택한다고 했음tools/allowed.go, custom_agent_tools.go, 마이그레이션 116/35. null과 []를 구분하고, 도구 목록 API, 알 수 없는 이름과 스위치 관리 항목 처리를 보완
    가입 정책빠른 시작, 개요, 설정, 시스템 설정이 여전히 invite_only를 초대 가입이라고 부름config/handler와 auth.registration_mode. 세 단계의 의미를 통일하고 업그레이드 조치를 따로 둠
    사용자 관리사용자 목록/활성·비활성 API가 없었고, 사용자 생성 진입점이 아직 계정과 접근에 있었음SystemSettings.vue, UserManagement.vue, system.go, router. 목록 페이지네이션, 비활성화 시 세션 취소, 보호 조건과 새 진입점을 보완
    갤러리저수준 이미지 처리 파라미터만 있고 사용자 흐름과 전체 API가 없었음knowledge.go, routes_knowledge.go, types/image_gallery.go. 갤러리 흐름, 속성 계약, GET/POST 필터와 ID별 상한을 보완
    이미지 검색스위치 요구 사항이 긴 저수준 설명 속에 묻혀 있었고 검색 진입점 개요가 없었음knowledgebase_search_image.go, 이미지 인덱스와 재순위화/답변 경로. 갤러리, 이미지 벡터, 텍스트 설명을 구분하고 기본값이 꺼짐이며 다시 파싱해야 함을 명시
    이미지 관찰대체 동작을 어떤 관찰 실수로도 내용이 사라지지 않는다고 잘못 적음image_attr_decision.go. on_unobserved로 대체 동작을 끌 수 있고, 완전하지만 틀린 음수 관찰값으로도 OCR을 건너뛸 수 있음을 설명
    모델Cohere를 추가했는데도 29개로 셌고, 확장 가이드에서 TEI/Pinecone 프로토콜이 빠짐providers의 Builtins/테스트가 30개로 명시. 숫자와 프로토콜 목록을 갱신하고 WeMM 기본 세션 배치 처리 설명을 보완
    데이터베이스전체 목록이 아직 PG 110 / SQLite 30에 머물렀고, SQLite에 MCP metadata가 없다고 적음마이그레이션 파일 111–118 / 31–36. 프로젝션 백필, 인덱스, OAuth 타임스탬프를 보완하고 기본 이미지와 첨부 파일 상태를 수정
    MCP 권한 부여문서가 권한 부여가 끝나면 서비스 연결 전체를 닫는다고 주장함CloseClientsAfterAuthorization. 현재 주체와 이전 client_id 연결 정리, 등록 정보 읽기 실패 시 보수적 대체 동작을 보완하고, 다른 사용자에게 절대 영향이 없다고 과장하지 않음
    로컬 스킬로컬 명령 실행만 소개하고 설치와 활성 버전을 빠뜨림tenant_skill_host.go, host_skills.go. 로컬 설치 대상, 버전 전환, 실패 시 이전 버전 유지를 보완
    Wiki/인용/스크린숏예전 이미지로는 새 그룹과 원문 위치 찾기를 보여 줄 수 없음설명을 갱신하고 실제 제품 스크린숏을 넣은 뒤 캡션을 대조. 과거 버전 이미지는 유지
    설정지식베이스 설명 예산과 아웃바운드 다이얼 타임아웃이 빠짐.env.example, config, 설명 생성 서비스. 기본값 2048 token과 5s를 보완하고 다이얼 타임아웃과 전체 요청 타임아웃을 구분
    릴리스 진입점홈페이지, 버전 내비게이션, 배지가 여전히 v0.8.2를 가리킴v0.8.3 페이지, 홈페이지 갤러리, 네 가지 README, 공유 내비게이션, 검사 스크립트, 현재 버전 메타데이터를 통일. 과거 설명과 독립 버전을 쓰는 의존성은 유지

    홈페이지 장기 콘텐츠 조정

    • 중국어 기능 이름은 프런트엔드와 같이 「画廊(갤러리)」로 통일했습니다. 갤러리와 멀티모달 Embedding은 홈페이지, 버전 설명, 지식베이스 가이드, 네 언어 README에서 따로 소개합니다.
    • 멀티모달 Embedding은 먼저 이 모델 유형을 지원한다는 점을 설명하고, Tencent WeMM-Embedding, Qwen3-VL-Embedding 등을 지원 예시로 듭니다. WeMM의 구체적인 프리셋과 배포 방식은 세부 내용에서 펼쳐 보이며, 활성화 조건과 기존 배포 문서 진입점은 유지합니다.
    • 로컬 브라우저는 버전 번호와 무관한 독립 그림·글 영역을 쓰고 실제 스크린숏을 재사용합니다. MCP Server는 생태계 통합으로, 대화 추가·분기·되돌리기는 Agent 개요로 옮겨 더 이상 같은 비중으로 보여 주지 않습니다. 스킬과 샌드박스, Wiki는 주제 섹션을 유지하며, Lite 로컬 프로젝트 디렉터리를 샌드박스 설명에 추가했습니다.
    • 언어 추가 같은 작은 업데이트는 더 이상 홈페이지 버전 보충란을 차지하지 않으며, 버전 설명에는 그대로 남깁니다. 홈페이지의 모델 공급업체 수는 30으로 수정했습니다.

    릴리스 표현과 과거 관례

    2026-09-23 Claude의 「v0.8.0부터 v0.8.2까지 문서 동기화 점검」 대화와 v0.8.2 버전 페이지를 참고했습니다.

    • 홈페이지는 용도 설명에 중점을 두고 짧은 문구에 큰 그림을 곁들입니다. 설정 전제와 프로토콜 세부 사항은 기능 문서에 둡니다.
    • 이번 버전 영역에는 네 가지 핵심 항목을 둡니다. 갤러리, 멀티모달 Embedding, Wiki 그래프, 원문 인용 위치 찾기입니다. 왼쪽에는 간결한 기능 내비게이션, 오른쪽에는 스크린숏을 배치하고 네 항목 설명을 모두 펼쳐 두어 설명과 그림이 한 화면에 보이게 합니다. 첨부 파일 필요 시 읽기, 플랫폼 사용자 관리, Seafile, Docker 터미널은 보조 링크로 둡니다.
    • 홈페이지 01–07과 사용 진입점은 배경 교차, 전체 폭 배경, 콘텐츠 컨테이너, 섹션 간격을 통일합니다. 밝은 배경 영역에는 구분선을 일관되게 두고, 다크 모드는 테마 변수를 재사용합니다.
    • 로컬 브라우저는 독립 주제 섹션을 유지합니다. 「작업 실행／확장 연결」 그림 두 장, BrowserSkill 아이콘, GitHub 진입점을 되살렸습니다. 왼쪽에는 「작업 실행」「확장 연결」 설명을 각각 펼치고 오른쪽에서 해당 스크린숏을 전환하며, 스킬 샌드박스와의 경계와 배경 구분을 보완했습니다.
    • 버전 페이지는 사용자가 무엇을 할 수 있는지를 기준으로 구성하며 업그레이드 조작과 제한 사항을 남깁니다. commit 수, 스냅숏, 철회 기록은 이 보고서에 남기고, 전체 기술 업데이트는 CHANGELOG를 참고합니다.
    • Wiki 그래프 렌더링과 상호작용 조정은 버전 장으로 따로 둡니다. #4147의 그룹 레이아웃, 주제 설명, 라벨 회피, 그룹 전환, 전체 그래프로 돌아가기를 대조했고, 홈페이지 Wiki 주제의 첫 항목에는 그룹 그래프 실제 스크린숏을 씁니다.

    2차 전체 재검토(2026-10-14)

    • v0.8.2부터 정해 둔 main 스냅숏까지의 commit 282개를 기준으로 홈페이지와 버전 페이지를 다시 대조했습니다. 릴리스 기준선은 바꾸지 않았습니다.
    • 홈페이지 생태계 목록에 Seafile을 추가하고 프런트엔드의 기존 아이콘을 재사용했습니다. 스킬 주제에 macOS Lite 로컬 설치를 보완했습니다. Docker/E2B/Cube 모두 터미널이 있으며, 그래픽 데스크톱은 E2B/Cube 데스크톱 템플릿에만 해당함을 명시했습니다.
    • 버전 페이지에 공유 에이전트가 호출자의 로컬 브라우저를 조작하는 기능, 도구 목록 검색, 검색 파라미터와 진단, 채널 세션 관리, 모델 완료 이벤트의 실제 모델 ID를 보완했습니다. 지식베이스를 넘나드는 Wiki 검색은 API 기능임을 명시하고 Wiki 장으로 되돌렸습니다.
    • 스캔한 PDF는 페이지 전체에 이미지 벡터를 만들지 않는다는 점, 원문 인용의 접근 권한과 원본 파일이 없을 때의 대체 동작, Seafile은 암호화되지 않은 단일 라이브러리만 지원하고 SeaDoc은 지원하지 않는다는 경계를 보완했습니다.
    • CHANGELOG가 #3950의 엔터티 지식 그래프 방향/출처 수정을 Wiki로 잘못 분류한 것을 바로잡고, 두 종류의 그래프를 각각 설명했습니다.
    • Swagger 원래 생성물에서 기존 경로 10개가 빠져 있었습니다. go.mod와 같은 swag v1.16.6으로 다시 생성했습니다. 모델 카탈로그 읽기/미리 보기/게시 인터페이스 3개(경로 2개)의 주석을 보완해 관리자 JWT 전용, 버전 충돌, JSON overlay 객체를 올바르게 선언했습니다. spans 주석에서 API 기본 경로가 중복되고 인증 선언이 빠진 문제도 고쳤습니다. 세 가지 생성물은 모두 make docs로 만들며 생성물을 손으로 고치지 않습니다.
    • 이번에 새로 추가한 백엔드 변경은 Swagger 주석과 schema 태그뿐이며 인터페이스 동작은 바꾸지 않습니다. 계약 검사는 새로 게시한 인터페이스, 기본 경로 중복 금지, overlay 객체 타입을 다룹니다.
