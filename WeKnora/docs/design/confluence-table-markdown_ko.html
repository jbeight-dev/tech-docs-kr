    Confluence 페이지 표 변환 개선 분석

    배경과 범위

    Confluence 커넥터는 페이지 API에서 HTML 본문을 받아 Markdown으로 변환한 뒤, .md 파일로 지식베이스 파싱 흐름에 넘깁니다. 이전에는 html-to-markdown/v2의 패키지 수준 변환 함수를 바로 호출했기 때문에 표 셀이 일반 텍스트가 되어 행과 열의 관계가 사라졌습니다.

    이번 작업은 Confluence 페이지 본문의 표만 다룹니다. 이미지, 매크로, 페이지 링크 등 다른 내용은 범위에 포함하지 않습니다. 해당 기능 요청은 Tencent/WeKnora#4794이고, 기존의 종합 이슈는 Tencent/WeKnora#3856입니다.

    변환 방식

    1. 페이지 전체 HTML을 변환하기 전에 원문 위치를 기준으로 완전한 <table> 블록을 찾아내고, 고유한 자리 표시자로 잠시 보호합니다.
    2. 표를 제외한 본문은 기존 변환기로 처리해 제목, 단락 등의 기존 동작을 유지합니다.
    3. 중첩되지 않은 표에는 docparser.NormalizeHTMLTables를 재사용합니다. 일반 표는 GFM Markdown으로 변환하고, 병합 셀이 있거나 GFM으로 안전하게 표현할 수 없는 표는 HTML 구조를 유지하되 각 행을 별도 줄로 나눕니다. 중첩된 표는 원본 HTML을 통째로 유지하고 마찬가지로 행마다 줄바꿈을 넣어, 범용 정규화기가 바깥쪽 표를 잘라 먹지 않게 합니다.
    4. 원래 순서대로 표를 다시 채워 넣어 표와 인접 본문의 위치가 어긋나지 않게 합니다.

    이 방식은 Confluence 가져오기, 증분 커서, 지식베이스 적재 인터페이스를 바꾸지 않습니다. 기존 문서의 원본 Markdown을 다시 만들려면 Confluence에서 전체 동기화를 해야 합니다. 이미 저장된 예전 .md를 다시 파싱하는 것만으로는 페이지 HTML 변환이 다시 실행되지 않습니다.

    검수와 한계

    • 일반 표는 원본 Markdown에 헤더, 구분 행, 셀 내용이 들어 있어야 합니다. 복잡한 표는 행과 열, 병합 셀 속성을 유지해야 합니다.
    • 여러 표와 표 앞뒤의 본문은 원래 순서를 유지해야 합니다. 표가 없는 페이지의 변환 결과는 바뀌지 않아야 합니다.
    • 동기화가 끝난 뒤에도 비동기 파싱이 끝나기를 기다렸다가 지식 청크의 표 내용을 확인해야 합니다.
    • 이번 개선은 복잡한 HTML 표를 모두 순수 Markdown으로 바꾸겠다고 약속하지 않습니다. HTML을 유지하는 것은 구조 손실을 피하기 위한 대체 동작입니다.
