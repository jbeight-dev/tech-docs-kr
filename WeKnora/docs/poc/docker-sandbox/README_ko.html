    Docker 샌드박스 백엔드 타당성 PoC

    현재 구현과 배포 요구 사항은 샌드박스 배포와 문제 해결을 참고하십시오. 이 PoC는 과거의 타당성 실험으로만 남겨 둔 것이며 현재 어댑터의 동작을 나타내지 않습니다.

    이 프로그램은 Docker Engine API를 직접 호출해 「Docker가 WeKnora RemoteSandboxClient 계약 + E2B식 Snapshot 워크플로를 감당할 수 있는가」를 항목별로 검증합니다. 제품 코드가 아니며 메인 모듈 빌드에도 참여하지 않습니다 (자체 go.mod가 있습니다). 조사 결론을 재현할 수 있는 증거로만 둡니다.

    각 항목은 PASS/FAIL과 실제 관측값을 출력합니다. (GAP)이 붙은 단계는 「Docker가 할 수 없는 것」을 단언하며, 이 단계들도 PASS로 끝납니다. 여기서 PASS는 차이가 재현됐다는 뜻이지 그 기능이 있다는 뜻이 아닙니다.

    실행 방법

    접근 가능한 Docker daemon(DOCKER_HOST를 따릅니다)이 있어야 하고, python:3.11-slim을 받을 수 있어야 합니다.

    cd docs/poc/docker-sandbox
go run .            # daemon 在本机 unix socket 上时可能需要 sudo -E

    프로그램은 uid 1000 user 계정이 있는 템플릿 이미지를 직접 만들고(E2B 템플릿 관례에 맞춤), 실행이 끝나면 자신이 만든 컨테이너를 삭제합니다. 남는 weknora-poc/* 이미지는 docker image rm으로 정리합니다.

    다루는 내용

    • 생명 주기: Create / Connect(클라이언트를 바꿔 재연결) / List(label 필터) / Delete / Pause / Stop+Start
    • 실행: user, workdir, env, stdin, stdout+stderr 분리, 종료 코드, 타임아웃
    • 파일 측면: archive API 읽기·쓰기와 stat, exec로 구현한 mkdir/ls/rm
    • 세션 의미론: pip install과 파일 쓰기가 exec를 넘어 유지되는지
    • Snapshot: 이미지로 commit, 스냅숏에서 새 샌드박스 시작, v1→v2 증분, label로 나열, 레이어 수와 용량
    • 차이 재현: 클라이언트가 취소해도 프로세스가 죽지 않음, CapDrop ALL 이후 root가 권한 비트를 넘지 못함, 스냅숏에 메모리 상태가 없음, daemon에 유휴 TTL이 없음, docker run을 kill하면 계속 실행 중인 컨테이너가 남음
