    GitHub 플러그인

    기능 제공 범위: DataHub Cloud 전용

    참고: Ask DataHub Plugins는 현재 비공개 베타(Private Beta)입니다. 이 기능을 활성화하려면 DataHub 고객 지원 담당자에게 문의하세요.

    GitHub Plugin은 GitHub MCP 서버를 통해 Ask DataHub를 GitHub에 연결합니다. AI 어시스턴트는 Ask DataHub 안에서 리포지토리 탐색, 코드 검토, pull request 생성 등을 수행할 수 있습니다.

    GitHub를 연결하는 이유

    GitHub 플러그인을 활성화하면 Ask DataHub로 다음을 할 수 있습니다.

    • 데이터 문제의 근본 원인 분석 — DataHub assertion이 문제를 감지하면, 관련 변환 로직이나 파이프라인 코드를 변경한 최근 커밋과 pull request를 검토해 원인을 추적합니다.
    • 데이터 개발 — 채팅을 떠나지 않고 dbt 모델을 탐색하고, 파이프라인 정의를 살펴보고, 문제를 수정하는 pull request를 생성합니다. 데이터 품질 문제 감지부터 수정 배포까지 하나의 대화에서 진행할 수 있습니다.
    • 코드 탐색 — 리포지토리 전반에서 변환 로직, 구성 파일, 파이프라인 정의를 찾아 살펴보고 데이터가 어떻게 생성되고 변환되는지 이해합니다.

    프롬프트 예시:

    • "data-platform 리포지토리의 ETL 파이프라인 최근 변경 사항을 보여 주세요"
    • "이번 주에 머지된 PR 중 revenue 모델을 변경한 것은 무엇인가요?"
    • "customer_churn의 dbt 모델 정의를 찾아 주세요"
    • "orders 변환의 null 처리 버그를 수정하는 PR을 생성해 주세요"

    사전 요구 사항

    • GitHub 계정(개인 또는 조직)
    • GitHub에서 OAuth App을 만들 수 있는 관리자 권한
    • Ask DataHub Plugins가 활성화된 DataHub Cloud
    • 플러그인을 구성할 수 있는 DataHub 플랫폼 관리자 권한

    관리자 설정

    GitHub 플러그인은 User OAuth 인증을 사용하며, 각 사용자가 자신의 GitHub 계정으로 인증합니다. GitHub OAuth App을 만들고 DataHub에서 구성해야 합니다.

    OAuth App은 조직(권장) 또는 개인 계정에서 만들 수 있습니다.

    • 조직 앱: 모든 조직 구성원이 바로 사용할 수 있으며, 한 사용자의 리포지토리로 범위가 제한되지 않습니다
    • 개인 앱: 기본적으로 개인 리포지토리로 범위가 제한됩니다

    옵션 A: 조직 OAuth App(권장)

    1단계: GitHub에서 OAuth App 만들기

    1. GitHub를 열고 조직의 OAuth Apps 페이지로 이동합니다. https://github.com/organizations/<YOUR_ORG>/settings/applications

    1. New OAuth App을 클릭하고 애플리케이션 세부 정보를 입력합니다
    필드 값
    Application name DataHub AI Plugin(또는 팀이 식별하기 쉬운 이름)
    Homepage URL https://<your-datahub-url>
    Authorization callback URL https://<your-datahub-url>/integrations/oauth/callback

    주의: 콜백 URL

    Authorization callback URL은 DataHub에 표시된 OAuth Callback URL과 정확히 일치해야 합니다(예: https://your-org.acryl.io/integrations/oauth/callback). 이 URL은 DataHub 플러그인 생성 양식에서 복사할 수 있습니다.

    1. Register application을 클릭합니다

    2단계: 자격 증명 수집

    1. 앱 페이지에서 Client ID를 복사합니다
    2. Generate a new client secret을 클릭하고 바로 복사합니다(다시 표시되지 않습니다)

    3단계: DataHub에서 플러그인 만들기

    1. DataHub에서 Settings > AI > Plugins로 이동합니다
    2. + Create를 클릭하고 GitHub MCP를 선택합니다
    3. 플러그인 세부 정보를 입력합니다
    필드 값
    Name GitHub
    Description 플러그인 설명
    Client ID 2단계에서 얻은 client ID
    Client Secret 2단계에서 얻은 client secret
    Default Scopes repo(필수, 아래 참고)
    1. DataHub 양식에 표시된 OAuth Callback URL을 복사하고, 1단계에서 GitHub에 입력한 Authorization callback URL과 일치하는지 확인합니다

    경고: 필수 스코프

    Ask DataHub가 리포지토리 코드, 커밋, pull request를 읽을 수 있도록 스코프에 반드시 repo를 포함해야 합니다. 이 스코프가 없으면 플러그인의 기능이 크게 제한됩니다.

    1. 필요하면 Instructions for the AI Assistant를 추가하고, Enable for Ask DataHub가 켜져 있는지 확인한 뒤 Create를 클릭합니다

    팁: 권장: 커스텀 지침 추가

    GitHub OAuth App은 사용자가 볼 수 있는 모든 리포지토리에 대한 접근 권한을 부여하므로 범위가 매우 넓을 수 있습니다. Instructions for the AI Assistant 필드를 사용해 AI가 데이터 팀과 가장 관련 있는 리포지토리와 조직에 집중하도록 안내할 것을 강력히 권장합니다. 예를 들면 다음과 같습니다.

    "acme/data-platform과 acme/etl-pipelines 리포지토리에 집중하세요. 핵심 데이터 변환 및 파이프라인 코드가 들어 있습니다. dbt 모델을 찾을 때는 acme/dbt-models를 확인하세요."

    이렇게 하면 AI가 관련 코드를 더 빨리 찾고 관련 없는 리포지토리를 검색하지 않습니다.

    옵션 B: 개인 계정 OAuth App

    단계는 위와 같지만, 조직 설정 대신 GitHub > Your Profile > Settings > Developer Settings > OAuth Apps로 이동합니다. 앱을 만들 때 GitHub와 DataHub를 나란히 열어 두세요. DataHub의 OAuth Callback URL을 GitHub로, GitHub의 Client ID/Secret을 DataHub로 복사해야 합니다.

    권장 스코프

    스코프 필수 여부 접근 범위
    repo 예 리포지토리 전체 접근(코드, PR, 이슈)
    read:org 아니요 조직 데이터 읽기(팀, 구성원)
    user 아니요 사용자 프로필 정보 읽기

    사용자 설정

    Settings > My AI Settings로 이동해 GitHub 플러그인을 찾고 Connect를 클릭합니다. 팝업이 열리면 GitHub에서 OAuth App을 승인합니다. 승인 후 DataHub로 리디렉션됩니다. 자세한 내용은 개요를 참고하세요.

    FAQ

    조직 OAuth App 대신 개인 OAuth App을 사용할 수 있나요?

    예. 개인 OAuth App도 같은 방식으로 동작하며 스코프, 승인 흐름, 플러그인 구성이 동일합니다. 차이점은 관리와 접근 방식입니다.

    • 조직 앱은 조직이 소유하며 모든 조직 관리자에게 표시됩니다. 앱을 승인한 조직 구성원은 누구나 조직 리포지토리에 접근할 수 있습니다. 팀에서 관리하기 쉽고 한 사람의 계정에 의존하지 않으므로 이 방식을 권장합니다.
    • 개인 앱은 개인 GitHub 계정에 연결됩니다. 다른 사용자가 앱을 승인하면 자신이 접근할 수 있는 모든 리포지토리(조직 리포지토리 포함)에 접근할 수 있습니다. 하지만 계정이 비활성화되면 앱이 동작을 멈춥니다.

    프로덕션 환경에서는 조직 수준 앱을 권장합니다. 개인 앱은 테스트나 개인 용도로 사용하기에 적합합니다.

    문제 해결

    OAuth 팝업 차단

    승인 팝업이 나타나지 않으면 브라우저의 팝업 차단 설정을 확인하고 DataHub 인스턴스 URL의 팝업을 허용하세요.

    승인 실패

    • GitHub의 Authorization callback URL이 DataHub에 표시된 OAuth Callback URL과 정확히 일치하는지 확인합니다
    • DataHub에 Client ID와 Client Secret을 올바르게 입력했는지 확인합니다
    • 조직 앱의 경우 OAuth App이 조직 정책으로 제한되어 있지 않은지 확인합니다

    제한된 리포지토리 접근

    • 조직 OAuth App의 경우 사용자가 승인 흐름에서 특정 조직에 대한 접근 권한을 부여해야 할 수 있습니다
    • 리포지토리 전체 접근을 위해 스코프에 repo가 포함되어 있는지 확인합니다
