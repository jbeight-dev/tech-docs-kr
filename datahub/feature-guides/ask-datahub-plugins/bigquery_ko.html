    BigQuery 플러그인

    기능 제공 범위: DataHub Cloud 전용

    참고: Ask DataHub Plugins는 현재 비공개 베타(Private Beta)입니다. 이 기능을 활성화하려면 DataHub 고객 지원 담당자에게 문의하세요.

    BigQuery Plugin은 BigQuery MCP 서버를 통해 Ask DataHub를 Google BigQuery에 연결해 채팅에서 바로 대화형 분석을 할 수 있게 합니다. Snowflake 및 Databricks 플러그인과 마찬가지로 DataHub는 적합한 데이터를 찾는 시맨틱 계층 역할을 하고, BigQuery는 쿼리를 실행해 결과를 반환하는 데이터 계층 역할을 합니다.

    BigQuery를 연결하는 이유

    BigQuery 플러그인을 활성화하면 Ask DataHub로 다음을 할 수 있습니다.

    • 대화형 분석 — 일상적인 언어로 질문하고 실제 데이터에 근거한 답변을 받습니다. DataHub가 메타데이터(설명, 소유권, 리니지)로 적합한 테이블을 찾으면 BigQuery가 쿼리를 실행합니다.
    • 데이터 탐색 — 데이터셋 구조를 이해하고, 샘플 데이터를 미리 보고, 컬럼 값을 살펴 데이터 품질이나 사용 사례 적합성을 평가합니다.
    • 데이터 디버깅 — DataHub assertion이 감지한 데이터 문제를 실제 데이터로 조사합니다. 소스에서 null, 중복, 예상치 못한 값, 최신성 문제를 확인합니다.

    플러그인이 Google OAuth를 사용하므로 각 사용자는 자신의 Google 계정으로 인증합니다. 사용자는 IAM으로 접근 권한을 부여받은 데이터만 볼 수 있으며, DataHub에서 별도 정책을 관리할 필요가 없습니다.

    프롬프트 예시:

    • "이번 분기 매출 기준 상위 10개 고객을 쿼리해 주세요"
    • "customers 테이블의 email 컬럼에 null 값이 몇 개 있나요?"
    • "orders 테이블의 샘플 행 5개를 보여 주세요"
    • "내 프로젝트의 모든 데이터셋을 나열해 주세요"

    사전 요구 사항

    • BigQuery API가 활성화된 Google Cloud 프로젝트
    • 프로젝트에서 BigQuery MCP 서버 활성화(아래 1단계 참고)
    • 사용자에게 프로젝트의 필수 IAM 역할이 있어야 합니다(roles/bigquery.dataViewer, roles/bigquery.jobUser, roles/mcp.toolUser 포함)
    • Ask DataHub Plugins가 활성화된 DataHub Cloud
    • 플러그인을 구성할 수 있는 DataHub 플랫폼 관리자 권한

    관리자 설정

    BigQuery 플러그인은 User OAuth 인증을 사용하며, 각 사용자가 자신의 Google 계정으로 인증합니다. 설정 과정은 BigQuery MCP 서버를 활성화하고, Google Cloud에서 OAuth 클라이언트를 만든 다음, DataHub에서 플러그인을 구성하는 순서입니다.

    1단계: BigQuery MCP 서버 활성화

    gcloud CLI를 사용해 Google Cloud 프로젝트에서 BigQuery MCP 서버를 활성화합니다.

    gcloud beta services mcp enable bigquery.googleapis.com \
    --project=YOUR_PROJECT_ID

    팁: gcloud 버전

    이 명령에는 최신 버전의 gcloud CLI beta 컴포넌트가 필요합니다. Invalid choice: 'mcp'가 표시되면 gcloud components update를 실행해 최신 버전으로 업데이트하세요.

    자세한 내용은 Google Cloud 문서를 참고하세요.

    2단계: OAuth 클라이언트 만들기 및 자격 증명 수집

    Google Auth Platform > Clients에서 Web application OAuth 클라이언트를 만듭니다. 클라이언트를 구성할 때 DataHub OAuth 콜백 URL을 Authorized redirect URI로 추가합니다.

    https://<your-datahub-url>/integrations/oauth/callback

    주의: 리디렉션 URI

    Authorized redirect URI는 DataHub 플러그인 생성 양식에 표시된 OAuth Callback URL과 정확히 일치해야 합니다(예: https://your-org.acryl.io/integrations/oauth/callback). 3단계에서 플러그인을 만들 때 DataHub 양식에서 이 URL을 복사할 수 있습니다.

    클라이언트를 만든 뒤 Client ID와 Client Secret을 바로 복사하세요. client secret은 다시 표시되지 않습니다.

    자세한 지침은 Google 문서의 OAuth 2.0 자격 증명 얻기를 참고하세요.

    3단계: DataHub에서 플러그인 만들기

    1. DataHub에서 Settings > AI > Plugins로 이동합니다
    2. + Create를 클릭하고 Custom MCP를 선택합니다
    3. 플러그인 세부 정보를 입력합니다
    필드 값
    Name BigQuery
    Description 플러그인 설명
    MCP Server URL https://bigquery.googleapis.com/mcp
    Authentication Type User OAuth (Each user authenticates)
    1. DataHub가 Google에서 OAuth 구성을 자동으로 찾습니다. 다음을 입력합니다
    필드 값
    Client ID 2단계에서 얻은 값
    Client Secret 2단계에서 얻은 값
    Default Scopes https://www.googleapis.com/auth/bigquery

    정보: OAuth 스코프

    https://www.googleapis.com/auth/bigquery 스코프는 BigQuery에 대한 읽기 및 쓰기 권한을 부여합니다. 사용 가능한 전체 스코프 목록은 BigQuery OAuth scopes를 참고하세요.

    1. 필요하면 Instructions for the AI Assistant를 추가하고, Enable for Ask DataHub가 켜져 있는지 확인한 뒤 Create를 클릭합니다

    사용자 설정

    Settings > My AI Settings로 이동해 BigQuery 플러그인을 찾고 Connect를 클릭합니다. Google로 리디렉션되어 인증한 뒤 DataHub로 돌아옵니다. 자세한 내용은 개요를 참고하세요.

    참고: OAuth 동의 화면

    OAuth 동의 화면이 Internal로 설정되어 있으면 Google Workspace 조직 내 사용자만 인증할 수 있습니다. External로 설정되어 있고 아직 인증받지 않았다면 사용자에게 경고가 표시될 수 있으며, Advanced > Go to <app name>을 클릭해 계속할 수 있습니다. 프로덕션 환경에서는 동의 화면 인증을 고려하세요.

    기능

    연결하면 Ask DataHub는 BigQuery MCP 서버로 다음을 수행할 수 있습니다.

    • SQL 쿼리 실행 — BigQuery 데이터에 SELECT 쿼리를 실행합니다(읽기 전용이며 쓰기 작업은 지원하지 않습니다)
    • 데이터셋과 테이블 탐색 — 프로젝트의 데이터셋과 데이터셋의 테이블을 나열합니다
    • 테이블 메타데이터 확인 — 스키마, 행 수, 기타 테이블 세부 정보를 확인합니다

    사용 가능한 전체 도구 목록은 BigQuery MCP 참조 문서를 참고하세요.

    문제 해결

    OAuth 실패

    • Google Cloud의 Authorized redirect URI가 DataHub에 표시된 OAuth Callback URL과 정확히 일치하는지 확인합니다
    • Client ID와 Client Secret을 올바르게 입력했는지 확인합니다
    • Google Cloud 프로젝트에 OAuth 동의 화면이 구성되어 있는지 확인합니다

    권한 오류

    • 사용자에게 프로젝트의 필수 IAM 역할이 있는지 확인합니다
    • 프로젝트에서 BigQuery MCP 서버가 활성화되어 있는지 확인합니다

    쿼리 실패

    • 사용자가 쿼리하는 데이터셋과 테이블에 접근 권한이 있는지 확인합니다
    • execute_sql 쿼리는 기본적으로 3분으로 제한되며, 더 오래 걸리는 쿼리는 자동으로 취소됩니다
    • BigQuery MCP는 Google Drive 외부 테이블 쿼리를 지원하지 않습니다
