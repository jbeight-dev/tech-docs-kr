    Snowflake 플러그인

    기능 제공 범위: DataHub Cloud 전용

    참고: Ask DataHub Plugins는 현재 비공개 베타(Private Beta)입니다. 이 기능을 활성화하려면 DataHub 고객 지원 담당자에게 문의하세요.

    Snowflake Plugin은 Ask DataHub를 Snowflake 관리형 MCP 서버에 연결해 채팅에서 바로 대화형 분석을 할 수 있게 합니다. DataHub는 AI가 적합한 데이터를 찾도록 돕는 시맨틱 계층 역할을 하고, Snowflake는 AI가 실제로 데이터를 쿼리하고 분석하게 하는 데이터 계층 역할을 합니다.

    Snowflake를 연결하는 이유

    Snowflake 플러그인을 활성화하면 Ask DataHub로 다음을 할 수 있습니다.

    • 대화형 분석 — 일상적인 언어로 질문하고 실제 데이터에 근거한 답변을 받습니다. DataHub가 메타데이터(설명, 소유권, 리니지)로 적합한 테이블을 찾으면 Snowflake가 쿼리를 실행합니다. 추가 메타데이터나 시맨틱 모델링이 필요하지 않습니다.
    • 데이터 탐색 — 데이터셋 구조를 이해하고, 샘플 데이터를 미리 보고, 컬럼 값을 살펴 데이터 품질이나 사용 사례 적합성을 평가합니다.
    • 데이터 디버깅 — DataHub assertion이 감지한 데이터 문제를 실제 데이터로 조사합니다. 소스에서 null, 중복, 예상치 못한 값, 최신성 문제를 확인합니다.

    플러그인이 OAuth를 사용하므로 각 사용자는 자신의 Snowflake 자격 증명으로 인증합니다. 사용자는 접근 권한을 부여받은 데이터만 볼 수 있으며, DataHub에서 별도 정책이나 grant를 관리할 필요가 없습니다.

    프롬프트 예시:

    • "이번 분기 매출 기준 상위 10개 고객을 쿼리해 주세요"
    • "customers 테이블의 email 컬럼에 null 값이 몇 개 있나요?"
    • "지난달과 이번 달의 매출을 지역별로 비교해 주세요"
    • "orders 테이블의 샘플 행 5개를 보여 주세요"

    사전 요구 사항

    • ACCOUNTADMIN(또는 MCP 서버와 보안 통합을 만들고 역할을 부여할 수 있는 동등한 권한)이 있는 Snowflake 계정
    • Ask DataHub Plugins가 활성화된 DataHub Cloud
    • 플러그인을 구성할 수 있는 DataHub 플랫폼 관리자 권한

    관리자 설정

    Snowflake 플러그인은 User OAuth 인증을 사용하며, 각 사용자가 자신의 Snowflake 계정으로 인증합니다. 설정 과정은 Snowflake에서 MCP 서버와 OAuth 보안 통합을 만든 다음 DataHub에서 플러그인을 구성하는 순서입니다.

    1단계: Snowflake에서 MCP 서버 만들기

    노출할 도구를 포함해 Snowflake에 MCP 서버를 만듭니다. Ask DataHub가 웨어하우스에 SQL 쿼리를 직접 실행할 수 있게 하는 SYSTEM_EXECUTE_SQL부터 시작하기를 권장합니다.

    도구 유형 용도
    SYSTEM_EXECUTE_SQL 권장. 웨어하우스에 SQL 쿼리를 직접 실행합니다. 플러그인을 유용하게 쓰기 위해 필요한 최소한의 도구입니다.
    CORTEX_ANALYST_MESSAGE Cortex Analyst 시맨틱 뷰에 대한 자연어 분석입니다. 원시 SQL 위에 큐레이션된 BI/분석 계층을 제공합니다.
    CORTEX_AGENT_RUN Ask DataHub에서 Cortex Agents를 하위 에이전트로 호출합니다.

    Snowflake는 추가 도구 유형도 지원합니다. 하나의 MCP 서버에 여러 도구를 포함할 수 있습니다.

    예시: SQL 실행과 Cortex Analyst 시맨틱 뷰가 포함된 서버를 만듭니다.

    USE ROLE ACCOUNTADMIN;
USE DATABASE YOUR_DATABASE;
USE SCHEMA YOUR_SCHEMA;

CREATE OR REPLACE MCP SERVER YOUR_MCP_SERVER
  FROM SPECIFICATION $$
    tools:
      - name: "execute_sql"
        type: "SYSTEM_EXECUTE_SQL"
        description: "Execute SQL queries against the data warehouse"
        title: "SQL Executor"
      - name: "revenue_analytics"
        type: "CORTEX_ANALYST_MESSAGE"
        identifier: "YOUR_DATABASE.YOUR_SCHEMA.REVENUE_SEMANTIC_VIEW"
        description: "Analytics over revenue and sales data"
        title: "Revenue Analytics"
  $$;

    참고: MCP 서버당 하나의 데이터베이스

    Snowflake MCP 서버의 범위는 단일 데이터베이스로 제한됩니다. Ask DataHub가 여러 데이터베이스를 쿼리해야 한다면 데이터베이스별로 별도의 MCP 서버(및 플러그인)를 만드세요.

    2단계: 접근 권한 부여

    MCP 서버를 사용할 역할에 사용 권한을 부여합니다.

    GRANT USAGE ON DATABASE YOUR_DATABASE TO ROLE YOUR_ROLE;
GRANT USAGE ON SCHEMA YOUR_DATABASE.YOUR_SCHEMA TO ROLE YOUR_ROLE;
GRANT USAGE ON MCP SERVER YOUR_DATABASE.YOUR_SCHEMA.YOUR_MCP_SERVER TO ROLE YOUR_ROLE;

    3단계: OAuth 보안 통합 만들기

    Snowflake를 OAuth 제공자로 사용하기 위한 보안 통합을 만듭니다. 리프레시 토큰을 활성화하고 리디렉션 URI를 DataHub 인스턴스의 OAuth 콜백으로 설정합니다.

    CREATE OR REPLACE SECURITY INTEGRATION YOUR_INTEGRATION_NAME
  TYPE = OAUTH
  ENABLED = TRUE
  OAUTH_CLIENT = CUSTOM
  OAUTH_CLIENT_TYPE = 'CONFIDENTIAL'
  OAUTH_REDIRECT_URI = 'https://<your-datahub-url>/integrations/oauth/callback'
  OAUTH_ISSUE_REFRESH_TOKENS = TRUE
  OAUTH_REFRESH_TOKEN_VALIDITY = 7776000;

    주의: 콜백 URL

    OAUTH_REDIRECT_URI는 DataHub 플러그인 생성 양식에 표시된 OAuth Callback URL과 정확히 일치해야 합니다(예: https://your-org.acryl.io/integrations/oauth/callback). 5단계에서 플러그인을 만들 때 양식에서 이 URL을 복사할 수 있습니다.

    주의: 리프레시 토큰

    OAUTH_ISSUE_REFRESH_TOKENS가 TRUE로 설정되어 있는지 확인하세요. 리프레시 토큰이 없으면 사용자가 자주 다시 인증해야 합니다.

    4단계: 인증 세부 정보 수집

    다음 쿼리를 실행해 DataHub에 필요한 정보를 수집합니다.

    OAuth 클라이언트 자격 증명:

    SELECT SYSTEM$SHOW_OAUTH_CLIENT_SECRETS('YOUR_INTEGRATION_NAME');

    OAUTH_CLIENT_ID와 OAUTH_CLIENT_SECRET을 포함한 JSON 객체가 반환됩니다.

    MCP Server URL:

    URL 형식은 다음과 같습니다.

    https://<account-url>/api/v2/databases/<DATABASE>/schemas/<SCHEMA>/mcp-servers/<SERVER_NAME>

    참고: 계정 URL 형식

    URL의 계정 로케이터 부분에는 점(.) 대신 하이픈(-)을 사용하세요. 예를 들어 계정 로케이터가 abc12345.us-east-1이면 URL에는 abc12345-us-east-1.snowflakecomputing.com을 사용합니다.

    이제 DataHub 구성에 필요한 값이 준비되었습니다.

    값 출처
    MCP Server URL 계정 URL, 데이터베이스, 스키마, 서버 이름으로 구성(위 형식 참고)
    Client ID SYSTEM$SHOW_OAUTH_CLIENT_SECRETS 출력
    Client Secret SYSTEM$SHOW_OAUTH_CLIENT_SECRETS 출력

    5단계: DataHub에서 플러그인 만들기

    1. DataHub에서 Settings > AI > Plugins로 이동합니다
    2. + Create를 클릭하고 Snowflake MCP를 선택합니다
    3. 플러그인 세부 정보를 입력합니다
    필드 값
    Name Snowflake
    Description 플러그인 설명
    MCP Server URL 4단계에서 얻은 URL
    Client ID 4단계에서 얻은 값
    Client Secret 4단계에서 얻은 값
    Default Scopes refresh_token session:role:<ROLE_NAME>

    경고: 올바른 역할 선택

    session:role:<ROLE_NAME> 스코프는 연결 시 사용자가 맡는 Snowflake 역할을 결정합니다. <ROLE_NAME>을 2단계에서 MCP 서버 접근 권한을 부여한 역할로 바꾸세요(예: session:role:DATA_ANALYST). 생략하면 사용자의 기본 역할이 사용되며, 이 역할에는 MCP 서버 접근 권한이 없을 수 있습니다. 각 사용자에게 지정한 역할이 Snowflake에서 반드시 부여되어 있어야 하며, 해당 역할은 보안 통합의 차단 역할 목록에 있으면 안 됩니다(문제 해결 참고).

    1. 필요하면 Instructions for the AI Assistant를 추가하고, Enable for Ask DataHub가 켜져 있는지 확인한 뒤 Create를 클릭합니다

    사용자 설정

    Settings > My AI Settings로 이동해 Snowflake 플러그인을 찾고 Connect를 클릭합니다. Snowflake로 리디렉션되어 인증한 뒤 DataHub로 돌아옵니다. 자세한 내용은 개요를 참고하세요.

    문제 해결

    사용자가 로그인할 수 없음 / OAuth 실패

    OAuth 보안 통합이 사용자의 역할을 차단하고 있을 수 있습니다. 맡으려는 역할이 차단 역할 목록에 없는지 확인하세요.

    ALTER SECURITY INTEGRATION "YOUR_INTEGRATION_NAME"
  SET BLOCKED_ROLES_LIST = ();

    쿼리 실패

    • 사용자의 Snowflake 역할에 대상 테이블의 SELECT 권한이 있는지 확인합니다
    • 사용자에게 MCP 서버의 USAGE가 부여되어 있는지 확인합니다
    • 웨어하우스가 일시 중단되지 않고 실행 중인지 확인합니다

    토큰 만료

    사용자에게 재인증 요청이 자주 표시되면 보안 통합에서 리프레시 토큰이 활성화되어 있는지(OAUTH_ISSUE_REFRESH_TOKENS = TRUE)와 OAUTH_REFRESH_TOKEN_VALIDITY가 적절한 기간으로 설정되어 있는지 확인합니다.
