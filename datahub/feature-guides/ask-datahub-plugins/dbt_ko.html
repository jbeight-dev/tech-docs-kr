    dbt Cloud 플러그인

    기능 제공 범위: DataHub Cloud 전용

    참고: Ask DataHub Plugins는 현재 비공개 베타(Private Beta)입니다. 이 기능을 활성화하려면 DataHub 고객 지원 담당자에게 문의하세요.

    dbt Cloud Plugin은 dbt 원격 MCP 서버를 통해 Ask DataHub를 dbt Cloud 환경에 연결합니다. AI 어시스턴트는 작업 실행, 모델 정의, 테스트 결과를 볼 수 있고, 적절히 구성하면 사용자를 대신해 SQL 쿼리도 실행할 수 있습니다.

    dbt Cloud를 연결하는 이유

    dbt Cloud 플러그인을 활성화하면 Ask DataHub로 다음을 할 수 있습니다.

    • 작업 실행 상태 확인 — 최근 dbt 실행의 성공 또는 실패 여부를 확인합니다
    • 모델 정의 살펴보기 — dbt 모델의 SQL과 구성을 확인합니다
    • 테스트 결과 검토 — 어떤 테스트가 통과하거나 실패했는지와 그 이유를 파악합니다
    • SQL 쿼리 실행 — dbt를 통해 웨어하우스에 쿼리를 실행합니다(추가 구성 필요)

    프롬프트 예시:

    • "revenue 모델의 최근 dbt 실행이 성공했나요?"
    • "orders 모델의 SQL 정의를 보여 주세요"
    • "최근 24시간 동안 실패한 dbt 테스트는 무엇인가요?"
    • "customers 테이블을 쿼리해 null 이메일이 있는지 확인해 주세요"

    사전 요구 사항

    • AI 기능이 활성화되어 있고 원격 MCP 서버가 동작 중인 dbt Cloud 계정
    • Semantic Layer 및 Developer 권한이 있는 dbt Cloud 개인 액세스 토큰 또는 서비스 토큰
    • dbt Cloud 프로덕션 환경 ID(SQL 실행에는 선택적으로 개발 환경 ID)
    • Ask DataHub Plugins가 활성화된 DataHub Cloud
    • 플러그인을 구성할 수 있는 DataHub 플랫폼 관리자 권한

    관리자 설정

    1단계: dbt 원격 MCP 서버 활성화

    dbt 원격 MCP 설정 가이드에 따라 dbt Cloud 프로젝트의 원격 MCP 서버를 활성화합니다.

    2단계: 구성 세부 정보 수집

    dbt Cloud에서 다음 정보가 필요합니다.

    MCP Server URL: dbt Cloud 호스트를 사용해 URL을 구성합니다.

    https://<YOUR_DBT_HOST_URL>/api/ai/v1/mcp/

    멀티 셀 계정의 호스트 URL 형식은 ACCOUNT_PREFIX.us1.dbt.com입니다. 자세한 내용은 dbt 리전 문서를 참고하세요.

    Production Environment ID: dbt Cloud에서 Orchestration > Environments로 이동해 URL에서 환경 ID를 복사합니다.

    API Token: 개인 액세스 토큰 또는 서비스 토큰을 생성합니다. 토큰에는 Semantic Layer 및 Developer 권한이 있어야 합니다.

    3단계: DataHub에서 플러그인 만들기

    1. DataHub에서 Settings > AI > Plugins로 이동합니다
    2. + Create를 클릭하고 dbt Cloud MCP를 선택합니다
    3. 플러그인 세부 정보를 입력합니다
    필드 값
    Name dbt Cloud
    Description 플러그인 설명
    MCP Server URL https://<YOUR_DBT_HOST_URL>/api/ai/v1/mcp/
    Production Environment ID 2단계에서 얻은 프로덕션 환경 ID

    1. 인증 유형을 선택합니다
    옵션 동작 방식 적합한 경우
    Shared API Key 관리자가 모든 사용자에게 사용되는 단일 서비스 토큰을 입력합니다 하나의 서비스 계정으로 중앙 집중식 접근
    User API Key 각 사용자가 연결할 때 자신의 개인 액세스 토큰을 입력합니다 사용자별 감사 추적과 접근 제어

    4단계: SQL 실행 활성화(선택 사항)

    Ask DataHub가 dbt를 통해 SQL 쿼리를 실행하도록 하려면 다음 추가 필드를 입력합니다.

    필드 설명
    Development Environment ID dbt Cloud 개발 환경 ID(Orchestration > Environments 페이지에서 확인)
    User ID dbt Cloud 사용자 ID(dbt Cloud의 Settings > Users URL에서 확인)

    주의

    Shared API Key를 사용하면 모든 사용자가 사용자 ID를 공유하므로 쿼리가 하나의 ID로 실행됩니다. User API Key 인증에서는 각 사용자가 연결할 때 자신의 사용자 ID를 입력합니다.

    Settings > Users로 이동해 프로필을 선택하면 URL에서 dbt Cloud 사용자 ID를 확인할 수 있습니다.

    SQL 실행이 동작하려면 각 사용자가 dbt Cloud에 개발 자격 증명(프로필의 웨어하우스 연결)도 구성해야 합니다.

    1. 필요하면 Instructions for the AI Assistant를 추가하고, Enable for Ask DataHub가 켜져 있는지 확인한 뒤 Create를 클릭합니다

    사용자 설정

    Settings > My AI Settings로 이동해 dbt Cloud 플러그인을 찾습니다. User API Key 인증을 사용한다면 Connect를 클릭하고 dbt Cloud API 토큰과 사용자 ID를 입력합니다. Shared API Key 인증을 사용한다면 플러그인을 켜기만 하면 됩니다. 자세한 내용은 개요를 참고하세요.

    사용 팁

    • dbt Cloud를 DataHub 리니지와 결합해 종단 간 디버깅을 수행합니다. 대시보드 문제를 DataHub 리니지를 따라 실패한 dbt 모델까지 추적할 수 있습니다
    • 특정 환경(프로덕션 또는 스테이징)을 지정해 질문하면 원하는 결과를 얻을 수 있습니다
    • dbt 테스트 결과와 DataHub assertion을 함께 사용해 데이터 품질을 완전하게 파악합니다

    정보: dbt Copilot 크레딧

    text_to_sql 도구만 dbt Copilot 크레딧을 소비합니다. 다른 MCP 도구(메타데이터 탐색, 시맨틱 계층 쿼리)는 소비하지 않습니다. 자세한 내용은 dbt 문서를 참고하세요.

    문제 해결

    연결 오류

    • dbt Cloud API 토큰이 유효하고 Semantic Layer 및 Developer 권한이 있는지 확인합니다
    • dbt Cloud 프로젝트에서 원격 MCP 서버가 활성화되어 있는지 확인합니다

    잘못된 프로젝트 또는 환경

    • Production Environment ID가 올바르게 설정되어 있는지 확인합니다
    • 환경 ID가 dbt Cloud URL에 표시된 값과 일치하는지 다시 확인합니다

    SQL 쿼리가 동작하지 않음

    • 해당 사용자의 개발 자격 증명이 dbt Cloud에 구성되어 있는지 확인합니다
    • Development Environment ID와 User ID가 설정되어 있는지 확인합니다
    • API 토큰에 쿼리 실행 권한이 있는지 확인합니다
