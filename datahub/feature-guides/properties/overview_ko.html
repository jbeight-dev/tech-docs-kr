    DataHub Structured Properties 소개

    기능 제공 범위: DataHub Core, DataHub Cloud

    DataHub Structured Properties를 사용하면 DataHub의 모든 엔터티 유형에 검증된 커스텀 속성을 추가할 수 있습니다. Structured Properties로 조직 고유의 속성을 기반으로 데이터 탐색과 거버넌스를 구현할 수 있습니다.

    Structured Properties란?

    Structured Properties는 DataHub 환경을 사용자 지정해 메타데이터를 조직의 고유한 요구에 맞출 수 있는 강력한 방법입니다. Date, Integer, DataHub Asset, Text 같은 특정 속성 유형을 정의해 자산에 의미 있고 맥락에 맞는 속성을 적용할 수 있습니다. 허용 값 제한이나 특정 형식 적용 같은 검증 규칙은 일관성을 보장하면서도 비즈니스 용어, 워크플로, 우선순위를 반영할 유연성을 제공합니다.

    Structured Properties는 다음 자산 유형에 추가할 수 있습니다.

    • Datasets, Columns, Tasks, Pipelines, Charts, Dashboards 등의 데이터 자산.
    • Domains, Glossary Terms & Groups, Data Products 등의 DataHub 엔터티.

    Structured Properties의 주요 기능:

    1. 타입이 지정된 필드: 속성에는 Date, Integer, URN, Text 같은 옵션을 포함해 명시적으로 타입이 지정됩니다.
    2. 허용 값: 값을 특정 형식이나 미리 정의된 허용 입력 목록으로 제한해 표준을 적용합니다.
    3. 대상 지정 적용: Structured Properties를 Datasets, Columns, Dashboards 같은 특정 자산 유형에 맞춰 조직의 데이터 관리 요구와 사용 맥락에 부합하게 할 수 있습니다.

    표시 설정

    Structured Properties는 메타데이터 관리를 강화하는 여러 구성 옵션을 제공합니다.

    • Hide Property: DataHub 사용자가 속성 값을 볼 수 없어야 하는 사용 사례에 사용합니다.
    • Show in Search Filters: 사용자가 특정 속성 값을 기준으로 자산을 필터링할 수 있게 해 검색 가능성을 높입니다.
    • Customize Visibility: Asset Badge, Asset Sidebar, Dataset Schema 뷰의 Columns Table 등 Structured Property가 표시되는 위치를 제어합니다.

    Structured Properties를 사용하는 이유

    Structured Properties는 특히 다음이 필요한 조직에 유용합니다.

    • 사용자 지정: 최종 사용자가 DataHub에서 자산을 찾는 방식을 사용자 지정합니다.
    • 거버넌스와 컴플라이언스: 내부 또는 외부 표준 준수를 지원하는 방식으로 메타데이터를 수집합니다.

    이러한 구성을 활용하면 팀은 메타데이터가 조직 정책을 준수하도록 보장하고 데이터 자산의 검색 가능성과 사용성을 높일 수 있습니다.

    제한 사항

    Text 및 Rich Text 속성의 값 크기

    문자열 기반 구조화된 속성 값(Text, Rich Text, Date, DataHub Entity / URN)은 Elasticsearch / OpenSearch keyword로 인덱싱됩니다. 각 값은 기본적으로 최대 32,766 UTF-8 바이트입니다(Lucene의 keyword term 제한).

    STRUCTURED_PROPERTIES_KEYWORD_MAX_LENGTH / structuredProperties.keywordMaxLength(기본값 32766)로 제한을 구성합니다. 기본적으로 DataHub는 구성된 제한을 초과하는 쓰기를 검증 오류로 거부하므로, 너무 큰 값은 검색 인덱스에 도달하지 않습니다.

    STRUCTURED_PROPERTIES_DROP_OVERSIZED_KEYWORD_VALUES_FROM_INDEX / structuredProperties.dropOversizedKeywordValuesFromIndex를 true(기본값 false)로 설정하면 해당 바이트 임곗값을 초과하는 값을 기본 스토리지에 저장하면서 Elasticsearch / OpenSearch 문서에서는 생략합니다. GraphQL과 OpenAPI 읽기는 저장된 값을 계속 반환하지만, 검색과 필터는 반환하지 않습니다. 바이트 임곗값 미만이지만 매핑의 ignore_above 문자 제한(keywordMaxLength / 4)을 초과하는 값은 문서 _source에 저장되어도 검색할 수 없는 상태로 남을 수 있습니다. 검색이나 필터링이 필요한 속성에는 더 짧은 값을 사용하세요. 큰 자유 형식 콘텐츠(긴 Markdown, HTML, 문서)는 구조화된 속성 값이 아니라 자산 문서 같은 다른 곳에 저장하세요.

    Number 속성에는 이 keyword 제한이 적용되지 않습니다.

    Search V3 템플릿이 fieldValueScores에서 숫자 속성을 지정하면 해당 속성이 검색 순위를 변경할 수 있습니다. 기본 제공 템플릿은 이를 지정하지 않습니다. 생략된 범위 값은 정의의 score에서 가져옵니다. 숫자 속성 점수를 참고하세요.
