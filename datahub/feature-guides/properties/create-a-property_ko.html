    DataHub Structured Property 만들기 및 추가하기

    기능 제공 범위: DataHub Core, DataHub Cloud

    이 가이드에서는 DataHub UI에서 Structured Property를 만드는 다음 과정을 설명합니다.

    1. 새 Structured Property 정의
    2. Structured Property의 표시 기본 설정 구성
    3. 자산에 Structured Property 추가
    4. 컬럼에 Structured Property 추가

    참고

    CLI로 Structured Properties를 만들고 할당하는 방법은 Create Structured Properties 튜토리얼을 참고하세요.

    사전 요구 사항

    Structured Properties를 만들거나 편집하거나 제거하려면 View Structured Properties 및 Manage Structured Properties 플랫폼 권한이 있어야 합니다.

    기존 Structured Property를 자산에 추가하거나, 값을 변경하거나, 자산에서 제거하려면 Edit Properties 메타데이터 권한이 있어야 합니다.

    새 Structured Property 정의

    탐색 모음에서 Govern > Structured Properties로 이동합니다.

    + Create를 클릭해 속성 정의를 시작합니다.

    먼저 다음 세부 정보를 입력합니다.

    1. Name and Description: 사용자가 역할과 맥락을 이해할 수 있도록 Structured Property의 목적과 의미를 명확히 설명합니다.

    2. Property Type: 수집하려는 메타데이터에 가장 적합한 유형을 선택합니다. 사용 가능한 유형은 Text, Number, Date, DataHub Entity, Rich Text입니다. "List" 옵션을 선택하면 속성에 여러 항목을 입력할 수 있습니다.

      참고: 값 크기 제한

      각 Text, Rich Text, Date, DataHub Entity 값은 기본적으로 최대 32,766 UTF-8 바이트입니다(Elasticsearch / OpenSearch keyword 제한이며 STRUCTURED_PROPERTIES_KEYWORD_MAX_LENGTH로 구성 가능). STRUCTURED_PROPERTIES_DROP_OVERSIZED_KEYWORD_VALUES_FROM_INDEX=true가 아니면 더 긴 값은 쓰기 시 거부되며, 이 설정을 사용하면 값을 기본 스토리지에 저장하고 검색에서는 생략합니다. 제한 사항을 참고하세요.

    3. Allowed Values (Optional): Text, Number, DataHub Entity 유형에 허용 값 집합을 정의해 자산 전반의 입력을 일관되게 유지합니다.

    4. Applies To: Structured Property를 연결할 수 있는 DataHub 자산 유형(예: Datasets, Dashboards, Pipelines)을 지정해 관련성과 정확성을 보장합니다.

    주의

    Structured Property를 저장한 뒤에는 허용 값을 편집하거나 제거할 수 없습니다. 다만 허용 값을 추가할 수는 있습니다.

    예를 들어 조직에서 개발 주기 동안 데이터 자산(예: Datasets, Tasks, Pipelines)을 분류하는 방식을 표준화하려 한다고 가정해 보겠습니다. Lifecycle Stage Structured Property를 만들면 Draft, Review, Prod 같은 허용 상태 목록을 미리 정의해 일관성과 투명성을 보장할 수 있습니다.

    Structured Property의 표시 기본 설정

    Structured Property를 정의할 때 DataHub 사용자에게 표시되는 방식을 사용자 지정할 수 있습니다. 기본적으로 Structured Properties는 자산의 Properties 탭에 표시되며, 다음 옵션으로 조건부 구성할 수 있습니다.

    1. Hide Property:
      DataHub 사용자가 UI에서 볼 수 없어야 하는 민감한 메타데이터가 Structured Property에 포함된 경우 이 옵션을 사용합니다. 필요한 권한이 있는 사용자만 속성 값을 보거나 상호작용할 수 있도록 보장합니다.

    2. Customize Visibility:
      DataHub UI에서 Structured Property가 표시되는 위치를 결정합니다.

      • Asset Badge: 핵심 메타데이터를 강조하기 위해 속성 값을 자산의 배지로 표시합니다.
      • Asset Sidebar: 자산을 탐색하는 동안 빠르게 볼 수 있도록 Asset Sidebar에 속성을 표시합니다.

    3. Show in Search Filters:
      사용자가 이 Structured Property의 값으로 자산을 필터링할 수 있도록 이 옵션을 활성화합니다. 검색 가능성을 높이고 특정 속성이나 분류를 가진 자산을 쉽게 검색할 수 있습니다.

    4. Show in Columns Table:
      Dataset Schema 뷰의 Columns Table에 Structured Property 값을 표시하려면 이 옵션을 사용합니다. 필드 수준 커스텀 메타데이터를 수집하고 스키마 세부 정보와 함께 제공할 때 특히 유용합니다.

    Lifecycle Stage 예시에서 사용자가 수명 주기 상태로 필터링하고 데이터 탐색 중에 한눈에 볼 수 있게 하려면 Show in Search Filters, Asset Badge, Asset Sidebar를 활성화합니다.

    자산에 Structured Property 추가

    Structured Property를 정의한 뒤에는 지정된 자산 유형에 추가할 수 있습니다.

    자산의 Properties 탭에서 + 버튼을 클릭하면 사용 가능한 모든 Structured Properties의 드롭다운 목록이 표시됩니다. 예를 들어 이제 pet_profiles 데이터셋의 옵션으로 Lifecycle Stage를 볼 수 있습니다.

    Lifecycle Stage 예시를 이어서, pet_profiles 데이터셋을 Prod 단계로 지정합니다.

    Save를 클릭하면 pet_profiles의 Lifecycle Stage가 자산 페이지의 다음 섹션에 표시됩니다.

    1. Properties Tab
    2. Asset Badge
    3. Asset Sidebar

    정보

    DataHub Compliance Forms를 사용하면 여러 자산의 값을 한 번에 쉽게 업데이트할 수 있습니다!

    자산의 Structured Property 편집 또는 제거

    Structured Property를 자산에 추가한 뒤에는 More 메뉴로 값을 수정하거나 속성을 완전히 제거할 수 있습니다.

    Structured Property 값으로 자산 검색

    Show in Search Filters가 활성화된 Structured Properties의 경우, 사용자는 허용 값을 기준으로 검색 결과를 필터링할 수 있습니다.

    예를 들어 Lifecycle Stage 속성이 필터로 활성화되어 있으면 Search 인터페이스의 More 드롭다운에서 찾을 수 있습니다.

    여기에서 Prod 같은 원하는 단계로 검색 결과를 빠르게 좁힐 수 있습니다.

    pet_profiles Asset Badge에 Prod 값이 눈에 띄게 표시되는 것을 확인하세요.

    컬럼에 Structured Property 추가

    Structured Properties는 컬럼 수준에 적용할 수 있어, 개별 데이터셋 필드가 비즈니스 개념이나 용어와 어떻게 관련되는지 더 깊은 컨텍스트를 제공합니다. 이 예시에서는 비즈니스 사용자가 데이터셋 컬럼과 일반 용어, 약어, 핵심 비즈니스 개념의 관계를 이해하도록 돕는 Business Label이라는 Structured Property를 만듭니다.

    Business Label 속성 정의

    다음 단계에 따라 Business Label Structured Property를 정의하고 구성합니다.

    1. Property Details:

      • Name: Business Label
      • Description: 다음과 같이 목적을 설명합니다.
        "비즈니스 사용자가 의미를 이해하도록 돕는, 데이터셋 컬럼의 사용자 친화적인 이름입니다."
      • Property Type: Text를 선택해 유효한 문자열을 입력할 수 있게 합니다.
      • Applies To: 이 속성이 Columns에만 적용되도록 설정합니다.

    2. Display Preferences:

      • 기본적으로 컬럼 수준 Structured Properties는 DataHub 내 모든 데이터셋의 모든 컬럼에 활성화되며 Column Sidebar에서 접근할 수 있습니다.
      • 선택적으로 Show in Table Columns를 활성화해 데이터셋 스키마의 Columns Table에 Business Label을 표시합니다.

    주의

    컬럼 사이드바에서 할당된 속성에 편리하게 접근할 수 있지만, Structured Properties를 너무 많이 추가하면 뷰가 복잡해질 수 있습니다. 명확성과 사용성을 유지하려면 사이드바에 표시되는 속성 수를 제한하세요.

    구성이 끝나면 Business Label Structured Property가 DataHub 내 데이터셋 자산의 모든 컬럼에 자동으로 추가됩니다.

    예를 들어 속성을 할당하면 pet_profiles 자산 페이지의 두 주요 영역에 표시됩니다.

    1. Columns Table: Business Label 속성과 입력된 값이 Dataset Schema의 Columns Table에 바로 표시되어 사용자가 필드 수준 메타데이터를 쉽게 볼 수 있습니다.
    2. Column Sidebar: Business Label을 포함해 컬럼용으로 구성된 Structured Properties가 컬럼 사이드바에도 표시됩니다.

    Business Label 같은 컬럼 수준 Structured Properties를 적용하면 인터페이스를 사용하기 쉽게 유지하면서 데이터 검색 가능성을 높이고 비즈니스 사용자에게 유용한 인사이트를 제공할 수 있습니다.

    Column Sidebar에서 Business Label 업데이트

    UI에서 특정 컬럼을 선택하면 컬럼 사이드바에 Business Label Structured Property가 표시됩니다. 적절한 권한이 있는 사용자는 이 인터페이스에서 값을 바로 보거나 업데이트할 수 있습니다.

    이 설정으로 Business Label 같은 컬럼별 메타데이터에 접근하고 활용할 수 있어, 비즈니스 사용자가 데이터셋의 구조와 핵심 비즈니스 개념과의 관계를 더 잘 이해할 수 있습니다.

    FAQ 및 문제 해결

    Structured Property의 정의를 변경할 수 없는 이유는 무엇인가요?

    Structured Property를 정의한 뒤에는 일부 항목만 수정할 수 있습니다.

    변경할 수 있는 항목:

    • 제목과 설명
    • 새 허용 값 추가
    • 새 지원 자산 유형 추가
    • 표시 기본 설정 업데이트

    변경할 수 없는 항목:

    • Structured Property의 유형
    • 기존 허용 값과 그 정의

    Structured Property를 Asset Badge로 표시하도록 구성할 수 없는 이유는 무엇인가요?

    • 허용 값이 있는 Text 및 Number 유형만 Asset Badge로 구성할 수 있습니다.
    • 자산당 하나의 Structured Property만 Badge로 표시할 수 있습니다.

    Structured Property로 검색 결과를 필터링할 수 없는 이유는 무엇인가요?

    • Structured Property가 검색 필터에 표시되도록 구성되어 있는지 확인합니다.
    • 검색 결과에 해당 Structured Property 값과 연결된 자산이 있는지 확인해 필터가 유효한지 확인합니다. 다른 검색어를 사용하거나 적용된 다른 필터를 완화해 보세요.

    자산에 Structured Property를 추가할 수 없는 이유는 무엇인가요?

    • Edit Properties 권한이 있는지 확인합니다.
    • Structured Property가 이미 생성되어 있고 수정하려는 자산 유형을 지원하는지 확인합니다.

    Text 또는 Rich Text 속성 값이 거부된 이유는 무엇인가요?

    • 각 문자열 기반 구조화된 속성 값(Text, Rich Text, Date, DataHub Entity)은 기본적으로 최대 32,766 UTF-8 바이트입니다(STRUCTURED_PROPERTIES_KEYWORD_MAX_LENGTH). 이 제한을 초과하는 값은 Elasticsearch / OpenSearch keyword로 인덱싱할 수 없어 거부됩니다. 단, STRUCTURED_PROPERTIES_DROP_OVERSIZED_KEYWORD_VALUES_FROM_INDEX가 활성화된 경우는 예외입니다(값은 저장되지만 검색할 수 없음). 값을 줄이거나 큰 콘텐츠를 자산 문서로 저장하세요. 제한 사항을 참고하세요.
