    커스텀 에이전트

    기능 제공 범위: DataHub Cloud 전용

    정보: Context 애드온

    커스텀 에이전트는 DataHub Cloud Context 애드온에 포함됩니다.

    Agents를 사용하면 메타데이터 그래프를 대상으로 일정에 따라, 이벤트에 반응해, 또는 필요할 때 작업을 자율적으로 실행하는 커스텀 AI 에이전트를 만들 수 있습니다. 각 에이전트에는 고유한 지침, 도구, 플러그인, 데이터 생태계에 대한 범위 지정 뷰를 구성할 수 있습니다.

    커스텀 에이전트의 용도는 두 가지입니다.

    • 도메인 관련 질문에 답변. 에이전트의 범위를 하나의 도메인으로 지정하고 고유한 지침과 플러그인을 구성한 뒤, Ask DataHub에서 사용하거나 MCP를 통해 자체 에이전트에 제공합니다. Build a Data Agent를 참고하세요.
    • 컨텍스트 계층 유지 관리. 누락된 설명 채우기, 도메인 내 문서화되지 않은 테이블 표시, 소유권 공백 보고처럼 데이터가 변경되어도 컨텍스트를 건강하게 유지하는 작업을 예약합니다.

    Agents는 Ask DataHub를 대화형 어시스턴트에서 자동화 플랫폼으로 확장하며, 세 가지 핵심 개념으로 구성됩니다.

    • Agents — 맞춤형 지침, 도구 접근 권한, 범위를 갖춘 목적별 커스텀 AI 에이전트
    • Tasks — 에이전트에 할당되는 반복 가능한 작업 단위로, 수동, 일정, 이벤트로 트리거됩니다
    • Decisions — 에이전트가 일시 중지하고 계속하기 전에 입력을 요청하는 사람 참여형(human-in-the-loop) 확인 지점

    사용 사례 예시

    • 데이터 탐색 에이전트 — "Snowflake Production" 에이전트나 "Marketing Domain" 에이전트처럼 생태계의 특정 부분으로 범위를 지정한 에이전트를 만들어, 사용자가 자연스러운 대화로 관련 데이터 자산을 탐색하도록 돕습니다.
    • 데이터 품질 및 거버넌스 보고서 — 데이터 자산 전반의 문서화 범위, 소유권 공백, 분류 상태, assertion 상태에 관한 보고서를 생성하는 작업을 예약합니다.
    • 데이터 분석 및 디버깅 에이전트 — AI Plugins로 Snowflake, GitHub 등의 도구에서 직접 작업을 수행하는 에이전트를 구축해, 쿼리 디버깅, 스키마 분석, 크로스 플랫폼 조사 같은 워크플로를 구현합니다.

    사전 요구 사항

    에이전트, 작업, 결정을 관리하려면 Manage Agents 플랫폼 권한이 있어야 합니다. 이 권한이 없으면 탐색 사이드바에 Agents 섹션이 표시되지 않습니다.

    이 권한이 없는 사용자도 Show in Ask DataHub Chat이 활성화된 에이전트와 상호작용할 수 있습니다. 다만 에이전트를 만들거나 구성할 수는 없습니다.

    에이전트

    에이전트는 페르소나, 즉 에이전트가 누구이고 무엇을 할 수 있으며 어떤 데이터를 볼 수 있는지를 캡슐화합니다. 에이전트에는 두 가지 종류가 있습니다.

    • 커스텀 에이전트 — 팀에서 UI로 만들며 모든 항목을 구성할 수 있습니다.
    • 기본 에이전트 — DataHub가 미리 만들어 플랫폼과 함께 제공합니다. 편집할 수는 없지만 작업과 채팅에 사용할 수 있습니다.

    에이전트 만들기

    Context > Agents로 이동해 Create Agent를 클릭합니다.

    필드 설명
    Name 에이전트의 표시 이름입니다.
    Tagline 에이전트 카드와 채팅 헤더에 표시되는 한 줄 설명입니다.
    Description 에이전트가 하는 일과 사용 시점입니다. Ask DataHub는 이 내용을 읽고 언제 질문을 이 에이전트로 라우팅할지 결정하므로 "X를 수행합니다. Y일 때 사용합니다."처럼 작성하세요.
    Instructions 에이전트 동작에 대한 자세한 지침입니다. @ 멘션으로 특정 자산을 참조할 수 있습니다.
    Tools 에이전트가 사용할 수 있는 DataHub 도구를 선택합니다(예: 검색, 리니지, 변경 작업).
    AI Plugins 외부 MCP 서버(예: Snowflake, GitHub)를 연결해 에이전트가 외부 도구에 접근할 수 있게 합니다.
    Scope 에이전트가 찾을 수 있는 자산과 문서를 By Domain 또는 By View로 제한합니다.
    Require Tool Review 에이전트가 메타데이터를 변경하는 도구를 실행하기 전에 채팅에서 확인을 요청합니다.
    Show in Ask DataHub Chat 활성화하면 이 에이전트가 Ask DataHub 채팅 인터페이스에서 선택 가능한 페르소나로 표시됩니다.

    에이전트 상세 페이지

    에이전트를 클릭하면 구성, 연결된 작업, 대기 중인 결정을 볼 수 있습니다. 여기에서 다음을 수행할 수 있습니다.

    • 에이전트 구성 편집
    • 채팅 드로어로 에이전트와 직접 채팅
    • 이 에이전트에 할당된 작업 생성
    • 에이전트가 요청한 대기 중인 결정 검토
    • Evals 탭에서 품질 추적: 이 에이전트를 대상으로 Context Evals를 실행하고 시간에 따른 통과율을 보여 줍니다

    DataHub 외부에서 에이전트 사용하기

    에이전트를 범위 지정 MCP 서버에 추가하면 단일 도구(예: ask_agent__finance-analyst)로 표시됩니다. 그러면 다른 에이전트와 MCP 클라이언트가 이 도구에 질문을 넘기고 답변을 받을 수 있습니다.

    이 방식으로 데이터 분석 에이전트를 구축하는 과정은 Build a Data Agent를 참고하세요.

    작업

    작업(task)은 에이전트에 할당되는 반복 가능한 지침입니다. 작업은 필요할 때, 일정에 따라, 또는 메타데이터 이벤트에 반응해 실행할 수 있습니다. 각 작업은 에이전트의 기본 지침, 도구 접근 권한, 플러그인 접근 권한, 기본 뷰를 상속합니다.

    작업 만들기

    Tasks 탭으로 이동하거나 에이전트 상세 페이지를 열고 Create Task를 클릭합니다.

    필드 설명
    Agent 이 작업을 실행할 에이전트입니다.
    Name 작업의 표시 이름입니다.
    Instructions 이 작업이 실행될 때 에이전트가 수행할 내용입니다.
    Allow Decisions 활성화하면 에이전트가 실행을 일시 중지하고 사람에게 입력을 요청할 수 있습니다.
    Trigger 작업을 시작하는 방식으로, Schedule 또는 Event입니다.

    일정 트리거

    일정 트리거는 cron 기반 구성을 사용합니다.

    • Frequency: 매시간(Hourly), 매일(Daily), 매주(Weekly)
    • Day of Week: (Weekly만 해당) 실행할 요일
    • Time of Day: (Daily/Weekly) 실행할 시각
    • Timezone: 일정의 시간대

    이벤트 트리거

    이벤트 트리거는 특정 메타데이터 이벤트가 발생할 때 실행됩니다. 현재 지원하는 이벤트는 다음과 같습니다.

    • Task Completion — 지정한 다른 작업이 완료되면 실행되어 작업을 연쇄적으로 수행할 수 있습니다

    향후 릴리스에서 이벤트 유형이 추가될 예정입니다.

    작업 실행하기

    작업의 트리거 방식과 관계없이, 작업 테이블이나 작업 상세 페이지에서 Run Now를 클릭하면 언제든 즉시 실행할 수 있습니다. 일정이나 이벤트 트리거를 활성화하기 전에 작업의 지침을 테스트하고 출력을 확인할 때 유용합니다.

    모달에는 에이전트의 사고 과정, 도구 호출, 결과를 포함한 진행 상황이 실시간으로 표시됩니다. 모달을 닫아도 실행은 취소되지 않습니다.

    작업 상세 페이지

    작업을 클릭하면 구성, 실행 기록, 대기 중인 결정을 볼 수 있습니다.

    • Active/Inactive 전환으로 일정 또는 이벤트 트리거 실행을 활성화하거나 비활성화
    • 작업 구성 편집
    • 작업을 필요할 때 실행
    • 실행별 상태, 소요 시간, 출력이 포함된 실행 기록 보기

    결정

    작업에 Allow Decisions가 활성화되어 있으면 에이전트가 실행 도중 일시 중지하고 사람의 입력을 요청할 수 있습니다. 이러한 요청은 Decisions 탭과 관련 에이전트/작업 상세 페이지에 표시됩니다.

    각 결정에는 다음이 표시됩니다.

    • 에이전트가 묻는 질문
    • 선택할 수 있는 미리 정의된 선택지(선택 사항)
    • 추가 컨텍스트를 입력하는 자유 텍스트 입력 필드(선택 사항)

    결정에 응답하기

    Respond를 클릭해 결정 모달을 열고, 옵션을 선택하거나 자유 텍스트를 입력한 뒤 제출합니다. 에이전트는 응답을 사용해 실행을 재개합니다.

    결정을 Dismiss할 수도 있으며, 이 경우 작업 실행이 중단됩니다.

    FAQ

    DataHub Cloud 없이 Agents를 사용할 수 있나요? 아니요. Agents는 DataHub Cloud Context 애드온에 포함됩니다.

    여러 작업이 같은 에이전트를 공유할 수 있나요? 예. 에이전트는 재사용 가능한 페르소나이므로, 지침과 트리거가 서로 다른 작업을 필요한 만큼 만들어 모두 같은 에이전트로 실행할 수 있습니다.

    아무도 결정에 응답하지 않으면 어떻게 되나요? 누군가 응답하거나 결정을 닫을 때까지 작업 실행은 "Waiting for Input" 상태로 일시 중지됩니다. 같은 작업의 예약된 재실행에는 영향을 주지 않습니다.

    에이전트가 접근할 수 있는 도구를 어떻게 제어하나요? 에이전트를 만들거나 편집할 때 Tools 선택기에서 특정 DataHub 도구를 활성화하거나 비활성화합니다. 외부 도구의 경우 AI Plugins를 구성해 MCP 서버를 연결하고 에이전트별로 접근 범위를 지정합니다.

    작업은 누구의 권한으로 실행되나요? 현재 작업은 해당 작업을 만든 사용자로 실행됩니다. 즉, 작업은 생성자가 가진 AI 플러그인 접근 권한과 권한을 상속합니다. 향후에는 권한을 제한할 수 있는 특정 서비스 계정으로 실행하는 기능을 지원할 계획입니다.

    작업 실행 중 에이전트가 수행한 도구 호출을 감사할 수 있나요? 예. 실행 기록에서 작업 실행 세부 정보를 열고 사고 블록을 펼치세요. 에이전트가 수행한 모든 도구 호출의 입력과 출력을 포함한 전체 추적을 볼 수 있습니다. 컴플라이언스와 거버넌스를 위한 완전한 감사 추적을 제공합니다.

    작업 실행 중에 작업 실행 모달을 닫으면 어떻게 되나요? 작업은 백그라운드에서 계속 실행됩니다. 작업의 실행 기록에서 상태와 출력을 확인할 수 있습니다.

    작업이 완료될 때 이메일, Slack, Teams로 알림을 받도록 구독할 수 있나요? 아직은 지원하지 않지만 곧 제공될 예정입니다!
