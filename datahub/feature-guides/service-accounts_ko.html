    서비스 계정

    기능 제공 범위: DataHub Core, DataHub Cloud

    DataHub Cloud v0.3.17, DataHub Core v1.4.0부터 사용할 수 있습니다.

    소개

    서비스 계정(Service Accounts)은 개인 사용자 자격 증명을 사용하지 않고 DataHub API에 프로그래밍 방식으로 접근할 수 있는 안전한 방법을 제공합니다. 자동화 워크플로, CI/CD 파이프라인, 데이터 수집 프로세스 등 사람이 아닌 ID가 DataHub와 상호작용해야 하는 모든 사용 사례를 위해 설계되었습니다.

    서비스 계정을 사용할 때의 주요 이점은 다음과 같습니다.

    1. 관심사 분리 - 자동화 자격 증명을 개인 사용자 계정에서 분리합니다
    2. 감사 가능한 접근 - 특정 자동화 워크플로별로 API 사용량을 추적합니다
    3. 세분화된 권한 - 서비스 계정별로 특정 역할과 정책을 할당합니다
    4. 토큰 관리 - 서비스 계정별로 토큰을 독립적으로 생성, 교체, 회수합니다
    5. 보안 - 사용자에게 영향을 주지 않고 접근 권한을 즉시 회수합니다

    사전 요구 사항과 권한

    서비스 계정을 관리하려면 Manage Service Accounts 플랫폼 권한이 있어야 합니다. 이 권한으로 다음을 할 수 있습니다.

    • 새 서비스 계정 만들기
    • 기존 서비스 계정 보기 및 나열
    • 서비스 계정 삭제
    • 서비스 계정의 액세스 토큰 생성

    기본적으로 Admin 역할의 사용자에게 이 권한이 있습니다. Policies로 다른 사용자나 그룹에 이 권한을 부여할 수 있습니다.

    서비스 계정 사용하기

    서비스 계정 접근

    서비스 계정은 DataHub의 Settings 페이지에서 관리할 수 있습니다.

    1. Settings(상단 탐색의 톱니바퀴 아이콘)로 이동합니다
    2. 왼쪽 사이드바에서 Users & Groups를 클릭합니다
    3. Service Accounts 탭을 선택합니다

    서비스 계정 만들기

    새 서비스 계정을 만드는 방법은 다음과 같습니다.

    1. Create Service Account 버튼을 클릭합니다
    2. 서비스 계정의 Name을 입력합니다(예: "Ingestion Pipeline", "CI/CD Bot")
    3. 선택적으로 서비스 계정의 목적을 설명하는 Description을 추가합니다
    4. Create를 클릭합니다

    서비스 계정에는 고유 식별자(URN)가 자동으로 할당됩니다. 이 URN의 형식은 다음과 같습니다.

    urn:li:corpuser:service_<uuid>

    액세스 토큰 생성

    서비스 계정을 만든 뒤 DataHub API에 인증하려면 액세스 토큰을 생성해야 합니다.

    1. Settings > Access Tokens로 이동합니다
    2. Generate new token을 클릭합니다
    3. 토큰 유형으로 Service Account를 선택합니다
    4. 드롭다운에서 서비스 계정을 선택합니다
    5. 토큰의 Name을 입력합니다(예: "production-ingestion-token")
    6. 토큰 유효 기간의 Duration을 선택합니다
    7. Generate를 클릭합니다

    주의: 중요

    생성된 토큰을 복사해 안전하게 보관하세요. 토큰은 한 번만 표시되며 나중에 다시 가져올 수 없습니다.

    서비스 계정에 역할 할당

    서비스 계정에 DataHub 역할을 할당해 권한을 제어할 수 있습니다. 역할을 할당하는 방법은 다음과 같습니다.

    1. Settings > Users & Groups > Service Accounts로 이동합니다
    2. 목록에서 서비스 계정을 찾습니다
    3. Role 드롭다운에서 역할(예: Admin, Editor, Reader)을 선택합니다
    4. 역할 할당을 확인합니다

    또는 서비스 계정을 Policies에 추가해 더 세분화된 권한을 제어할 수 있습니다.

    서비스 계정 삭제

    서비스 계정을 삭제하는 방법은 다음과 같습니다.

    1. Settings > Users & Groups > Service Accounts로 이동합니다
    2. 삭제할 서비스 계정을 찾습니다
    3. 오른쪽의 점 3개 더보기 메뉴를 클릭합니다
    4. Delete 버튼(휴지통 아이콘)을 클릭합니다

    경고

    서비스 계정을 삭제하면 연결된 모든 액세스 토큰이 즉시 무효화됩니다. 해당 토큰을 사용하는 자동화 워크플로는 모두 동작을 멈춥니다.

    액세스 토큰 회수

    서비스 계정 전체를 삭제하지 않고 특정 토큰을 회수하는 방법은 다음과 같습니다.

    1. Settings > Access Tokens로 이동합니다
    2. 회수할 토큰을 찾습니다
    3. Revoke를 클릭합니다
    4. 회수를 확인합니다

    서비스 계정 토큰 사용하기

    서비스 계정의 액세스 토큰을 생성하면 이를 사용해 DataHub API에 인증할 수 있습니다.

    DataHub CLI 사용

    # Set the token as an environment variable
export DATAHUB_GMS_TOKEN="<your-service-account-token>"

# Or pass it directly
datahub get --urn "urn:li:dataset:..."

    Python SDK 사용

    from datahub.emitter.rest_emitter import DatahubRestEmitter

# Create an emitter with service account token
emitter = DatahubRestEmitter(
    gms_server="http://localhost:8080",
    token="<your-service-account-token>"
)

# Use the emitter for API calls
emitter.emit(...)

    GraphQL API 사용

    curl -X POST 'https://your-datahub-instance/api/graphql' \
  -H 'Authorization: Bearer <your-service-account-token>' \
  -H 'Content-Type: application/json' \
  -d '{"query": "{ me { corpUser { urn } } }"}'

    REST API 사용

    curl 'https://your-datahub-instance/openapi/v3/entity/dataset/...' \
  -H 'Authorization: Bearer <your-service-account-token>'

    GraphQL API 참조

    GraphQL API로 서비스 계정을 프로그래밍 방식으로 관리할 수도 있습니다.

    서비스 계정 만들기

    mutation createServiceAccount($input: CreateServiceAccountInput!) {
  createServiceAccount(input: $input) {
    urn
    type
    name
    displayName
    description
    createdBy
    createdAt
  }
}

    변수:

    {
  "input": {
    "displayName": "My Ingestion Pipeline",
    "description": "Service account for automated data ingestion"
  }
}

    서비스 계정 나열

    query listServiceAccounts($input: ListServiceAccountsInput!) {
  listServiceAccounts(input: $input) {
    start
    count
    total
    serviceAccounts {
      urn
      name
      displayName
      description
      createdBy
      createdAt
      updatedAt
    }
  }
}

    변수:

    {
  "input": {
    "start": 0,
    "count": 20,
    "query": ""
  }
}

    서비스 계정 가져오기

    query getServiceAccount($urn: String!) {
  getServiceAccount(urn: $urn) {
    urn
    name
    displayName
    description
    createdBy
    createdAt
    updatedAt
  }
}

    서비스 계정 삭제

    mutation deleteServiceAccount($urn: String!) {
  deleteServiceAccount(urn: $urn)
}

    서비스 계정의 액세스 토큰 만들기

    mutation createAccessToken($input: CreateAccessTokenInput!) {
  createAccessToken(input: $input) {
    accessToken
    metadata {
      id
      actorUrn
      ownerUrn
      name
      description
    }
  }
}

    변수:

    {
  "input": {
    "type": "SERVICE_ACCOUNT",
    "actorUrn": "urn:li:corpuser:service_<uuid>",
    "name": "my-token-name",
    "duration": "ONE_YEAR"
  }
}

    유효한 기간 옵션(enum): ONE_HOUR, ONE_DAY, ONE_WEEK, ONE_MONTH, THREE_MONTHS, SIX_MONTHS, ONE_YEAR. NO_EXPIRY는 ACCESS_TOKEN_ALLOW_NO_EXPIRY=true일 때만 허용됩니다.

    duration 대신 durationIso(ISO-8601, 예: P30D 또는 P1Y)를 전달할 수도 있습니다. duration과 durationIso 중 정확히 하나가 필요합니다. 허용되는 ISO 값은 ACCESS_TOKEN_ALLOWED_DURATIONS로 구성합니다(생성 시 허용 목록이며 기존 토큰에는 영향을 주지 않습니다).

    모범 사례

    명명 규칙

    각 서비스 계정의 목적을 나타내는 설명적인 이름을 사용하세요.

    • ingestion-snowflake-prod - Snowflake 프로덕션 수집용
    • cicd-github-actions - GitHub Actions CI/CD 파이프라인용
    • airflow-metadata-sync - Airflow 메타데이터 동기화용

    토큰 교체

    보안을 유지하려면 서비스 계정 토큰을 정기적으로 교체하세요.

    1. 서비스 계정의 새 토큰을 생성합니다
    2. 자동화가 새 토큰을 사용하도록 업데이트합니다
    3. 이전 토큰을 회수합니다

    최소 권한 접근

    각 서비스 계정에 필요한 최소 권한을 할당하세요.

    • 수집 파이프라인: 특정 엔터티 유형의 생성/업데이트만 허용하는 커스텀 정책을 할당합니다
    • 읽기 전용 통합: Reader 역할 또는 커스텀 읽기 전용 정책을 사용합니다
    • 관리자 자동화: 꼭 필요한 경우에만 Admin 역할을 사용합니다

    FAQ 및 문제 해결

    Service Accounts 탭이 보이지 않는 이유는 무엇인가요?

    Service Accounts 탭은 Manage Service Accounts 권한이 있는 사용자에게만 표시됩니다. DataHub 관리자에게 접근을 요청하세요.

    서비스 계정 토큰이 동작을 멈췄습니다

    다음을 확인하세요.

    1. 토큰 만료: 토큰이 만료되었을 수 있습니다. 새 토큰을 생성하세요.
    2. 서비스 계정 삭제: 서비스 계정이 삭제되었을 수 있습니다. 새로 만드세요.
    3. 토큰 회수: 누군가 토큰을 회수했을 수 있습니다. 새로 생성하세요.
    4. 권한 변경: 서비스 계정의 권한이 수정되었을 수 있습니다.

    서비스 계정에 어떤 토큰이 있는지 볼 수 있나요?

    예. Settings > Access Tokens로 이동해 서비스 계정 이름으로 필터링하면 연결된 모든 토큰을 볼 수 있습니다. 토큰을 보려면 서비스 계정의 소유자로 필터링해야 합니다. 서비스 계정을 만든 사람이 토큰 소유자가 됩니다.

    서비스 계정을 삭제하면 토큰은 어떻게 되나요?

    서비스 계정을 삭제하면 연결된 모든 토큰이 무효화됩니다.

    정책에서 서비스 계정을 사용할 수 있나요?

    예. 서비스 계정은 일반 사용자처럼 정책에 추가할 수 있습니다. 정책 행위자를 구성할 때 서비스 계정의 URN(예: urn:li:corpuser:service_<uuid>)을 사용하세요.

    개인 액세스 토큰과 서비스 계정 토큰의 차이점은 무엇인가요?

    기능 개인 액세스 토큰 서비스 계정 토큰
    연결 대상 사용자 서비스 계정
    권한 사용자의 권한을 상속 서비스 계정의 역할/정책 기준
    회수의 영향 토큰 보유자에게만 영향 해당 자동화에만 영향
    사용 사례 개별 사용자 API 접근 자동화 워크플로와 통합
