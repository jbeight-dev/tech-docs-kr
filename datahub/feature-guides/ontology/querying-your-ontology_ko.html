    온톨로지 쿼리하기

    기능 제공 범위: DataHub Cloud 전용 · 비공개 베타

    이 페이지에서는 코드와 AI 에이전트에서 관계 그래프를 읽는 방법을 설명합니다.

    여기에 나오는 모든 인터페이스는 같은 다중 홉 관계 탐색을 실행합니다. 엔터티에서 시작해 지정한 관계 유형 집합을 최대 홉 수까지 따라가고, 도달한 모든 항목을 반환합니다.

    DataHub Cloud v2.2.1 이상에서 사용할 수 있으며 기능 플래그는 필요하지 않습니다.

    탐색 가능한 대상 찾기

    "모든 관계 유형"을 뜻하는 와일드카드는 없으므로 따라갈 유형을 직접 지정해야 합니다. 인스턴스에 어떤 유형이 있는지 알아보려면 관계 그래프 스키마를 내보내세요. 모든 관계 유형과 연결하는 엔터티 유형, 방향 의미, 내장(NATIVE) 또는 사용자 정의(CUSTOM) 여부가 반환됩니다.

    curl -H "Authorization: Bearer $DATAHUB_TOKEN" \
  "$DATAHUB_GMS_URL/openapi/v3/relationship/schema?entityType=glossaryTerm"

    PREFIX dh:     <urn:li:ontology:>
PREFIX et:     <urn:li:entityType:datahub.>
PREFIX rel:    <urn:li:relationshipType:>
PREFIX schema: <https://schema.org/>

rel:governedBy  rdf:type       rdf:Property ;
        rdfs:label             "Governed By" ;
        rdfs:comment           "The regulation or policy term that governs this concept." ;
        schema:domainIncludes  et:glossaryTerm ;
        schema:rangeIncludes   et:glossaryTerm ;
        dh:origin              "CUSTOM" ;
        dh:reverseDisplayName  "Governs" .

    반환되는 주어가 바로 아래에서 관계 유형으로 전달하는 값입니다. Turtle이 아닌 형식을 원하면 ?format=json-ld(또는 n-triples, rdf-xml)를 추가하세요.

    REST API로 탐색하기

    GET /openapi/v3/relationship/traverse는 그래프를 따라가 도달한 엔터티를 반환합니다.

    curl -H "Authorization: Bearer $DATAHUB_TOKEN" \
  "$DATAHUB_GMS_URL/openapi/v3/relationship/traverse\
?urn=urn:li:glossaryTerm:customer\
&relationshipTypes=IsA\
&relationshipTypes=urn:li:relationshipType:governedBy\
&direction=UNDIRECTED\
&maxHops=2"

    {
  "count": 2,
  "total": 2,
  "partial": false,
  "relationships": [
    {
      "relationshipType": "urn:li:relationshipType:governedBy",
      "entityType": "glossaryTerm",
      "urn": "urn:li:glossaryTerm:gdpr",
      "degree": 1,
      "degrees": [1],
      "directionMode": "DIRECTED",
      "transitive": false,
      "reverseDisplayName": "Governs"
    },
    {
      "relationshipType": "IsA",
      "entityType": "glossaryTerm",
      "urn": "urn:li:glossaryTerm:businessCustomer",
      "degree": 1,
      "degrees": [1],
      "directionMode": "DIRECTED",
      "transitive": false
    }
  ]
}

    매개변수

    매개변수 의미
    urn 시작할 엔터티입니다. 필수입니다.
    relationshipTypes 반복 가능합니다. 내장 이름(IsA, HasA, DownstreamOf, …) 또는 urn:li:relationshipType:* URN을 사용하며 동일하게 탐색합니다. urn:li:structuredProperty:* URN도 허용되며, 이 URN이 가리키는 관계 유형으로 해석됩니다. includeLineage=true가 아니면 필수입니다.
    direction OUTGOING(기본값), INCOMING, UNDIRECTED입니다. 엣지는 메타데이터를 가진 엔터티에서 참조하는 엔터티를 가리키므로, X에서 INCOMING을 사용하면 엣지가 X를 가리키는 엔터티를 반환합니다. 대칭 관계 유형은 이 값과 관계없이 양방향으로 탐색합니다.
    maxHops 탐색 깊이로, 1–20입니다. 기본값은 1입니다.
    entityTypes 반복 가능합니다. 최종 결과뿐 아니라 모든 홉에서 방문하는 엔터티 유형을 제한합니다.
    includeLineage 리니지 관계 유형을 나열하지 않고 같은 호출에서 전체 네이티브 리니지 엣지 집합도 탐색합니다.
    lineageDirection UPSTREAM, DOWNSTREAM, BOTH(기본값)입니다. includeLineage=true일 때만 의미가 있습니다.
    resolveEquivalents 요청한 표준 어휘 술어(예: skos:broader)를 이를 동등 속성으로 선언한 관계 유형으로 확장합니다.

    degree는 시작 엔터티로부터의 홉 거리이고, degrees는 엔터티에 도달한 모든 깊이를 나열합니다. partial: true는 탐색이 제한에 도달했거나 시간 초과되었음을 뜻하므로 쿼리 범위를 좁히세요.

    GraphQL로 탐색하기

    searchAcrossRelationships 쿼리는 같은 탐색에 엔터티 정보 채우기와 페이징을 더한 것입니다. 온톨로지 그래프 UI 자체가 이 쿼리를 호출합니다.

    query {
  searchAcrossRelationships(
    input: {
      urn: "urn:li:glossaryTerm:customer"
      relationshipTypes: ["IsA", "HasA", "urn:li:relationshipType:governedBy"]
      direction: UNDIRECTED
      maxHops: 2
      count: 50
    }
  ) {
    total
    isPartial
    relationships {
      relationshipType
      degree
      directionMode
      transitive
      reverseDisplayName
      entity {
        urn
        ... on GlossaryTerm {
          properties {
            name
            description
          }
        }
      }
    }
  }
}

    start와 count로 페이징합니다. isPartial은 위의 partial과 같은 의미입니다.

    참고: 리니지는 별도의 축입니다

    relationshipTypes와 direction은 명명된 관계 탐색에만 적용됩니다. includeLineage가 true이면 전체 네이티브 리니지 엣지 집합도 탐색하며(lineageDirection으로만 제어), 두 탐색 결과를 합칩니다. 순수한 데이터 흐름 질문("이 테이블에 데이터를 공급하는 것은 무엇인가?")에는 그 용도로 만들어진 리니지 API를 대신 사용하세요.

    AI 에이전트로 쿼리하기

    DataHub의 MCP 서버는 같은 탐색을 get_relationships 도구로 노출하므로, 어시스턴트가 온톨로지 질문에 바로 답할 수 있습니다. 위의 스키마 내보내기에 해당하는 MCP 도구인 get_metadata_graph와 함께 사용하면, 에이전트는 어떤 것도 하드코딩하지 않고 존재하는 관계 유형을 찾아 탐색할 수 있습니다.

    에이전트에게 제공하면 유용한 패턴은 다음과 같습니다.

    먼저 get_metadata_graph를 호출해 이 인스턴스에서 어떤 관계 유형이 어떤 엔터티 유형을 연결하는지 확인한 다음, 질문과 관련된 유형으로 get_relationships를 호출하세요.

    get_relationships는 REST 매개변수(urn, relationship_types, direction, max_hops, entity_types, include_lineage, lineage_direction)를 그대로 따르고, 에이전트가 필요한 엔터티 필드만 가져오도록 fields 허용 목록을 추가합니다. 덕분에 토큰 예산 안에 더 많은 결과를 담을 수 있습니다. 결과는 페이징됩니다. 응답의 nextOffset을 offset으로 다시 전달하고, hasMore가 false이면 중지합니다.

    에이전트를 인스턴스에 연결하는 방법은 DataHub MCP 서버를 참고하세요.

    실용적인 참고 사항

    • 유형을 지정하세요. 와일드카드는 없습니다. 잘못된 유형으로 탐색하면 아무것도 반환되지 않으며, 관계가 없는 엔터티를 탐색한 결과와 똑같아 보입니다.
    • 다중 홉 탐색에서 entityTypes에 주의하세요. 필터가 모든 홉에 적용되므로 제외된 엔터티 유형을 지나는 경로는 끊어집니다. maxHops > 1이면 생략하는 것이 좋습니다.
    • isPartial / partial을 확인하세요. 제한에 걸린 탐색은 빈 결과가 아닙니다. 잘린 답변을 믿지 말고 관계 유형이나 엔터티 유형을 좁히거나 홉 수를 줄이세요.
    • 권한 부여가 적용됩니다. 탐색은 호출자가 볼 수 있는 엔터티만 반환합니다.

    쿼리 자체를 탐색 매개변수가 아닌 표준 그래프 쿼리 언어로 표현해야 한다면 SPARQL을 사용한 고급 쿼리를 참고하세요.
