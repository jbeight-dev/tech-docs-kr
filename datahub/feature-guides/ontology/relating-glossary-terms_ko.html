    용어집 용어 연결하기

    기능 제공 범위: DataHub Cloud 전용 · 비공개 베타

    관계는 용어집을 온톨로지로 바꾸는 요소입니다. 이 페이지에서는 UI와 API로 관계를 만드는 방법을 설명합니다.

    사전 요구 사항

    • 연결할 용어가 이미 있어야 합니다. 용어와 용어 그룹을 만드는 방법은 Business Glossary를 참고하세요.
    • 용어의 관계를 편집하려면 Manage Glossaries 플랫폼 권한 또는 해당 용어에 대한 Edit Entity가 필요합니다.

    올바른 관계 선택하기

    탐색, 전파, AI 도구는 관계 유형을 기준으로 동작하므로 올바른 유형을 선택할 필요가 있습니다.

    표현하려는 내용 사용할 관계 방향
    B는 A의 더 구체적인 종류입니다 Inherits (Is A) 방향 있음
    A는 B로 구성됩니다(B는 A의 일부 또는 속성) Contains (Has A) 방향 있음
    A와 B는 같은 의미입니다 Synonym 방향 없음
    A와 B는 반대 의미입니다 Antonym 방향 없음
    B는 A를 다른 언어나 방언으로 표현한 것입니다 Translates to 방향 있음
    B는 A의 허용 값 중 하나입니다 Valid value 방향 있음
    A와 B는 연결되어 있지만 위의 어느 것도 맞지 않습니다 Related to 방향 없음

    방향이 있는 관계는 방향에 따라 다르게 읽히므로 역방향 레이블도 있습니다. Inherits는 Inherited by, Contains는 Contained by, Translates to는 Translated from, Valid value는 Valid value for로 읽힙니다. 방향이 없는 관계는 양방향으로 같게 읽히며 한 번만 만들면 됩니다.

    Related to는 다른 어떤 관계도 맞지 않을 때만 사용하세요. 두 용어가 연결되어 있다는 사실만 기록하고 어떻게 연결되었는지는 기록하지 않으므로 탐색에서 활용할 정보가 없습니다. 이 관계를 자주 사용하게 된다면 커스텀 관계 유형이 필요할 가능성이 높습니다.

    UI에서 관계 추가하기

    1. 연결할 용어집 용어를 엽니다.
    2. Related Terms 탭으로 이동합니다.
    3. + Add Terms를 클릭합니다.
    4. 관계 유형을 선택한 다음 하나 이상의 용어를 검색해 선택합니다.
    5. Add를 클릭합니다.

    관계 유형 선택기에는 내장 유형과 인스턴스에 정의된 모든 커스텀 관계 유형이 나열됩니다.

    탭은 관계를 유형별로 묶으며, 유형별 필터 칩에는 인스턴스에 정의된 커스텀 관계 유형을 포함해 용어가 가진 관계 수가 표시됩니다.

    관계는 현재 보고 있는 용어를 기준으로 작성됩니다. 방향이 있는 관계에서는 해당 용어가 소스입니다. Individual Customer 페이지에서 Inherits → Customer를 추가하면 "Individual Customer inherits Customer"로 기록되며, Customer 페이지의 Inherited by 아래에 Individual Customer가 표시됩니다.

    대칭 관계(Synonym, Antonym, Related to)는 어느 쪽에서든 같게 읽히므로 편한 용어에서 한 번만 만들면 됩니다.

    관계를 제거하려면 Related Terms 탭에서 관련 용어에 마우스를 올리고 제거 작업을 사용합니다. 어느 쪽에서 제거하든 엣지가 삭제됩니다.

    API로 관계 추가하기

    addRelatedTerms GraphQL mutation은 소스 용어의 관계에 하나 이상의 용어를 추가합니다.

    mutation {
  addRelatedTerms(
    input: {
      urn: "urn:li:glossaryTerm:individualCustomer"
      termUrns: ["urn:li:glossaryTerm:customer"]
      relationshipType: isA
    }
  )
}

    relationshipType 값은 다음과 같습니다.

    값 관계
    isA Inherits
    hasA Contains
    synonymOf Synonym of
    antonymOf Antonym of
    translatesTo Translates to
    hasValue Valid value
    isRelatedTo Related to

    관계를 삭제하려면 같은 입력 형태로 removeRelatedTerms를 사용합니다.

    관계 일괄 로드

    엣지가 몇 개를 넘어가면 UI를 클릭하는 대신 메타데이터로 관계를 로드하세요. glossaryRelatedTerms aspect는 용어의 모든 나가는 관계를 담으므로 용어당 한 번의 쓰기로 충분합니다.

    from datahub.emitter.mce_builder import make_term_urn
from datahub.emitter.mcp import MetadataChangeProposalWrapper
from datahub.ingestion.graph.client import DatahubClientConfig, DataHubGraph
from datahub.metadata.schema_classes import GlossaryRelatedTermsClass

graph = DataHubGraph(DatahubClientConfig(server="http://localhost:8080"))

graph.emit(
    MetadataChangeProposalWrapper(
        entityUrn=make_term_urn("individualCustomer"),
        aspect=GlossaryRelatedTermsClass(
            isRelatedTerms=[make_term_urn("customer")],  # Inherits
            hasRelatedTerms=[make_term_urn("customerId")],  # Contains
            synonymOf=[make_term_urn("retailCustomer")],
        ),
    )
)

    경고

    glossaryRelatedTerms aspect를 쓰면 용어의 기존 관계가 교체됩니다. 이미 관계가 있는 용어에 추가한다면 현재 aspect를 읽어 병합하세요.

    Business Glossary 수집 파일에 inherits와 contains 관계를 직접 표현할 수도 있습니다. 용어집 자체를 버전 관리한다면 가장 깔끔한 방법입니다.

    이후 동작

    추가한 모든 관계는 DataHub 메타데이터 그래프의 엣지로 구체화됩니다. 이후 다음이 가능합니다.

    • 온톨로지 그래프에 그려집니다 — 온톨로지 시각화하기를 참고하세요.
    • API와 AI 에이전트로 따라갈 수 있습니다 — 온톨로지 쿼리하기를 참고하세요.
