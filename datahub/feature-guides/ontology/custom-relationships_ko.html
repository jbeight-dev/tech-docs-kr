    커스텀 관계 추가하기

    기능 제공 범위: DataHub Cloud 전용 · 비공개 베타

    내장 어휘인 Inherits, Contains, Synonym, Antonym, Translates to, Valid value, Related to는 범용 용어집 모델링을 다루지만 조직 고유의 어휘는 다루지 않습니다. governed by, derived from, certified by, supersedes 같은 관계에는 자체 관계 유형을 정의할 수 있습니다.

    이때 relationship Structured Property를 사용합니다.

    DataHub Cloud v2.2.1 이상에서 사용할 수 있습니다.

    동작 방식

    값 유형이 DataHub 엔터티인 Structured Property는 이미 한 자산에서 다른 자산을 가리킵니다. 해당 속성의 relationship 스위치를 켜면 DataHub는 각 할당을 메타데이터 그래프의 실제 엣지로도 구체화합니다. 그러면 속성이 일급 관계처럼 동작해, 온톨로지 그래프에 그려지고, traverse API로 따라갈 수 있으며, SPARQL로 도달할 수 있습니다.

    두 엔터티가 관련되며, 각각의 역할을 알아 두면 좋습니다.

    • 구조화된 속성은 겉면입니다. 사용자가 할당하고 속성 UI에 표시되는 대상입니다.
    • 관계 유형(urn:li:relationshipType:*)은 술어의 정체성을 담습니다. 표시 이름, 방향 의미, 전이성, 역방향 레이블, RDF 술어 매핑이 여기에 해당합니다. 그래프 엣지의 키는 속성이 아니라 이 관계 유형입니다.

    보통 관계 유형을 직접 만들 필요는 없습니다. UI와 GraphQL 생성/업데이트 경로가 관계 유형을 만들고 포인터를 연결해 줍니다.

    UI에서 관계 속성 만들기

    1. Govern → Structured Properties로 이동해 새 속성을 만듭니다.
    2. value type을 DataHub 엔터티 유형으로 설정하고, 허용 유형을 관계가 가리킬 대상으로 제한합니다. 용어 간 관계라면 양쪽 모두 Glossary Term입니다.
    3. Display Preferences를 열고 Treat as Relationship을 켭니다.
    4. 관계의 의미를 구성합니다(아래 참고).
    5. 저장합니다.

    Treat as Relationship 스위치는 엔터티 값 속성에서만 사용할 수 있습니다. 그렇지 않으면 가리킬 대상이 없기 때문입니다. 속성의 값 유형을 엔터티 유형이 아닌 것으로 전환하면 관계 설정이 지워집니다.

    관계 의미

    스위치를 켜면 네 가지 설정이 관계의 의미를 정의합니다.

    설정 동작
    Direction Directed(기본값)는 소스 → 대상으로 진행합니다. Undirected는 대칭이며, 요청한 방향과 관계없이 양방향으로 따라갑니다.
    Reverse Label 방향성 관계를 역방향으로 읽을 때의 레이블입니다(정방향 "Governed By"에 대한 "Governs"). 표시 전용이며 두 번째 엣지를 만들지 않습니다.
    Transitive 이 관계의 연쇄가 의미 있음을 선언합니다. A → B → C는 A → C를 의미합니다. 탐색 클라이언트에 제공되며 SPARQL의 RDFS 체제에서 사용됩니다.
    Equivalent Properties 이 관계에 해당하는 표준 어휘 술어를 CURIE 또는 IRI(skos:broader, skos:exactMatch)로 지정합니다. 표준 기반 쿼리가 엣지에 도달할 수 있게 합니다.

    신중하게 설정하세요. 방향과 전이성은 관계를 따라가는 방식에 영향을 주므로 그래프를 탐색하는 모든 대상이 받는 결과가 달라집니다.

    API로 관계 속성 만들기

    mutation {
  createStructuredProperty(
    input: {
      id: "governedBy"
      qualifiedName: "governedBy"
      displayName: "Governed By"
      description: "The regulation or policy term that governs this concept."
      valueType: "urn:li:dataType:datahub.urn"
      cardinality: MULTIPLE
      entityTypes: ["urn:li:entityType:datahub.glossaryTerm"]
      typeQualifier: {
        allowedTypes: ["urn:li:entityType:datahub.glossaryTerm"]
      }
      settings: {
        isRelationship: true
        relationshipSemantics: {
          directionMode: DIRECTED
          reverseDisplayName: "Governs"
          transitive: false
          equivalentProperties: ["skos:broader"]
        }
      }
    }
  ) {
    urn
  }
}

    이렇게 하면 구조화된 속성과 이 속성이 가리키는 관계 유형(속성의 id를 공유하는 urn:li:relationshipType:governedBy)이 모두 만들어집니다.

    관계 할당하기

    정의한 뒤에는 다른 구조화된 속성처럼 할당합니다. 값은 반대쪽 끝에 있는 엔터티의 URN입니다.

    mutation {
  upsertStructuredProperties(
    input: {
      assetUrn: "urn:li:glossaryTerm:customer"
      structuredPropertyInputParams: [
        {
          structuredPropertyUrn: "urn:li:structuredProperty:governedBy"
          values: [{ stringValue: "urn:li:glossaryTerm:gdpr" }]
        }
      ]
    }
  ) {
    properties {
      structuredProperty {
        urn
      }
    }
  }
}

    용어집 용어에서 커스텀 관계는 Related Terms 탭에 내장 관계와 함께 표시되며, 여기에서 추가하고 제거할 수 있습니다.

    엣지는 비동기로 구체화되므로, 새로 할당한 관계가 그래프와 traverse API에 나타나기까지 잠시 시간이 걸립니다.

    커스텀 관계 쿼리하기

    커스텀 관계 유형은 내장 유형과 똑같이 탐색합니다. 내장 이름을 전달하는 위치에 관계 유형 URN을 전달하세요.

    curl -H "Authorization: Bearer $DATAHUB_TOKEN" \
  "$DATAHUB_GMS_URL/openapi/v3/relationship/traverse\
?urn=urn:li:glossaryTerm:customer\
&relationshipTypes=urn:li:relationshipType:governedBy\
&direction=OUTGOING"

    구조화된 속성 URN(urn:li:structuredProperty:governedBy)도 허용되며 같은 관계 유형으로 해석됩니다. 온톨로지 쿼리하기를 참고하세요.

    모델링 지침

    • 의미당 하나의 관계. 실제 의미를 설명하는 주석을 달아 Related to를 재사용하지 마세요. 별도의 유형이 있어야 엣지를 쿼리하고 추론할 수 있습니다.
    • 양방향 이름 지정. 역방향 표시 이름은 비용이 들지 않으며, 그래프의 모든 역방향 뷰를 읽기 쉽게 만듭니다.
    • 실제로 전이적일 때만 표시. 전이성은 추론을 허용하므로, 잘못 선언하면 폐포 계산에서 확신에 찬 잘못된 답변이 나옵니다.
    • 맞는 표준이 있으면 매핑. skos:broader나 rdfs:subClassOf를 동등 속성으로 선언하면 외부 도구와 표준 기반 쿼리가 DataHub의 이름을 몰라도 관계에 도달할 수 있습니다.
    • 속성을 삭제하면 엣지도 제거됩니다. relationship 구조화된 속성을 제거하면 이 속성이 구체화한 그래프 엣지도 정리됩니다.

    이 기능 활성화하기

    인스턴스에서 활성화하려면 DataHub 담당자에게 문의하세요.

    플래그가 없으면 DataHub는 새 관계 속성을 정의하려는 시도를 거부합니다. 엣지가 조용히 구체화되지 않는 관계를 선언하지 못하게 하기 위해서입니다.

    자체 관리 배포에서는 플래그를 설정하고 재시작합니다.

    STRUCTURED_PROPERTY_GRAPH_EDGES_ENABLED=true

    플래그는 GMS와, 독립 실행형 컨슈머를 실행한다면 MAE 및 MCE 컨슈머에서 일치해야 합니다. MAE 컨슈머는 엣지를 구체화하고 MCE 컨슈머는 관계 속성 정의를 제어합니다. Helm에서는 하나의 전역 값이 셋 모두에 적용됩니다.

    global:
  datahub:
    structuredPropertyGraphEdgesEnabled: true
