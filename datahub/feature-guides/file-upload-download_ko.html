    문서의 파일 업로드 및 다운로드

    기능 제공 범위: DataHub Core, DataHub Cloud

    DataHub의 파일 업로드 및 다운로드 기능을 사용하면 이미지, 다이어그램 같은 지원 파일로 자산 및 컬럼 문서를 보강해, 데이터 카탈로그를 더 유익하고 이해하기 쉽게 만들 수 있습니다.

    문서에 파일 업로드를 사용하는 이유

    파일 업로드는 데이터 자산을 문서화하고 소통하는 방식을 다음과 같이 바꿉니다.

    • 문서 품질 향상: 시각적 다이어그램, 아키텍처 도면, 스크린샷을 문서에 바로 추가해 복잡한 개념을 설명합니다
    • 리소스 중앙화: 관련 문서 자료를 여러 시스템에 흩어 두지 않고 데이터 자산과 함께 한곳에 보관합니다
    • 이해도 향상: 맥락에 바로 포함된 시각 자료로 사용자가 데이터 구조, 파이프라인, 관계를 더 빨리 파악하도록 돕습니다
    • 소통 표준화: 텍스트와 시각 요소를 결합한 일관되고 전문적인 문서를 만듭니다

    복잡한 데이터 파이프라인을 문서화하는 데이터 엔지니어, 예시 스크린샷으로 컬럼 정의를 설명하는 데이터 분석가, 참조 자료를 제공하는 데이터 스튜어드 모두, 파일 업로드로 문서를 더 포괄적이고 접근하기 쉽게 만들 수 있습니다.

    포함된 항목

    지원되는 파일 유형

    현재 이미지는 문서 안에 인라인으로 표시됩니다. 다른 유형의 파일은 업로드하고 다운로드할 수 있으며, 향후 릴리스에서 PDF와 텍스트 파일 같은 추가 인라인 미리 보기를 지원할 예정입니다.

    업로드 방법

    문서에 파일을 추가하는 편리한 방법은 두 가지입니다.

    • 끌어다 놓기: 파일 시스템의 파일을 문서 편집기로 바로 끌어다 놓습니다
    • 업로드 버튼: 편집기 도구 모음의 파일 업로드 버튼을 클릭해 파일 시스템에서 파일을 찾아 선택합니다

    파일 관리

    파일을 업로드하면 DataHub는 자동으로 다음을 수행합니다.

    • 파일의 메타데이터(유형, 크기, 원본 파일 이름)를 추적하는 새 dataHubFile 엔터티를 만듭니다
    • 파일을 업로드한 위치의 컨텍스트(자산 문서, 컬럼 문서 등)를 저장합니다
    • 사용자가 파일을 다운로드하려고 할 때 이 컨텍스트 정보로 권한을 적용합니다

    파일은 S3에 안전하게 저장되며, 접근은 파일이 업로드된 자산에 대한 사용자 권한을 기준으로 제어됩니다.

    파일 업로드 설정

    파일 업로드 기능을 사용하려면 DataHub를 S3 스토리지에 연결하도록 구성해야 합니다.

    사전 요구 사항

    AWS 역할 인증이 원활히 동작하려면 DataHub 인스턴스가 AWS에 배포되어 있어야 합니다.

    필수 구성

    DataHub GMS 서비스에 다음 환경 변수를 설정합니다.

    DATAHUB_BUCKET_NAME

    업로드된 파일을 저장할 S3 버킷의 이름입니다.

    DATAHUB_BUCKET_NAME=your-datahub-files-bucket

    DATAHUB_ROLE_ARN

    S3 버킷에서 파일을 업로드하고 다운로드할 권한이 구성된 AWS 역할 ARN입니다.

    DATAHUB_ROLE_ARN=arn:aws:iam::123456789012:role/DataHubFileAccessRole

    AWS 역할 구성

    AWS 역할은 다음 두 가지 핵심 요구 사항에 맞게 올바르게 구성해야 합니다.

    S3 권한

    역할에는 S3 버킷과 상호작용하기 위한 적절한 권한이 필요합니다. 최소한 다음을 포함해야 합니다.

    • s3:PutObject - 파일 업로드
    • s3:GetObject - 파일 다운로드
    • s3:DeleteObject - 사용하지 않는 파일의 가비지 컬렉션

    역할에 연결된 IAM 정책으로 이러한 권한을 구성합니다.

    신뢰 관계

    DataHub GMS 서비스가 역할을 맡을(assume) 수 있도록 역할의 신뢰 관계를 업데이트합니다. 신뢰 정책은 DataHub GMS가 실행되는 AWS 서비스 또는 역할이 이 역할을 맡도록 허용해야 합니다.

    신뢰 관계를 올바르게 구성하지 않으면 DataHub가 AWS에 인증해 S3 버킷에 접근할 수 없습니다.

    파일 업로드하기

    문서에 파일을 추가하는 방법은 다음과 같습니다.

    1. 문서를 추가할 자산이나 컬럼으로 이동합니다
    2. 문서 편집기를 엽니다
    3. 다음 중 하나를 수행합니다.
      • 파일을 편집기로 바로 끌어다 놓거나,
      • 도구 모음의 파일 업로드 버튼을 클릭하고 파일 시스템 대화상자에서 파일을 선택합니다
    4. 이미지는 바로 인라인으로 표시되고, 다른 파일 유형은 다운로드 링크로 표시됩니다
    5. 문서 변경 사항을 저장합니다

    파일은 편집기에 추가하는 즉시, 문서 변경 사항을 저장하기 전에도 S3에 업로드됩니다.

    파일 다운로드하기

    사용자가 업로드된 파일이 포함된 문서를 볼 때 다음과 같이 표시됩니다.

    • 이미지: 문서 안에 자동으로 인라인 표시됩니다
    • 기타 파일: 사용자가 클릭해 파일을 받을 수 있는 다운로드 링크로 표시됩니다

    권한 확인

    사용자가 파일을 다운로드하려고 하면 DataHub는 파일이 원래 업로드된 자산이나 컬럼을 볼 권한이 있는지 확인합니다. 이를 통해 파일 접근이 기존 DataHub 권한 구조를 따르도록 보장합니다.

    연결된 자산을 볼 권한이 없는 사용자는 직접 링크가 있더라도 파일을 다운로드할 수 없습니다.

    파일 메타데이터와 추적

    업로드된 각 파일은 DataHub에서 dataHubFile 엔터티로 표현되며, 다음을 저장합니다.

    • 파일 유형: 업로드된 파일의 MIME 유형
    • 파일 크기: 바이트 단위 크기
    • 원본 파일 이름: 업로드 당시의 파일 이름
    • 업로드 컨텍스트: 파일이 추가된 엔터티(자산 또는 컬럼)

    이 메타데이터는 파일 검색, 사용량 추적, 고아 파일 정리 같은 향후 기능에 활용됩니다.

    모범 사례

    문서에서 파일 업로드를 사용할 때는 다음을 따르세요.

    • 설명적인 파일 이름 사용: 원본 파일 이름이 유지되므로 나중에 파일을 쉽게 식별할 수 있습니다
    • 이미지 크기 최적화: 큰 이미지는 로드하는 데 오래 걸릴 수 있으므로 업로드 전에 크기 조정을 고려하세요
    • 컨텍스트 제공: 이미지 주변에 설명 텍스트를 추가해 사용자가 보고 있는 내용을 설명합니다
    • 대용량 파일의 대안 고려: 매우 큰 파일은 직접 업로드하는 대신 외부 스토리지로 연결하는 것을 고려하세요
    • 권한 검토: 사용자에게 이 기능을 활성화하기 전에 S3 역할과 버킷 권한이 올바르게 구성되어 있는지 확인합니다

    문제 해결

    파일이 업로드되지 않음

    파일 업로드에 실패하면 다음을 확인합니다.

    • DATAHUB_BUCKET_NAME이 올바르게 설정되어 있고 버킷이 존재하는지
    • DATAHUB_ROLE_ARN이 유효하고 기존 역할을 가리키는지
    • AWS 역할의 신뢰 관계가 DataHub GMS의 역할 맡기를 허용하는지
    • 역할에 필요한 S3 권한(s3:PutObject)이 있는지
    • S3 버킷에 호스트 URL의 업로드를 허용하는 CORS 정책이 설정되어 있는지

    파일이 다운로드되지 않음

    사용자가 파일을 다운로드할 수 없으면 다음을 확인합니다.

    • 사용자에게 파일이 업로드된 자산을 볼 권한이 있는지
    • AWS 역할에 버킷에 대한 s3:GetObject 권한이 있는지
    • 파일이 S3에 아직 존재하는지(수동으로 삭제되지 않았는지)

    인증 문제

    AWS 인증 오류가 표시되면 다음을 수행합니다.

    • DataHub 인스턴스가 AWS에 배포되어 있는지 확인합니다
    • AWS 역할의 신뢰 관계 구성을 확인합니다
    • GMS 서비스에 필요한 AWS 자격 증명 또는 인스턴스 프로필이 있는지 확인합니다

    다음 단계

    문서에서 파일 업로드를 사용하는 방법을 이해했으니 이제 다음을 진행합니다.

    • 환경 구성: 필요한 S3 버킷과 AWS 역할을 설정합니다
    • 이미지로 테스트: 먼저 자산 문서에 이미지를 업로드해 인라인 표시가 어떻게 동작하는지 확인합니다
    • 팀 교육: 데이터 소유자와 스튜어드에게 시각 자료로 문서를 보강하는 방법을 알려 줍니다
    • 사용량 모니터링: S3 버킷을 주시해 스토리지 요구 사항을 파악합니다
    • 업데이트 확인: PDF 미리 보기와 추가 파일 유형 지원 같은 향후 기능을 확인합니다

    파일 업로드는 DataHub 문서를 더 포괄적이고 사용하기 쉽게 만들어, 조직이 더 풍부하고 유익한 데이터 카탈로그를 구축하도록 돕습니다.
