    데이터 액세스 역할

    정보

    이 기능은 현재 비공개 베타(Private Beta)입니다.

    소개

    DataHub의 Access Roles 기능을 사용하면 소스 시스템의 외부 역할을 DataHub의 데이터 자산과 함께 수집할 수 있습니다. 사용자는 특정 자산에 접근하려면 어떤 역할이 필요한지 알 수 있습니다.

    Data Access Workflows는 테이블, 대시보드 등의 접근을 요청하고 검토하는 워크플로를 만드는 기능입니다. 반면 이 기능을 사용하면 특정 자산에 이미 접근 권한이 있는 역할을 확인하고, 외부 플랫폼으로 이동해 해당 역할의 접근을 요청할 수 있습니다.

    이를 통해 데이터 생태계 전반의 접근 제어를 한곳에서 볼 수 있으며, 데이터 소비자에게 다음과 같은 도움을 줍니다.

    1. 사용 가능한 접근 권한 찾기 - 여러 데이터 플랫폼에서 자신에게 이미 프로비저닝된 역할을 찾습니다
    2. 적절한 접근 권한 요청 - 필요한 접근에 알맞은 역할을 쉽게 식별하고 가입을 요청합니다
    3. 거버넌스 단순화 - 역할 정보를 DataHub에 모아 접근 관리 프로세스를 간소화합니다

    외부 역할을 DataHub에 통합하면 접근 요청의 번거로움을 줄이고, 사용자가 필요한 데이터에 적절한 수준의 접근 권한을 갖도록 보장할 수 있습니다.

    구성

    DataHub Core

    DataHub Core 배포에서는 Access Management 기능이 기본적으로 비활성화되어 있습니다. 활성화하려면 datahub-gms 서비스 컨테이너의 SHOW_ACCESS_MANAGEMENT 환경 변수를 true로 설정하면 됩니다. 예를 들어 docker/datahub-gms/docker.env에 다음과 같이 구성합니다.

    SHOW_ACCESS_MANAGEMENT=true

    DataHub Cloud

    DataHub Cloud를 사용 중이라면 DataHub Cloud Customer Success 담당자에게 문의하기만 하면 Access Management 기능을 활성화할 수 있습니다. 담당자가 별도의 구성 변경 없이 사용자 환경에서 이 기능을 활성화해 줍니다.

    UI 위치

    올바르게 구성되었다면 데이터셋 아래에 "Access Management"라는 새 탭이 나타납니다.

    데이터 모델

    Access Management는 DataHub 메타데이터 모델에 Role이라는 새 엔터티를 도입합니다. Role은 다음으로 구성됩니다.

    • 고유 키(URN)
    • 역할의 속성(이름, 설명, 유형, 요청 URL)
    • 해당 역할이 프로비저닝된 사용자 목록

    그런 다음 access라는 새 aspect를 통해 이 역할을 데이터셋과 연결해야 합니다.

    참고: 중요 참고 사항

    현재는 Dataset 엔터티만 Access Management를 지원합니다.

    주의: role과 datahubrole을 혼동하지 마세요

    "role" 엔터티는 소스 시스템(Snowflake, BigQuery 등)에 존재하는 외부 역할 정의를 가리킵니다. 반면 "datahubrole"은 DataHub 자체의 권한을 관리하기 위한 것입니다(예: admin 역할은 제안된 메타데이터 변경을 수락할 수 있습니다).

    DataHub에서 접근 관리하기

    Access Management는 CLI나 Python API로 설정할 수 있습니다. 세 가지 주요 단계는 다음과 같습니다.

    외부 역할 생성

    datahub put --urn "urn:li:role:reader" --aspect roleProperties -d - <<-EOF
{
  "name": "Snowflake Reader Role",
  "description": "Description for Snowflake Reader Role",
  "type": "READ",
  "requestUrl": "http://custom-url-for-redirection.com"
}
EOF

    import datahub.emitter.mce_builder as builder
from datahub.emitter.rest_emitter import DatahubRestEmitter
from datahub.emitter.mcp import MetadataChangeProposalWrapper
from datahub.metadata.schema_classes import RolePropertiesClass, ChangeTypeClass

# Create a role properties aspect
role_properties = RolePropertiesClass(
    name="Snowflake Reader Role",
    description="Description for Snowflake Reader Role",
    type="READ",
    requestUrl="http://custom-url-for-redirection.com"
)

# Create a metadata change proposal
mcp = MetadataChangeProposalWrapper(
    changeType=ChangeTypeClass.UPSERT,
    entityUrn="urn:li:role:reader",
    aspectName="roleProperties",
    aspect=role_properties
)

# Emit the metadata
emitter = DatahubRestEmitter(gms_server="http://localhost:8080")
emitter.emit(mcp)

    역할에 사용자 할당(선택 사항)

    datahub put --urn "urn:li:role:reader" --aspect actors -d - <<-EOF
{
  "users": [
    {"user": "urn:li:corpuser:datahubuser"}
  ]
}
EOF

    from datahub.metadata.schema_classes import ActorsClass, ActorClass

# Create an actors aspect
actors = ActorsClass(
    users=[
        ActorClass(user="urn:li:corpuser:datahubuser")
    ]
)

# Create a metadata change proposal
mcp = MetadataChangeProposalWrapper(
    changeType=ChangeTypeClass.UPSERT,
    entityUrn="urn:li:role:reader",
    aspectName="actors",
    aspect=actors
)

# Emit the metadata
emitter.emit(mcp)

    데이터셋에 역할 할당

    datahub put --urn "urn:li:dataset:(urn:li:dataPlatform:hive,fct_users_created,PROD)" --aspect access -d - <<-EOF
{
  "roles": [
    {"urn": "urn:li:role:reader"},
    {"urn": "urn:li:role:writer"}
  ]
}
EOF

    from datahub.metadata.schema_classes import AccessClass, RoleAssociationClass

dataset_urn = "urn:li:dataset:(urn:li:dataPlatform:hive,fct_users_created,PROD)"

# Create an access aspect with multiple roles
access_aspect = AccessClass(
   roles=[
       RoleAssociationClass(urn="urn:li:role:reader"),
       RoleAssociationClass(urn="urn:li:role:writer")
   ]
)

# Create a metadata change proposal
mcp = MetadataChangeProposalWrapper(
   changeType=ChangeTypeClass.UPSERT,
   entityUrn=dataset_urn,
   aspectName="access",
   aspect=access_aspect
)

# Emit the metadata
emitter.emit(mcp)

    사용 사례

    외부 역할을 DataHub에 통합하면 유용한 대표적인 시나리오는 다음과 같습니다.

    1. 통합 접근 현황 - 데이터 엔지니어가 여러 플랫폼에 걸쳐 민감한 데이터에 접근할 수 있는 모든 사용자를 하나의 인터페이스에서 확인합니다
    2. 셀프서비스 접근 요청 - 분석가가 특정 데이터셋에 접근하는 데 필요한 역할을 찾아 DataHub에서 바로 요청합니다
    3. 접근 감사 - 컴플라이언스 팀이 누가 어떤 역할을 통해 어떤 데이터셋에 접근할 수 있는지 검토합니다
    4. 온보딩 가속화 - 새로운 팀원이 자신의 직무에 필요한 접근 권한을 빠르게 파악합니다

    Access Management의 향후 계획

    Access Management에 계획된 개선 사항은 다음과 같습니다.

    • 역할뿐 아니라 외부 정책도 모델링
    • BigQuery, Snowflake 등의 소스에서 역할과 정책을 자동으로 추출
    • 데이터셋 외의 더 많은 엔터티 유형으로 지원 확대
    • 승인을 포함한 고급 접근 요청 워크플로
