    Metrics & Semantic Models

    기능 제공 범위: DataHub Core, DataHub Cloud

    주의: 베타

    Metrics & Semantic Models는 현재 베타(Beta)입니다. 기반 엔터티 모델은 안정적이지만 UI 환경, 리니지 시각화, 수집 범위는 활발히 개선되고 있습니다. 앞으로 몇 차례 릴리스에 걸쳐 사이드바 탐색, 엔터티 페이지 레이아웃, 리니지 렌더링이 계속 개선될 예정입니다.

    팁: 모델링 지침을 찾고 있나요?

    이 가이드는 Metrics & Semantic Models가 무엇이고 어떻게 켜는지를 다룹니다. 비즈니스 개념을 모델링하는 권장 패턴(Glossary Term과 Metric을 언제 사용할지, Snowflake와 dbt에서 같은 KPI를 어떻게 표현할지, 메트릭 리니지가 처음부터 끝까지 어떻게 동작하는지)은 Metrics & Semantic Models — 모범 사례를 참고하세요.

    Metrics & Semantic Models를 사용하는 이유

    DataHub Metrics는 메트릭 정의를 위한 카탈로그로, 팀이 비즈니스 측정값을 문서화하고, 찾고, 거버넌스하는 방식을 바꿉니다.

    • 정의에 대한 단일 기준 정보 — 각 메트릭을 소유자, 설명, 계산, 차원 컨텍스트와 함께 한 번만 카탈로그화해 "어떤 매출 수치가 맞는가?"라는 논쟁을 끝냅니다.
    • KPI에서 소스와 소비자까지 이어지는 리니지 — 모든 메트릭을 읽는 논리 데이터셋을 거쳐 그 바탕이 되는 물리 테이블과 컬럼까지, 그리고 이를 소비하는 Charts, Dashboards, Datasets까지 추적합니다.
    • AI를 위한 컨텍스트 — 모든 메트릭에 동의어, 자연어 지침, 예시 질문을 연결해, 에이전트와 Ask DataHub가 추측하는 대신 카탈로그화된 정의를 기준으로 자연어 질문을 해석하게 합니다.
    • 다른 자산과 같은 거버넌스 — Metrics와 Semantic Models는 완전한 DataHub 엔터티입니다. 소유자, 도메인, 태그, 용어집 용어, 구조화된 속성, 문서를 Datasets와 같은 방식으로 연결합니다.
    • 이식 가능하고 도구에 종속되지 않는 모델 — 이 모델은 모든 시맨틱 계층의 메트릭을 받아들이도록 설계되었으므로(현재 Snowflake Semantic Views와 dbt, 알파 단계인 Cube와 MicroStrategy, 로드맵에 있는 Databricks metric views와 추가 BI 도구 메트릭), 카탈로그에 투자하는 것이 하나의 도구에 베팅하는 일이 아닙니다. Apache Ossie와의 필드 수준 중복은 별도로 문서화되어 있습니다.

    포함된 항목

    이 기능에는 두 가지 새로운 엔터티 유형이 포함됩니다.

    Semantic Model

    Semantic Model은 데이터셋 그룹, 데이터셋 간의 관계(즉, 허용되는 조인 패턴), 해당 데이터셋에서 파생할 수 있는 차원과 메트릭을 정의합니다. 그 위에서 계산되는 메트릭을 뒷받침하는 차원 컨텍스트 역할을 합니다.

    각 Semantic Model 페이지에는 다음이 포함됩니다.

    • Governance — 이름, 설명, 소유자, 도메인, 태그, 구조화된 속성, 용어집 용어.
    • Datasets — 모델이 노출하는 논리 데이터셋(각각 Semantic Model Dataset 하위 유형의 완전한 DataHub Dataset).
    • Relationships — 모델의 논리 데이터셋 간 조인 경로와 카디널리티, 선택적 AI 컨텍스트 힌트.
    • Related Metrics — 이 모델이 뒷받침하는 모든 메트릭.
    • Definition — 왕복 변환과 디버깅을 위해 그대로 보존된 소스 플랫폼 DDL / YAML(예: Snowflake CREATE SEMANTIC VIEW 문).
    • AI Context — LLM 지원 탐색을 위한 동의어, 자연어 지침, few-shot 예시.
    • Lineage — 모델의 구성원 데이터셋과 메트릭을 둘러싼 경계 상자. 홉은 Semantic Model 자체가 아니라 이러한 구성원(및 그 물리/BI 이웃)을 거칩니다.

    Metric

    Metric은 total_revenue, daily_active_users, conversion_rate 같은 명명된 비즈니스 측정값의 SQL 계산을 명시적으로 정의하며, 선택적으로 AI Context를 포함해 에이전트가 동의어, 메트릭이 답해야 할 예시 질문, 샘플 쿼리를 이해하도록 돕습니다.

    각 Metric 페이지에는 다음이 포함됩니다.

    • Expression — 메트릭을 계산하는 SQL로, 하나 이상의 방언(ANSI_SQL, SNOWFLAKE, MDX, TABLEAU, DATABRICKS, MAQL, OTHER)을 사용합니다.
    • Semantic Model — 이 메트릭이 계산되는 모델.
    • Derived From / Related Metrics — 상위 메트릭과 의미상 동급 메트릭(예: total_revenue와 customer_count에서 파생된 revenue_per_customer).
    • AI Context — 동의어(revenue, topline, gross), 지침, 샘플 질문.
    • Governance — 이름, 설명, 소유자, 도메인, 태그, 구조화된 속성, 용어집 용어.
    • Lineage — 업스트림으로는 메트릭이 읽는 논리 및 물리 데이터셋, 다운스트림으로는 이를 소비하는 Charts, Dashboards, Datasets. Semantic Model은 구성원을 둘러싼 경계 상자이며 체인의 홉이 아닙니다.

    Semantic Model Datasets

    Semantic Model이 노출하는 모든 논리 데이터셋은 그 자체로 하위 유형이 Semantic Model Dataset인 완전한 Dataset 엔터티입니다. 즉, 각 논리 데이터셋에는 dbt Sources, Looker Views, Snowflake Dynamic Tables와 똑같이 자체 스키마, 거버넌스 표면, 리니지 그래프, 검색 결과가 있습니다.

    각 필드에는 DIMENSION(그룹화/필터링 속성), MEASURE(집계 가능한 숫자 값), FILTER(명명된 불리언 조건자) 중 무엇인지 식별하는 시맨틱 주석과 기반 SQL 표현식, 측정값의 경우 집계 함수가 포함됩니다.

    사전 요구 사항

    DataHub Cloud 고객: Metrics & Semantic Models를 사용하려면 DataHub Cloud 2.1.0 이상이 필요합니다. 이 기능은 2.3.0부터 기본적으로 켜져 있으며, 조직에서 끄려면 DataHub 담당자에게 문의하세요.

    DataHub Core(OSS) 배포: DataHub Core v1.7.0 이상에서 사용할 수 있습니다. 이 기능은 v1.8.0부터 기본적으로 켜져 있습니다. UI에서 Metrics를 숨기려면 GMS 서비스에 METRICS_ENABLED=false를 설정합니다.

    GraphQL app-config 쿼리로 플래그를 확인합니다.

    {
  appConfig {
    featureFlags {
      metricsEnabled
    }
  }
}

    왼쪽 탐색 사이드바에 Beta 배지와 함께 Metrics 섹션이 표시됩니다.

    메트릭 수집

    Snowflake Semantic Views에서 수집

    DataHub의 Snowflake 커넥터는 Snowflake Semantic Views에서 Semantic Models와 Metrics를 직접 내보냅니다.

    Snowflake recipe에서 활성화합니다.

    source:
  type: snowflake
  config:
    account_id: ...
    username: ...
    include_technical_schema: true

    semantic_views:
      enabled: true # ingest Semantic Views at all
      emit_semantic_model_entities: null # tri-state — see below
      column_lineage: true # physical→logical column lineage

    emit_semantic_model_entities 제어 옵션에는 세 가지 상태가 있습니다.

    값 동작
    null(기본값) 자동 감지합니다. Metrics가 활성화된 DataHub Cloud ≥ 2.1.0에서는 SM/Metric 엔터티를 내보냅니다. 그 외(이전 Cloud, 명시적 옵트인이 없는 OSS/자체 호스팅, 연결 없는 실행)에서는 기존 Semantic View 데이터셋으로 대체됩니다.
    true SM/Metric 내보내기를 요청합니다. Cloud에서는 서버와 플래그가 지원하면 적용되며, OSS에서는 운영자가 이러한 엔터티를 등록하는 서버를 실행해야 합니다.
    false 서버가 새 엔터티를 지원하더라도 기존 Semantic View 데이터셋 동작을 강제합니다.

    Snowflake Semantic Views는 Snowflake의 네이티브 기능입니다. Semantic Views 위에 Cortex Analyst 통합도 사용한다면 이 통합은 Snowflake Enterprise Edition 이상으로 제한되지만, Semantic Views를 DataHub에 카탈로그화하는 작업은 Cortex에 의존하지 않습니다.

    Cube와 MicroStrategy에서 수집

    Cube와 MicroStrategy 소스도 Semantic Models와 Metrics를 내보낼 수 있습니다. recipe에 emit_semantic_model_entities: true를 설정하세요. 둘 다 알파 단계입니다.

    DataHub Python SDK에서 내보내기

    상위 수준 SDK 빌더(datahub.sdk.SemanticModel, .Metric, .SemanticModelDataset)를 사용해 스크립트나 커넥터에서 프로그래밍 방식으로 메트릭과 시맨틱 모델을 내보냅니다.

    from datahub.sdk import (
    DataHubClient,
    DialectExpressionInput,
    Metric,
    SemanticModel,
)

client = DataHubClient(server="...", token="...")

model = SemanticModel(
    platform="snowflake",
    path="analytics",
    id="orders_model",
    name="Orders Model",
    description="Sales analytics semantic model",
    datasets=[...],
    relationships=[...],
)

metric = Metric(
    platform="snowflake",
    path="analytics.orders_model",
    id="total_revenue",
    name="Total Revenue",
    description="Sum of order amounts.",
    semantic_model=model.urn,
    expression=DialectExpressionInput(
        dialect="SNOWFLAKE",
        expression="SUM(orders.amount)",
    ),
)

for mcp in [*model.as_mcps(), *metric.as_mcps()]:
    client.entities.upsert(mcp)

    전체 튜토리얼과 참조: Semantic Models & Metrics SDK 가이드.

    메트릭 탐색

    찾아보기

    왼쪽 탐색의 Metrics 항목을 클릭하면 Semantic Model별로 그룹화된 찾아보기 트리가 있는 랜딩 페이지 /metrics가 열립니다. 모델을 펼치면 해당 모델이 뒷받침하는 메트릭을 볼 수 있습니다. 소유자, 도메인, 태그, 플랫폼으로 필터링하고 정렬합니다.

    검색

    Metrics와 Semantic Models는 전역 검색과 검색창 자동 완성에 표시됩니다. 표시 이름, 설명, 플랫폼으로 검색하고, Type 필터로 Metrics 또는 Semantic Models로 좁힙니다. Semantic Model별로 그룹화된 메트릭을 탐색하는 가장 좋은 방법은 여전히 전용 /metrics 찾아보기 트리입니다. Browse V2에는 이러한 엔터티 유형이 나열되지 않으므로 Search 또는 /metrics를 사용하세요.

    리니지

    Metric의 Lineage 탭에는 업스트림 측에 메트릭이 읽는 데이터셋(및 그 물리 소스)이, 다운스트림 측에 이를 소비하는 Charts, Dashboards, Datasets가 표시됩니다. 파생 메트릭은 Metric 간 홉으로 표시됩니다.

    Semantic Model은 구성원 데이터셋과 메트릭을 둘러싼 경계 상자로, 이들을 시각적으로 묶지만 그 자체가 리니지 그래프의 홉은 아닙니다. Semantic Model의 Lineage 탭을 열면 상자 안에 구성원이 그려지며, 구성원을 펼치면 물리 및 BI 이웃이 나타납니다.

    Impact Analysis는 엔터티 수준에서 양방향으로 동작합니다. 컬럼 수준 영향 분석(물리 컬럼에서 모든 다운스트림 메트릭 필드까지)은 아직 로드맵에 있습니다.

    거버넌스

    Metrics와 Semantic Models는 DataHub의 표준 거버넌스 표면을 재사용합니다.

    • Owners — 사용자, 그룹, 역할별로 소유권을 할당합니다.
    • Domains — 메트릭을 비즈니스 도메인(Sales, Marketing, Finance 등)으로 묶습니다.
    • Tags & Glossary terms — 데이터셋에 사용하는 것과 같은 분류 체계를 적용합니다. Certified, Deprecated, PII 태그가 예상대로 동작합니다.
    • Structured properties — 타입이 지정된 메타데이터(메트릭 가산성, 메트릭 종류, 측정값 형태 등)로 모델을 확장합니다.
    • Documentation & links — 긴 형식의 문서와 조직의 지식.

    AI Context

    모든 Semantic Model, Metric, 시맨틱 주석이 달린 필드에는 AI Context 레코드를 포함할 수 있습니다.

    • Synonyms — 메트릭을 부르는 다른 이름(ARPU ↔ revenue_per_customer).
    • Instructions — LLM이 메트릭을 해석하거나 쿼리할 때 사용할 자연어 지침.
    • Examples — 메트릭의 사용 방식을 보여 주는 샘플 질문이나 SQL 스니펫.
    • Custom instructions — 임의의 구조화된 힌트.

    향후 릴리스에서는 AI Context가 Ask DataHub와 카탈로그를 기반으로 하는 모든 에이전트에 바로 제공되어, URN이 아닌 자연어 참조로 메트릭 정의를 찾을 수 있게 됩니다.

    향후 계획

    Metrics 환경에 적극적으로 투자하고 있습니다. 단기 작업은 다음과 같습니다.

    • 에이전트 워크플로 중에 에이전트가 가져올 수 있도록 하는 DataHub MCP를 통한 Metrics & Semantic Models.
    • 추가 수집 소스. Snowflake Semantic Views와 dbt를 넘어 Databricks Unity Catalog metric views, Sigma, BI 도구 측정값까지 확장합니다.
    • 소스 컬럼에서 메트릭까지 이어지는 컬럼 수준 리니지. 컬럼에서 메트릭까지 완전한 영향 분석으로, 원시 컬럼 변경이 어떤 KPI에 영향을 주는지 확인합니다.
    • 리니지 시각화 개선. 더 깔끔한 노드 레이블, 접힌 중간 노드, 그래프 노이즈를 줄이는 Semantic Model 컨테이너 뷰.
    • AI 네이티브 탐색. Ask DataHub가 동의어와 표현식 인식 SQL을 사용해 자연어 질문을 카탈로그화된 메트릭 정의로 해석합니다.

    FAQ

    DataHub가 메트릭 값을 쿼리할 수 있나요? 아니요. DataHub는 계산, 차원 컨텍스트, 리니지, 거버넌스 등 메트릭 정의를 위한 카탈로그입니다. 값 계산과 시각화는 BI 도구나 시맨틱 계층에서 수행합니다.

    Metrics를 사용하려면 Snowflake가 필요한가요? 아니요. Python SDK로 모든 소스에서 Semantic Models와 Metrics를 내보낼 수 있습니다. Snowflake Semantic Views는 바로 사용할 수 있는 첫 번째 수집 경로이며, 더 많은 경로를 준비 중입니다.

    이 기능이 출시되기 전에 수집한 기존 Snowflake Semantic Views는 어떻게 되나요? DataHub에 기존 Semantic View 데이터셋으로 유지됩니다. 새 모델로 이전할 준비가 되면 datahub migrate snowflake-semantic-views CLI가 거버넌스(소유자, 도메인, 태그, 용어집 용어, 문서, 사용 중단, 애플리케이션, 컬럼 수준 태그/용어)를 새 Semantic Model 및 Metric URN으로 복사합니다. 마이그레이션은 자동이 아니므로, DataHub 담당자에게 문의해 전환을 계획하세요. 리니지와 정책은 CLI로 마이그레이션되지 않습니다. 이후 emit_semantic_model_entities: true로 Snowflake 수집을 실행해 구조적 aspect를 채우세요.

    메트릭은 환경별로 구분되나요? 아니요. Metric URN은 의도적으로 환경 한정자(PROD, STAGING 등)를 생략합니다. PROD와 STAGING의 total_revenue는 같은 메트릭 엔터티로 해석됩니다. 플랫폼 간 메트릭(예: dbt와 Snowflake 모두에 정의된 같은 측정값)은 URN에 플랫폼이 인코딩되므로 별개로 유지됩니다.

    메트릭에 커스텀 속성(예: 가산성, 측정값 형태)을 추가할 수 있나요? 예. Metrics는 Structured Properties, 즉 타입이 지정되고 거버넌스로 제어되며 검색 패싯을 지원하는 커스텀 필드를 지원합니다. 아직 일급 스키마 필드로 만들 정도는 아닌 플랫폼별 메타데이터에 사용하세요.
