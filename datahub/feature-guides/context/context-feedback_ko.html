    Context Feedback

    기능 제공 범위: DataHub Cloud 전용 · 공개 베타

    정보: Context 애드온

    Context Feedback은 DataHub Cloud Context 애드온에 포함됩니다.

    에이전트는 자신이 확신하지 못할 때를 압니다. 에이전트가 정의를 찾지 못하거나, 서로 다른 두 정의를 발견하거나, 사용자에게 수정을 받으면 Context Feedback에 메모를 기록합니다. 메모는 한곳에 모이므로 팀은 실제 사용에서 컨텍스트가 부족한 부분을 확인하고, 각 공백을 한 번 수정한 뒤, eval을 추가해 수정 상태를 유지할 수 있습니다.

    피드백 동작 방식

    1. 에이전트가 질문에 답하는 중에 컨텍스트의 공백에 부딪힙니다.
    2. 공백의 종류, 이를 유발한 질문, 관련 자산을 담은 짧은 메모를 기록합니다. 메모에는 데이터 값이나 쿼리 결과가 절대 포함되지 않습니다.
    3. 메모는 Validation > Feedback에 표시되어 팀이 검토할 수 있습니다.
    4. 검토자가 근본적인 컨텍스트를 수정하고, 해당 질문의 eval을 추가하고, 메모를 해결 처리합니다.

    에이전트는 네 가지 공백을 보고합니다.

    유형 의미
    Missing context 에이전트가 필요한 것을 찾지 못했습니다.
    Incorrect context 찾은 내용이 잘못되었거나 오래되었습니다.
    Conflicting context 두 소스의 내용이 서로 다릅니다.
    User correction 사용자가 답변이 틀렸다고 말하고 이유를 설명했습니다.

    Ask DataHub와 커스텀 에이전트는 공백을 자동으로 보고합니다. 자체 에이전트는 DataHub MCP 서버를 통해 보고할 수 있으며, 오픈소스 datahub-sql-workflow 스킬이 에이전트에 그렇게 하도록 지시합니다.

    스크린샷: Validation > Feedback에서 피드백을 검토하는 화면.

    피드백에 대응하기

    Validation > Feedback을 열어 에이전트가 보고한 내용을 확인합니다. 각 메모에 대해 공백이 실제로 존재하는지 확인한 다음, 누락된 정의 작성, 설명 명확화, 오래된 테이블 사용 중단 등으로 그 원인이 되는 컨텍스트를 수정합니다. DataHub 어시스턴트가 메모를 조사해 도움이 될 최소한의 변경을 제안할 수 있습니다. 승인하기 전에는 아무것도 변경되지 않습니다.

    컨텍스트를 수정한 뒤에는 공백을 드러낸 질문에 대한 eval을 추가하고 메모를 해결 처리합니다. 시간이 지나면 eval 모음이 조직이 실제로 묻는 질문을 반영하게 됩니다.

    같은 테이블에 관한 여러 메모는 보통 하나의 근본 문제를 가리키므로 함께 검토하는 것이 좋습니다. 시간이 지나도 컨텍스트를 유지 관리하는 과정에서 피드백이 어떤 역할을 하는지는 5단계: 컨텍스트 피드백과 개선을 참고하세요.

    API 접근

    DataHub GraphQL API로 피드백 나열과 상태 업데이트 등 프로그래밍 방식으로 피드백을 관리할 수도 있습니다.

    FAQ

    피드백이 표시되지 않습니다. Settings > AI에서 피드백 수집이 켜져 있는지 확인하세요. 외부 에이전트는 datahub-sql-workflow 스킬 등으로 지시받은 경우에만 공백을 보고합니다.

    Ask DataHub의 좋아요와 싫어요가 피드백을 생성하나요? 아니요. 이러한 평가는 DataHub가 제품을 개선하는 데 도움을 줍니다. Context Feedback은 에이전트가 컨텍스트의 공백을 발견할 때 생성되며, 사용자가 에이전트를 수정한 경우가 많습니다.

    누가 피드백을 검토할 수 있나요? Manage Context Feedback 권한이 있는 사람이면 누구나 가능합니다. Admins와 Editors에게는 기본적으로 이 권한이 있습니다.
