    Certification

    기능 제공 범위: DataHub Cloud 전용 · 공개 베타

    정보: Context 애드온

    Certification은 DataHub Cloud Context 애드온에 포함됩니다.

    대부분의 조직에는 어떤 질문의 답처럼 보이는 테이블, 대시보드, 문서가 여럿 있지만 실제 답은 하나뿐입니다. 인증(Certification)을 사용하면 데이터를 잘 아는 사람이 어느 것을 신뢰해야 하는지 지정할 수 있습니다. 자산이나 문서를 인증하면 DataHub는 그것이 나타나는 모든 곳에 표시를 남기고, 누가 왜 보증했는지 기록하며, 이 신호를 AI 에이전트에 전달합니다. 그러면 에이전트는 신뢰할 수 있는 소스를 바탕으로 답변을 구성하고, 그렇게 할 수 없을 때는 이를 알립니다.

    인증 동작 방식

    1. Certify 권한이 있는 사람이 자산이나 문서를 인증합니다. 이유를 설명하는 메모를 선택적으로 남길 수 있습니다.
    2. DataHub는 해당 페이지, 검색 결과, 리니지, 언급되는 모든 위치에서 이름 옆에 인증 표시를 보여 줍니다. 표시 위에 마우스를 올리면 인증한 사람, 시점, 메모를 볼 수 있습니다.
    3. AI 에이전트는 어떤 소스가 인증되었는지 확인하고 해당 소스를 우선해 답변을 구성합니다. Ask DataHub는 답변이 아무도 인증하지 않은 컨텍스트에 의존하는 경우에도 사용자에게 알려 주며, 자체 에이전트에도 같은 동작을 하도록 지침을 제공할 수 있습니다.

    인증할 수 있는 대상은 다음과 같습니다.

    범주 인증할 수 있는 대상
    데이터 자산 데이터셋, 대시보드, 차트, 데이터 파이프라인, 데이터 태스크, 컨테이너
    시맨틱 계층 메트릭과 시맨틱 모델
    컨텍스트 생성된 문서를 포함한 컨텍스트 문서

    스크린샷: 데이터셋의 인증 표시와, 인증한 사람, 시점, 이유를 보여 주는 호버 카드.

    인증할 수 있는 사람

    자산이나 문서를 인증하거나 인증을 제거하려면 해당 자산이나 문서에 대한 Certify 권한이 있어야 합니다.

    • Admins와 Editors는 기본적으로 모든 자산을 인증할 수 있습니다.
    • 그 외의 사람은 자산 소유자를 포함해, 관리자가 정책에서 Certify를 부여해야 합니다. 정책으로 모든 자산이나 특정 도메인의 자산 같은 일부 자산에 대해 권한을 부여할 수 있으므로, 각 영역의 담당자가 해당 영역의 대상을 인증하도록 할 수 있습니다.

    자산 편집 권한에는 인증 권한이 포함되지 않습니다. 인증이 조직이 신뢰하는 사람의 의도적인 결정으로 남도록 하기 위해서입니다. 인증은 항상 인증한 사람의 이름으로 기록됩니다.

    자산과 문서 인증하기

    • 자산 페이지에서: 헤더의 인증 아이콘을 클릭하거나 ⋮ 메뉴에서 Certify를 선택합니다. 메모를 추가하고 Certify를 클릭합니다.
    • 문서에서: 페이지 오른쪽 상단의 인증 아이콘을 클릭합니다.
    • 일괄 인증: Context > Certification을 열고 Certify Assets를 클릭한 다음 인증할 자산을 검색해 선택합니다.

    메모에는 "예약 매출의 기준 데이터입니다. 테스트 계정은 제외합니다."처럼 자산을 무엇에 신뢰할 수 있는지 작성합니다. 사람과 에이전트는 이 메모를 읽고 자산이 자신의 질문에 맞는지 판단합니다.

    인증을 제거하려면 인증 아이콘을 다시 클릭하거나 Remove certification을 선택합니다. 인증은 편집할 수 없습니다. 메모를 변경하려면 인증을 제거한 뒤 자산을 다시 인증하세요.

    스크린샷: 데이터셋 페이지에서 메모와 함께 인증하는 화면.

    인증된 자산 관리하기

    Context > Certification에는 조직이 인증한 모든 항목이 항목별 인증자, 시점, 방법과 함께 나열됩니다. 유형이나 소스로 필터링하고, 이름으로 검색하고, 인증을 하나씩 또는 일괄로 제거할 수 있습니다.

    인증된 자산은 검색하는 모든 곳에서도 찾을 수 있습니다. Certification으로 필터링하거나 View에 Certification을 조건으로 추가하세요.

    스크린샷: 인증된 자산이 나열된 Certification 페이지.

    AI 에이전트의 인증 활용 방식

    DataHub는 에이전트에 자산과 문서를 반환할 때 어떤 항목이 인증되었는지 알려 주며, 에이전트는 인증된 소스를 우선해 답변을 구성합니다. Ask DataHub는 답변이 아무도 인증하지 않은 컨텍스트에 의존하는 경우에도 사용자에게 알려 줍니다. DataHub의 MCP 서버로 연결된 에이전트도 같은 정보를 받지만, 사용자에게 알릴지는 각 에이전트의 지침에 따라 달라집니다. 에이전트 응답에 인증 활용하기를 참고하세요.

    인증은 신뢰가 가장 중요한 상황에서 에이전트에 도움이 됩니다.

    • Text-to-SQL: 여러 테이블이 질문에 답할 수 있을 때 에이전트는 인증된 테이블로 쿼리를 구성하며, 질문을 다루는 인증된 소스가 없으면 Ask DataHub가 사용자에게 알려 줍니다.
    • 데이터 탐색: 누군가 데이터를 어디서 찾는지 물으면, 에이전트는 표현이 우연히 일치하는 사본보다 인증된 자산을 먼저 안내합니다.

    스크린샷: Ask DataHub가 인증된 테이블을 바탕으로 답변하면서 인증되었음을 알리는 화면.

    에이전트 응답에 인증 활용하기

    Ask DataHub는 별도 설정 없이 인증을 활용합니다. DataHub의 MCP 서버로 연결된 에이전트는 어떤 소스가 인증되었는지 볼 수 있지만, 사용자에게 어떻게 설명할지는 각 에이전트의 지침에 따라 달라집니다. 답변을 공유해도 되는지 항상 사용자에게 알리는 등 에이전트가 답변에서 인증을 설명하는 방식을 정확히 제어하려면, 인증을 해석하는 방법을 지침에 추가하세요. 커스텀 에이전트의 지침이나 자체 에이전트가 사용하는 스킬에 추가하면 됩니다.

    예를 들면 다음과 같습니다.

    ## Qualifying responses through certification

Each context document and data asset used in this flow is either certified or
not. Certified assets are those that data team admins have explicitly identified
as trustworthy.

## Explaining unverified sources in answers

When a response depends on sources that DataHub inferred automatically, rather
than ones a person wrote, curated, or certified, qualify the response clearly,
and say that it should be reviewed before it is fully trusted or shared
publicly.

## Explaining certified sources in answers

When a response depends only on certified context documents and data assets,
say that only certified sources were used to generate the answer, to help build
trust with the users who rely on your answers.

    API 접근

    DataHub GraphQL API의 updateCertification 및 batchUpdateCertification mutation으로 프로그래밍 방식으로 인증하고 인증을 제거할 수도 있습니다.

    FAQ

    인증 아이콘이나 Certification 페이지가 보이지 않습니다. Certify 권한이 필요합니다. Certification 페이지를 사용하려면 모든 자산에 대한 권한도 있어야 합니다. 특정 도메인의 자산처럼 일부 자산만 인증할 수 있다면 해당 자산의 페이지에서 인증하세요.

    인증이 만료되나요? 아니요. 누군가 제거할 때까지 유지됩니다.

    인증하면 자산에 접근할 수 있는 사람이 달라지나요? 아니요. 인증은 신뢰 신호이며 접근 제어가 아닙니다.

    자산이 변경되면 인증은 어떻게 되나요? 아무 일도 일어나지 않습니다. 인증은 그대로 유지되므로, 정의가 변경되면 인증된 자산을 검토하세요.
