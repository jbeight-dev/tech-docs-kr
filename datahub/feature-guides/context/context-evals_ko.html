    Context Evals

    기능 제공 범위: DataHub Cloud 전용

    정보: Context 애드온

    Context Evals는 DataHub Cloud Context 애드온에 포함됩니다.

    Context Evals는 에이전트가 DataHub의 컨텍스트를 사용해 실제 비즈니스 질문에 올바르게 답할 수 있는지 측정합니다. 각 eval은 질문과 전문가가 제시할 답변을 짝지은 것입니다. DataHub는 일정에 따라 eval을 실행하고, AI 판정자가 모든 응답의 점수를 매깁니다. eval이 실패하면 보통 컨텍스트의 공백을 가리킵니다. 공백을 해결하면 다음 실행에서 통과합니다.

    컨텍스트를 추가하기 전에 eval을 먼저 정의해 모든 변경 사항을 측정하기를 권장합니다. Build a Data Agent 가이드의 1단계: eval 정의를 참고하세요.

    eval 동작 방식

    1. 각 eval에는 "지난 분기의 순매출 유지율은 얼마였나요?" 같은 질문, 예상 답변(보통 SQL), 올바른 답변이 반드시 사용하거나 사용하지 않아야 하는 테이블 같은 선택적 규칙이 있습니다.
    2. 에이전트는 사용자에게 답할 때와 마찬가지로 DataHub 컨텍스트를 사용해 질문에 답합니다.
    3. AI 판정자가 응답을 예상 답변과 비교합니다. SQL의 경우 쿼리가 동일한지가 아니라 동등한지를 확인합니다.
    4. 결과는 각 판정의 근거와 함께 통과율로 집계되므로 어떤 컨텍스트가 누락되었는지 확인할 수 있습니다.

    기본적으로 내장 DataHub 에이전트가 eval에 답합니다. 커스텀 에이전트에 연결된 eval은 해당 에이전트를 대상으로 실행됩니다.

    스크린샷: Validation > Evals에서 eval 결과를 추적하는 화면.

    eval 만들기

    eval은 Validation > Evals에 있습니다. 세 가지 방법으로 만들 수 있습니다.

    • 팀이 실제로 묻는 질문으로 직접 작성합니다. 가장 좋은 시작 방법으로, 데이터 전문가가 작성하거나 검토한 20~50개의 질문으로 시작합니다.
    • 게시된 컨텍스트 문서에서 생성합니다. DataHub가 질문과 예상 답변의 초안을 작성하고, 추가하기 전에 관리자가 각각을 검토합니다.
    • YAML로 코드에 정의하고, evals CLI를 사용해 CI에서 관리합니다.

    커스텀 에이전트의 eval은 해당 에이전트의 Evals 탭에서도 추가할 수 있습니다.

    eval 실행과 결과 검토

    eval을 필요할 때 실행하거나 일일 실행을 켜서, 답변을 깨뜨리는 변경 사항이 다음 날 아침에 드러나도록 할 수 있습니다. 제안된 변경 사항을 게시하기 전에 eval을 실행할 수도 있습니다. 컨텍스트 변경 사항 검토를 참고하세요.

    eval이 실패하면 열어서 에이전트의 답변과 예상 답변을 비교하고 판정자의 근거를 읽어 보세요. 대부분의 실패는 문서화되지 않은 메트릭이나 서로 내용이 다른 두 문서처럼 누락되거나 불명확한 컨텍스트에서 비롯됩니다. 여러 테이블이 유효한데 하나만 요구하는 경우처럼 eval 자체가 너무 엄격할 때도 있으며, 이 경우 eval을 업데이트합니다.

    에이전트가 DataHub 외부에서 실행된다면 자체 테스트 하네스가 답변을 DataHub에 보고해 채점받을 수 있으므로, 모든 에이전트를 같은 방식으로 측정할 수 있습니다.

    API 접근

    DataHub GraphQL API로 eval 생성, 업데이트, 실행, 결과 읽기 등 프로그래밍 방식으로 eval을 관리할 수도 있습니다.

    FAQ

    eval에 AI 크레딧이 사용되나요? 예. 에이전트가 질문에 답하고 AI 판정자가 채점하므로 실행할 때마다 AI 크레딧이 소비됩니다. 가장 중요한 질문에 집중해 eval 모음을 구성하세요.

    이미 eval 플랫폼을 사용하고 있습니다. DataHub eval을 사용하는 이유는 무엇인가요? DataHub eval은 에이전트가 DataHub에서 올바른 컨텍스트를 찾아 사용할 수 있는가라는 한 가지 질문에 집중합니다. Langfuse나 LangSmith 같은 도구의 종단 간 에이전트 eval을 보완합니다.

    누가 eval을 만들고 실행할 수 있나요? Manage Evals 권한이 있는 사람이면 누구나 가능합니다. Admins와 Editors에게는 기본적으로 이 권한이 있습니다.
