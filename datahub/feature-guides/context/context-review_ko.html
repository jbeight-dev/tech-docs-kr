    컨텍스트 변경 사항 검토

    기능 제공 범위: DataHub Cloud 전용 · 공개 베타

    정보: Context 애드온

    컨텍스트 검토는 DataHub Cloud Context 애드온에 포함됩니다.

    AI 에이전트는 제공된 컨텍스트가 무엇이든 그에 따라 동작하므로, 무엇을 넣을지는 데이터를 잘 아는 사람이 결정해야 합니다. DataHub에서는 팀원, DataHub AI, 자체 에이전트, Context Generation 등 누구나 컨텍스트 변경을 제안할 수 있습니다. 해당 컨텍스트의 소유자는 각 제안을 검토하고, eval로 테스트할 수 있으며, 에이전트가 보기 전에 승인합니다.

    검토 동작 방식

    1. 제안. 컨텍스트 문서 편집이나 새로 생성된 문서 같은 변경 사항이 제안됩니다.
    2. 검토. 제안은 관련 컨텍스트의 소유자(문서, 테이블, 도메인의 소유자 등)와 관리자에게 전달됩니다. 검토자는 제안을 편집하고, eval을 실행해 도움이 되는지 확인할 수 있습니다.
    3. 게시. 승인되면 변경 사항이 적용되고 에이전트가 사용하기 시작합니다.

    검토를 거치는 변경 사항은 다음과 같습니다.

    • Ask DataHub, 자체 에이전트, 또는 문서를 직접 편집할 수 없는 사람이 제안한 편집
    • 승인을 요구하도록 설정한 경우 생성된 컨텍스트 문서
    • eval 모음에 추가하기 전에 관리자가 검토하는 생성된 eval
    • 제안된 테이블 및 컬럼 설명

    문서 소유자처럼 편집 권한이 있는 사람은 제안 없이 컨텍스트를 직접 변경할 수 있습니다.

    스크린샷: 제안된 컨텍스트 변경 사항을 검토하는 화면.

    변경 제안하기

    누구나 변경을 제안할 수 있습니다. DataHub에서 문서를 편집할 수 없는 사람은 해당 문서에 변경 사항을 바로 제안할 수 있습니다. 채팅에서는 Ask DataHub나 자체 에이전트에게 "이탈 정의를 60일로 업데이트해 줘"처럼 편집을 제안하도록 요청할 수 있습니다. Slack과 Teams에서도 동작합니다.

    제안 검토하기

    자신에게 할당된 제안은 Tasks > Proposals에 표시됩니다. 제안을 열어 변경 내용을 확인하고, 필요하면 편집하고, 관련 eval을 실행합니다. DataHub는 변경 사항이 이미 게시된 것처럼 각 eval에 답하므로 변경으로 무언가가 수정되거나 깨지는지 확인할 수 있습니다. 그런 다음 승인하거나 거부합니다.

    생성된 문서의 경우 검토가 필요한 위치를 선택합니다. 대부분의 팀은 생성된 문서를 자동으로 게시하고 eval로 검증하며, 민감한 도메인에만 승인을 요구합니다. Context Generation을 참고하세요.

    API 접근

    DataHub GraphQL API로 제안 나열, 승인, 거부 등 프로그래밍 방식으로 제안을 관리할 수도 있습니다.

    FAQ

    누가 제안을 승인할 수 있나요? 관련 컨텍스트의 소유자와 관리자입니다.

    거부된 제안을 복구할 수 있나요? 거부된 제안은 아무것도 변경하지 않고 닫힙니다. 다시 시도하려면 변경을 다시 제안하세요.
