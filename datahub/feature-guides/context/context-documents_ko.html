    Context Documents

    기능 제공 범위: DataHub Core, DataHub Cloud

    Context Documents는 사람과 AI 에이전트에게 필요하지만 테이블 스키마만으로는 얻을 수 없는 지식을 담습니다. 메트릭의 의미, 신뢰할 수 있는 테이블, 접근 요청 방법, 주의할 사항 등이 여기에 해당합니다.

    에이전트는 일상적인 언어로 질문해 이러한 문서를 찾습니다. 좋은 컨텍스트 문서는 특정 질문에 답하기 위한 지도처럼 읽힙니다. "순매출 유지율을 계산하려면 이 테이블에서 시작해 이렇게 조인하고, 체험 계정을 제외하세요." 거버넌스와 프로세스에도 똑같이 잘 맞습니다. "고객 PII에 접근하는 방법과 승인자는 다음과 같습니다."

    데이터 에이전트를 위한 스킬이라고 생각하면 됩니다. 에이전트가 질문에 필요할 때만 가져오는 작은 노하우 조각입니다.

    Context Documents의 출처는 두 가지입니다.

    • 사람이 DataHub에서 작성하거나 Notion, Confluence, GitHub에서 가져옵니다.
    • Context Generation(DataHub Cloud)이 분석가가 실행한 쿼리, BI, 시맨틱 모델 같은 분석 활동의 산출물로 작성합니다. 각 문서는 팀이 반복해서 답하는 비즈니스 질문에 대한 지도입니다.

    문서를 게시하면 팀, Ask DataHub, MCP 서버로 연결된 모든 에이전트가 볼 수 있습니다. 문서를 도메인에 할당하면 해당 도메인의 에이전트로 제한할 수 있습니다.

    주요 기능

    Context Documents는 DataHub의 일급 구성 요소입니다. 다음을 할 수 있습니다.

    • 유형별 분류 — Runbook, FAQ, Policy, Decision Log 등
    • 메타데이터로 구성 — Domains, Tags, Glossary Terms, Owners, Structured Properties
    • 관련 자산 연결 — 문서가 설명하는 테이블, 대시보드, 차트, 도메인, 데이터 제품, 용어집 용어에 연결합니다. 에이전트는 해당 자산을 조회할 때마다 관련 문서를 봅니다.
    • 표시 범위 제어 — 게시해 조직 및 AI 에이전트와 공유하거나 초안으로 유지합니다
    • 버전 기록 추적 — 시간에 따른 변경 사항을 보고 이전 버전을 복원합니다
    • 외부 소스에서 가져오기 — Notion, Confluence, GitHub의 문서를 가져옵니다
    • 실제 사용에서 생성 — DataHub Cloud의 Context Generation이 쿼리 기록과 BI 정의로 문서를 작성합니다

    문서 만들기

    왼쪽 탐색 메뉴의 Documents 섹션에서 문서를 만듭니다.

    1. + New를 클릭해 새 문서를 만듭니다.
    2. 계층 구조에 넣을 상위 문서를 선택합니다(선택 사항).
    3. 제목을 입력하고 서식 있는 텍스트 편집기로 내용을 작성합니다.
    4. 필요에 따라 메타데이터(Type, Owner, Tags, Domain)를 추가합니다.

    특정 테이블을 위한 가드레일

    "금액 단위는 센트입니다", "항상 is_test를 필터링하세요", "일별 스냅샷이므로 여러 날에 걸쳐 합산하면 안 됩니다"처럼 하나의 테이블에 속하는 지식이 있습니다. 이러한 지식을 문서에 작성하고 문서를 테이블에 연결하세요.

    • 문서에서 Related Assets에 테이블을 추가합니다.
    • 또는 테이블 페이지에서 Add related link or context를 사용합니다.

    관련 문서는 자산과 함께 전달됩니다. 에이전트가 테이블을 조회하면 별도로 검색할 필요 없이 스키마와 함께 가드레일을 받습니다. 대시보드, 도메인, 데이터 제품, 용어집 용어에도 동일하게 적용됩니다.

    문서 가져오기

    Documents에서 Import를 클릭하고, 소스를 선택하고, 연결을 구성합니다. DataHub는 한 번 또는 일정에 따라 실행할 수 있는 관리형 수집 소스를 만듭니다. 가져오기를 관리하려면 다른 Data Sources와 같은 권한이 필요합니다.

    기본적으로 모든 소스는 DataHub에 Native(편집 가능) 문서를 만듭니다. 소스 시스템에 연결된 읽기 전용 문서를 원하면 데이터 소스 구성에서 Document import mode를 External로 전환하세요.

    소스 방향 참고 가이드
    Notion 단방향(Notion → DataHub) 기본은 Native이며 선택적으로 External(읽기 전용). 역동기화 없음. Notion에서 가져오기
    Confluence 단방향(Confluence → DataHub) 기본은 Native이며 선택적으로 External(읽기 전용). 역동기화 없음. Confluence에서 가져오기
    GitHub 가져오기, 역동기화는 DataHub Cloud만 기본은 Native이며 선택적으로 External(읽기 전용). 역동기화는 DataHub Cloud만 지원. GitHub에서 가져오기

    스크린샷: Import Documents 소스 선택 화면(Notion, Confluence, GitHub).

    Upload files를 선택해 Markdown, Word, HTML, 텍스트, CSV 파일을 직접 가져올 수도 있습니다.

    실행과 일정은 Data Sources / Ingestion 페이지에서 추적합니다.

    문서 게시하기

    문서는 Draft 또는 Published 상태일 수 있습니다. Draft 문서는 소유자인 본인에게만 표시됩니다. Published 문서는 다른 모든 사람에게 표시됩니다.

    문서 헤더의 Published를 전환해 문서를 게시하거나 게시 취소합니다.

    정보: Context Documents는 기본적으로 Published 상태로 생성됩니다.

    문서 이동하기

    문서 계층 구조는 언제든 다시 구성할 수 있습니다.

    1. 문서를 열거나 디렉터리 트리의 컨텍스트 메뉴를 사용합니다.
    2. Move를 선택합니다.
    3. 새 상위 문서를 선택합니다(또는 최상위로 이동합니다).

    문서 검색하기

    DataHub의 기본 검색창에서 데이터 자산과 함께 문서를 찾거나, 왼쪽 탐색 모음의 Documents 탭에서 찾을 수 있습니다.

    문서 기록

    문서 기록 타임라인에서 변경 사항을 추적하고, 이전 버전을 보고, 문서 내용을 복원할 수 있습니다.

    변경 유형은 다음과 같습니다.

    • 문서 생성
    • 문서 제목 변경
    • 문서 내용 변경
    • 문서 게시 또는 게시 취소
    • 관련 자산 업데이트

    Ask DataHub의 Context Documents

    Ask DataHub에 질문하면 AI가 메타데이터 그래프와 함께 게시된 문서를 검색합니다. 관련 컨텍스트를 찾으면 Ask DataHub는 응답에 해당 문서를 인용합니다. 문서는 질문과의 일치도, 사용 빈도, 최근 업데이트 시점에 따라 순위가 매겨지므로 자주 사용되고 최신 상태인 문서가 먼저 표시됩니다. 외부 에이전트가 MCP 서버로 검색할 때도 같은 순위가 적용됩니다.

    참고: Ask DataHub는 DataHub Cloud에서만 사용할 수 있습니다.

    문서를 만들고, 편집하고, 삭제할 수 있는 사람

    역할 생성 편집 및 이동 삭제
    Admin 예 예 예
    Editor 예 예 자신이 소유한 문서만
    Reader 아니요 아니요 아니요

    문서 소유자는 역할과 관계없이 문서를 편집, 이동, 삭제할 수 있습니다.

    이를 변경하려면 정책을 편집하세요.

    프로그래밍 방식 접근

    Context Documents에는 다음 방법으로 접근할 수 있습니다.

    • Python SDK: 프로그래밍 방식으로 문서를 만들고, 업데이트하고, 가져옵니다. Documents API 튜토리얼을 참고하세요.
    • MCP Server: AI 에이전트와 외부 도구에 문서를 노출합니다. DataHub MCP 서버를 참고하세요.
