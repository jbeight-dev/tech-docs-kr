    범위 지정 MCP 서버

    기능 제공 범위: DataHub Cloud 전용

    정보: Context 애드온

    범위 지정 MCP 서버는 DataHub Cloud Context 애드온에 포함됩니다.

    개요

    기본 DataHub MCP 엔드포인트는 관리형 도구 전체를 노출합니다. 범위 지정 MCP 서버(Scoped MCP servers)를 사용하면 플랫폼 관리자가 특정 사용 사례의 AI 에이전트나 채팅 어시스턴트에 맞춘 커스텀 서버를 추가로 만들 수 있으며, 각 서버에는 전용 URL이 있습니다.

    커스텀 MCP 서버별로 다음을 할 수 있습니다.

    • 도구 표시 및 숨기기 — MCP 서버 기반 에이전트에 노출할 도구와 작업을 결정합니다.
    • 커스텀 서버 지침 제공 — MCP 서버를 사용하는 에이전트가 활용하는 기본 지침을 사용자 지정합니다.
    • 특정 데이터 자산 및 컨텍스트 문서 노출 — 검색과 조회를 특정 데이터 자산과 컨텍스트 문서로 제한하는 DataHub Search View를 선택적으로 제공해 신호와 노이즈를 분리합니다.

    클라이언트는 기본 서버와 같은 방식(OAuth 또는 개인 액세스 토큰)으로 연결하되, 범위 지정 URL을 가리킵니다. 클라이언트 설정과 인증은 MCP 서버 가이드를 참고하세요.

    사전 요구 사항

    • Context 애드온이 있는 DataHub Cloud
    • Manage platform settings 권한(플랫폼 관리자)

    범위 지정 MCP 서버 만들기

    정보: 관리자 전용

    플랫폼 설정 관리 권한이 있는 사용자만 MCP 서버를 만들거나 편집할 수 있습니다.

    1. Settings → AI → MCP Servers로 이동합니다.
    2. Enable MCP Servers(페이지 상단의 마스터 스위치)가 켜져 있는지 확인합니다.
    3. Create를 클릭합니다.

    스크린샷: MCP Servers 관리 페이지(기본 + 범위 지정 서버, 마스터 스위치, Create).

    1. 다음을 입력합니다.
      • Name — 표시 이름(예: Finance MCP Server)
      • Slug — 경로에 사용되는 URL 안전 ID(예: finance). 생성 후에는 변경할 수 없습니다.
      • Description(선택 사항)
      • Base instructions / Custom instructions — 이 범위에서 에이전트가 동작하는 방식
      • Tools — 노출할 도구를 선택합니다. 비워 두면 모든 도구를 노출합니다
      • Scope to View(선택 사항) — 검색과 조회를 저장된 View로 제한합니다
    2. 양식에 표시된 Connection URL을 복사합니다(예: https://<tenant>.acryl.io/mcp/finance).
    3. 저장합니다.

    범위 지정 서버의 Tools에는 표준 도구 외에 다음을 포함할 수 있습니다.

    • Evals: Context Evals를 나열, 실행, 보고하는 도구입니다. 기본 서버에는 절대 노출되지 않습니다.
    • Agents: 아래를 참고하세요.

    DataHub 에이전트를 도구로 노출하기

    범위 지정 MCP 서버를 사용하면 DataHub 외부에서 DataHub 에이전트를 사용할 수 있습니다. 기본 서버는 에이전트를 노출하지 않으므로, 범위 지정 서버를 만들고 Tools에서 에이전트를 선택합니다. 그러면 MCP 클라이언트에 ask_agent__finance-analyst처럼 에이전트 이름을 딴 단일 도구로 표시됩니다. 외부 에이전트가 질문을 전달하면 DataHub 에이전트가 자체 지침, 범위, 플러그인을 사용해 답합니다.

    이렇게 하면 도메인 로직을 이를 검증하는 eval 및 컨텍스트와 함께 DataHub에 두면서, 사용자는 이미 사용 중인 도구를 계속 사용할 수 있습니다. 이 방식을 선택할 시점은 Build a Data Agent를 참고하세요.

    범위 지정 서버에 클라이언트 연결하기

    기본 서버와 다른 것은 URL뿐입니다. 전송 방식과 인증은 동일합니다.

    주의: mcp.datahub.com이 아닌 테넌트 URL을 사용하세요

    https://mcp.datahub.com/mcp는 항상 테넌트의 기본 서버로 연결되며, 이를 통해 범위 지정 서버를 선택할 수 없습니다. 대신 Settings → AI → MCP Servers의 Connection URL(예: https://<tenant>.acryl.io/mcp/finance)을 사용하세요.

    URL을 직접 조합하지 말고 복사한 다음, 아래에서 사용 중인 클라이언트의 단계를 따르세요.

    Claude(웹 및 데스크톱)
    1. Customize → Connectors를 엽니다.
    2. +를 클릭한 다음 Add custom connector를 클릭합니다.
    3. Name: 범위를 식별할 수 있게 지정합니다(예: DataHub — Finance). 여러 개를 나란히 실행할 수 있습니다.
    4. Remote MCP server URL: 범위 지정 Connection URL입니다.
    5. Advanced settings는 비워 둡니다. DataHub가 DCR로 클라이언트를 등록합니다.
    6. Add를 클릭한 다음 Connect를 클릭하고 DataHub에 로그인합니다.

    URL이 테넌트를 식별하므로 Claude는 DataHub 도메인을 묻지 않습니다.

    Team 및 Enterprise에서는 소유자가 Organization settings → Connectors에서 커넥터를 추가하고, 구성원은 Customize → Connectors에서 개별적으로 연결합니다.

    Claude Code 
    claude mcp add --transport http datahub-finance https://<tenant>.acryl.io/mcp/finance

    첫 번째 도구 호출은 401을 반환합니다. /mcp를 실행하고 서버를 선택한 뒤 Authenticate를 선택합니다. 공존할 수 있도록 각 서버의 이름을 다르게 지정하세요(datahub-finance, datahub-sales).

    Cursor

    ~/.cursor/mcp.json(전역) 또는 .cursor/mcp.json(프로젝트)에 항목을 추가합니다.

    {
  "mcpServers": {
    "datahub-finance": {
      "url": "https://<tenant>.acryl.io/mcp/finance"
    }
  }
}

    저장한 다음 브라우저에서 OAuth 흐름을 완료합니다.

    개인 액세스 토큰(서비스 계정, 무인 에이전트)

    OAuth를 사용할 수 없는 클라이언트의 경우:

    {
  "mcpServers": {
    "datahub-finance": {
      "command": "npx",
      "args": [
        "-y",
        "mcp-remote",
        "https://<tenant>.acryl.io/mcp/finance",
        "--header",
        "Authorization: Bearer <token>"
      ]
    }
  }
}

    토큰을 프로비저닝하려면 에이전트 워크플로용 서비스 계정을 참고하세요.

    범위 지정은 접근 제어가 아닙니다

    범위 지정 View는 에이전트가 기본적으로 보여 주는 내용을 바꿉니다. 누군가의 접근 권한을 회수하지는 않습니다. 같은 사용자가 기본 서버, UI, API로 범위 밖을 여전히 쿼리할 수 있습니다.

    사용자가 범위 밖의 데이터를 읽지 못하게 해야 한다면 뷰 정책으로 볼 수 있는 대상을 제한하고, 범위 지정 서버는 그 위의 사용 편의 계층으로 다루세요.

    누락된 컨텍스트 처리

    Custom instructions에서 도구가 아무것도 반환하지 않을 때 에이전트의 동작 방식을 지정합니다. 기본적으로 에이전트는 일반 지식에 의존할 수 있으므로, 잘못된 답변이 무응답보다 나쁜 경우에는 이를 명시하세요.

    이 도구로 사용할 수 있는 재무 컨텍스트로만 질문에 답하세요. 도구가 질문과 관련된 자산, 문서, 쿼리를 반환하지 않으면 답할 컨텍스트가 없다고 말하고 누구에게 문의할지 제안하세요. 사전 지식으로 답하거나 도구가 반환하지 않은 값을 추론하지 마세요.

    이는 지침이며 보장이 아닙니다. 서버를 출시하기 전에 범위 밖으로 예상되는 질문으로 테스트하세요.

    MCP 서버 편집

    1. Settings → AI → MCP Servers로 이동합니다.
    2. 서버(이름 링크)를 열거나 행 메뉴 → Edit를 사용합니다.
    3. 필요에 따라 이름, 설명, 지침, 도구, View를 업데이트합니다. slug(따라서 연결 URL 경로)는 고정됩니다.
    4. 저장합니다.

    다음도 할 수 있습니다.

    • 테이블에서 서버를 삭제하지 않고 활성화 또는 비활성화
    • Default 서버 편집(slug 없음)으로 공유 /mcp 엔드포인트의 도구, 지침, View 변경
    • 범위 지정 서버 삭제 — 연결 URL이 즉시 동작을 멈춥니다

    문제 해결

    에이전트가 볼 수 있어야 하는 테이블이나 문서를 찾지 못합니다. 서버의 View에 포함되어 있지 않습니다. 자산이 도메인에 할당되어 있는지(또는 View의 다른 필터와 일치하는지), View에 문서가 포함되어 있는지 확인하세요. 컨텍스트 문서는 테이블과 마찬가지로 View 필터를 따릅니다.

    에이전트 도구(예: ask_agent__finance-analyst)가 표시되지 않습니다. 서버의 Tools에서 에이전트가 선택되어 있는지, 서버가 활성화되어 있는지, 클라이언트가 서버의 Connection URL을 사용하는지 확인하세요. https://mcp.datahub.com/mcp는 항상 기본 서버로 연결되며 범위 지정 서버로는 연결되지 않습니다.

    datahub-sql-workflow 스킬이 SQL 컨텍스트 도구가 없다고 보고합니다. 서버의 Tools 목록에서 제외되어 있습니다. Tools를 비워 모두 포함하거나 SQL 컨텍스트 도구를 선택하세요. 이 도구에는 Context 애드온이 필요합니다.

    첫 번째 도구 호출이 401을 반환합니다. 클라이언트가 아직 로그인하지 않았습니다. Claude Code에서는 /mcp를 실행하고 서버를 선택한 뒤 Authenticate를 선택합니다. 다른 클라이언트는 연결할 때 로그인하라는 메시지를 표시합니다.

    Connection URL이 동작을 멈췄습니다. 서버가 비활성화되었거나 삭제되었습니다. 다시 활성화하거나 새 서버를 만드세요. 서버의 slug와 URL은 생성 후 변경할 수 없습니다.
