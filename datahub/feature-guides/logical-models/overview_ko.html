    논리 모델

    참고: 지원되는 엔터티 유형

    현재 논리 모델은 데이터셋과 그에 따른 스키마 필드만 지원합니다. 다른 엔터티 유형은 지원하지 않습니다.

    참고: 권한

    논리 모델을 만들고 컬럼을 편집하려면 Create Logical Models 플랫폼 권한이 필요하며, 이 권한은 기본적으로 Admin 역할에 부여됩니다. Admin은 커스텀 플랫폼 정책으로 다른 역할(예: Editor)에 이 권한을 부여할 수 있습니다. 물리 하위 항목을 연결하거나 연결 해제하려면 영향을 받는 데이터셋에 대한 일반 데이터셋 Edit 권한이 필요합니다. 논리 모델에 주석(태그, 용어집 용어, 소유자, 설명)을 달려면 일반 데이터셋 Edit 권한이 필요하고, 삭제하려면 Delete 권한이 필요합니다. 다른 데이터셋과 똑같습니다.

    논리 모델이란?

    논리 모델은 소스 시스템의 특정 물리적 구현에 묶이지 않고 데이터베이스 테이블의 개념과 구조를 나타냅니다. 다른 DataHub 데이터셋 엔터티처럼 논리 모델은 데이터 유형과 설명을 포함해 컬럼을 기술하며, 태그, 용어, 소유자, 커스텀 속성 같은 다른 메타데이터를 가질 수 있습니다. 하지만 물리 데이터셋과 달리 논리 모델은 데이터가 저장되어 쿼리할 수 있는, 소스 시스템에 실제로 존재하는 테이블을 나타내지 않습니다.

    논리 모델은 같은 유형이나 형태의 데이터를 나타내거나 같은 데이터를 저장하는 테이블이 여러 개 있을 때 유용합니다. 같은 테이블이 Snowflake, Redshift, BigQuery 같은 여러 클라우드 제공자에 복제될 수 있는 멀티 클라우드 데이터 생태계에서 흔합니다. gold/silver/bronze 계층처럼 단일 시스템에 여러 복제본이 있는 경우에도 유용합니다. DataHub에서 이 관계를 드러내려면 논리 모델을 각 물리적 표현에 연결해야 합니다. DataHub Cloud 고객은 모든 물리 하위 항목의 메타데이터를 논리 모델 수준에서 관리할 수 있는 중앙 집중식 관리를 추가로 활용할 수 있습니다.

    표시 방식

    참고: 기능 플래그

    UI에서 논리 모델을 보려면 datahub-gms에서 환경 변수 LOGICAL_MODELS_ENABLED를 true로 설정해야 합니다.

    예를 들어 Snowflake에 Users 테이블, BigQuery에 AllUsers 테이블, Apache Hive에 UsersAttributes 테이블이 있다고 가정해 보겠습니다. 세 테이블은 이름이 다르고 구조도 약간 다를 수 있지만, 논리적으로는 사용자별 특정 정보(컬럼)가 담긴 사용자 테이블이라는 같은 데이터를 나타냅니다. Users라는 논리 테이블을 만들고 각 물리 하위 항목에 연결합니다.

    관계가 생성되면 논리 상위 항목과 물리 하위 항목 모두의 엔터티 사이드바에 표시됩니다.

    논리 상위 항목과 물리 하위 항목의 컬럼도 연결할 수 있습니다.

    논리 모델 만들기

    논리 모델은 다른 DataHub 데이터셋처럼 만듭니다. Python SDK 사용을 권장합니다.

    UI에서 만들기

    LOGICAL_MODELS_ENABLED를 사용하면 UI에서 논리 모델을 바로 만들 수도 있습니다. 검색 결과 컨트롤 모음의 Create Logical Model 작업을 사용하면 모델의 이름, 플랫폼, 컬럼을 입력하는 양식이 열립니다. 생성한 뒤에는 모델의 Schema 탭에서 컬럼을 추가하거나, 이름을 바꾸거나, 유형을 변경하거나, 삭제할 수 있습니다.

    참고: 논리 모델 플랫폼

    논리 모델은 엔터티 하위 유형으로 식별되지 않고, 논리 플랫폼(논리 플랫폼으로 표시된 데이터 플랫폼)에 있는 데이터셋입니다. 플랫폼 선택기는 내장 logical 플랫폼을 포함한 기존 논리 플랫폼 또는 새 논리 플랫폼이 되는 커스텀 이름(최대 15자)을 제공합니다. 일반 비논리 플랫폼에는 논리 모델을 만들 수 없습니다. 논리 모델이 사용자에게 익숙한 시스템에 저장되어 있다면 해당 시스템용 커스텀 플랫폼을 만들고 커스텀 아이콘을 제공하기를 권장합니다. 그렇지 않으면 특별한 기본 아이콘이 있는 내장 logical 플랫폼 사용을 권장합니다.

    "logical" 플랫폼에 데이터셋 만들기

        from datahub.sdk import DataHubClient, Dataset
    client = DataHubClient.from_env()
    dataset = Dataset(
        platform="logical",
        name=logical_model_name,
        description=logical_model_description,
        schema=[
            # tuples of (field name / field path, data type, description)
            (
                "zipcode",
                "varchar(50)",
                "This is the zipcode of the address. Specified using extended form and limited to addresses in the United States",
            ),
            ("street", "varchar(100)", "Street corresponding to the address"),
            ("date_column", "date", "Date of the last sale date for this property"),
        ],
    )
    client.entities.upsert(dataset)

    커스텀 플랫폼에 데이터셋 만들기

        # Create custom platform with custom logo
    from datahub.sdk import DataHubClient
    from datahub.emitter.mcp import MetadataChangeProposalWrapper
    from datahub.metadata.schema_classes import DataPlatformInfoClass, PlatformTypeClass
    from datahub.metadata.urns import DataPlatformUrn

    urn = DataPlatformUrn("<platformName>").urn()
    aspect = DataPlatformInfoClass(
        name="<platformName>",
        type=PlatformTypeClass.OTHERS,
        datasetNameDelimiter=".",
        logoUrl="<url>"
    )
    client = DataHubClient.from_env()
    client._graph.emit(MetadataChangeProposalWrapper(entityUrn=urn, aspect=aspect))

    # Create dataset in custom platform
    from datahub.sdk import DataHubClient, Dataset
    client = DataHubClient.from_env()
    dataset = Dataset(
        platform="<platformName>",
        ...  # See above
    )
    client.entities.upsert(dataset)

    논리 모델 연결하기

    논리 -> 물리 관계의 핵심은 LogicalParent aspect로 만들어진다는 점입니다. 컬럼을 연결하려면 각 하위 스키마 필드 엔터티에도 이 aspect를 만들어야 합니다. 다만 사용 편의를 위해 OpenAPI 엔드포인트를 권장합니다.

    UI에서 연결하기

    논리 모델 프로필의 Physical Children 사이드바 섹션은 물리 데이터셋을 연결(선택적 컬럼 매핑 포함)하고 기존 하위 항목을 연결 해제하는 작업을 제공합니다. 논리 모델의 컬럼을 호환되지 않게 편집하면(컬럼 제거, 이름 변경, 유형 변경) 변경된 컬럼을 참조하는 하위 컬럼 매핑만 해제됩니다. 하나 이상의 매핑이 남아 있는 한 하위 항목은 영향받지 않은 다른 컬럼 매핑과 함께 연결을 유지하며, 남은 매핑이 없을 때만 완전히 연결 해제됩니다. 컬럼 추가는 호환성을 깨지 않으며 기존 연결에 영향을 주지 않습니다. 호환되지 않는 변경 후 자동으로 다시 연결되지는 않으므로, 영향받은 하위 항목은 새 스키마에 맞게 수동으로 다시 연결해야 합니다.

    OpenAPI

    OpenAPI 엔드포인트는 단일 논리-물리 쌍에 대한 논리 -> 물리 관계와, 지정된 경우 컬럼 간 컬럼 수준 관계를 만듭니다.

    curl -X POST 'http://localhost:8080/openapi/v3/logical/<physical_child_urn>/relationship/physicalInstanceOf/<logical_model_urn>' \
  -H 'accept: application/json' \
  -H 'Content-Type: application/json' \
  -d '{
    "<logical_column_name_0>": "<physical_column_name_0>",
    "<logical_column_name_1>": "<physical_column_name_1>",
    "<logical_column_name_2>": "<physical_column_name_2>"
  }'

    이러한 관계는 제거할 수도 있습니다(DataHub Cloud v0.3.15부터).

    curl -X DELETE 'http://localhost:8080/openapi/v3/logical/<physical_child_urn>/relationship/physicalInstanceOf' \
  -H 'accept: application/json' \
  -H 'Content-Type: application/json'

    Python SDK

    Python SDK로도 같은 엔드포인트를 쿼리할 수 있습니다.

        from datahub.sdk import DataHubClient
    client = DataHubClient.from_env()
    url = f"{client._graph.config.server}/openapi/v3/logical/{child_urn}/relationship/physicalInstanceOf/{parent_urn}"
    client._graph._post_generic(url, {column.parent_name: column.child_name for column in columns})

    또는 LogicalParent aspect를 내보내 단일 관계를 만들 수 있습니다.

        from datahub.sdk import DataHubClient
    from datahub.emitter.mcp import MetadataChangeProposalWrapper
    from datahub.metadata.schema_classes import EdgeClass, LogicalParentClass
    client = DataHubClient.from_env()

    client._graph.emit(MetadataChangeProposalWrapper(entityUrn=child_urn, aspect=LogicalParentClass(parent=EdgeClass(destinationUrn=parent_urn))))

    관계를 제거할 수도 있습니다.

        from datahub.sdk import DataHubClient
    from datahub.emitter.mcp import MetadataChangeProposalWrapper
    from datahub.metadata.schema_classes import EdgeClass, LogicalParentClass
    client = DataHubClient.from_env()

    client._graph.emit(MetadataChangeProposalWrapper(entityUrn=child_urn, aspect=LogicalParentClass(parent=None)))

    권한 부여

    물리 데이터셋을 논리 상위 항목에 연결하거나 연결 해제하면 하위 엔터티(데이터셋, 그리고 컬럼 연결의 경우 스키마 필드)에 LogicalParent aspect를 씁니다. 연결을 설정할 때는 하위 항목과 제안된 상위 항목 모두에 Edit Entity가 필요하고, 상위 항목을 지울 때는 하위 항목에만 Edit Entity가 필요합니다.

    각 측은 독립적으로 확인됩니다. 데이터셋은 해당 데이터셋에 대한 Edit Entity가 필요하고, 스키마 필드는 포함하는 데이터셋 또는 스키마 필드 URN에 대한 Edit Entity를 허용합니다. 하위 측과 상위 측은 서로 다른 권한 부여 유형을 사용할 수 있습니다(예: 물리 측은 데이터셋 정책, 논리 측은 스키마 필드 정책). OpenAPI 논리 모델 엔드포인트는 MCP를 일괄 쓰기 전에 같은 규칙을 적용합니다.

    이 규칙은 MCP 수집, GraphQL(setLogicalParent), OpenAPI 관계 엔드포인트에 적용됩니다.
