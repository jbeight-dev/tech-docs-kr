    홈 페이지

    기능 제공 범위: DataHub Cloud 전용

    DataHub의 Home Page를 사용하면 조직과 개별 사용자가 가장 관련성 높은 데이터 자산과 정보를 전면에 배치한 개인화된 모듈형 홈 페이지를 만들 수 있습니다.

    홈 페이지를 사용하는 이유

    Home Page는 팀이 DataHub와 상호작용하는 방식을 다음과 같이 바꿉니다.

    • 인사이트까지 걸리는 시간 단축: 가장 중요한 데이터 자산, 도메인, 리소스를 홈 페이지에 바로 표시해 즉시 접근할 수 있습니다
    • 워크플로 개인화: 자신의 역할, 프로젝트, 데이터 요구에 맞춘 홈 페이지를 만듭니다
    • 데이터 검색 가능성 향상: 중요한 컬렉션, 문서, 빠른 링크를 강조해 팀이 필요한 것을 더 빨리 찾도록 돕습니다
    • 조직 뷰 표준화: 관리자는 일관된 기본 환경을 만들면서도 개별 사용자 지정을 허용할 수 있습니다

    특정 대시보드에 빠르게 접근해야 하는 데이터 분석가, 특정 도메인에 집중하는 데이터 엔지니어, 데이터 거버넌스 리소스를 알리려는 관리자 모두의 워크플로에 Home Page를 맞출 수 있습니다.

    포함된 항목

    Home Page는 행당 최대 3개까지 배치할 수 있는 모듈로 구성됩니다. 다음 중에서 선택할 수 있습니다.

    기본 모듈

    • Your Assets: 자신이 소유한 데이터 자산으로, 담당 자산에 빠르게 접근할 수 있습니다
    • Your Subscriptions: 업데이트와 알림을 구독한 자산
    • Domains: 쉽게 탐색할 수 있도록 조직에서 가장 많이 사용하는 도메인을 선별해 표시합니다

    커스텀 모듈

    • Quick Link: 문서 사이트, 대시보드, 도구 같은 중요한 외부 참조 링크
    • Collection: 쉽게 찾을 수 있도록 강조하려는 데이터 자산의 큐레이션 컬렉션
    • Documentation: DataHub 사용자가 홈 페이지에서 봐야 할 고정 문서
    • Hierarchy: 선택한 도메인 또는 용어집 용어/용어 그룹별로 구성한 자산의 하향식 뷰

    조직 공지

    조직의 중요한 공지는 모든 모듈 위에 표시되며, 사용자가 개별적으로 닫을 수 있습니다.

    기본 구성

    이 버전으로 업그레이드하면 기본 홈 페이지에 다음이 자동으로 포함됩니다.

    • 상단의 조직 기존 고정 링크
    • 1행: Your Assets 및 Your Subscriptions 모듈
    • 2행: Domains 모듈

    홈 페이지 개인화

    홈 페이지 사용자 지정을 시작하면 조직 기본값에서 "포크"해 자신만의 개인 버전을 만듭니다. 변경 사항은 다른 사용자에게 영향을 주지 않으며, 필요하면 언제든 조직 기본값으로 돌아갈 수 있습니다.

    참고

    사용자 지정은 현재 DataHub Cloud에서만 지원합니다. DataHub Core는 사용자 지정할 수 없는 기본 홈 페이지를 지원합니다.

    새 모듈 추가

    "Add Module"을 클릭해 사용 가능한 모듈 유형을 찾아 선택합니다. 커스텀 모듈은 특정 설정으로 구성할 수 있습니다.

    모듈 재배치

    모듈을 끌어다 놓아 행 내에서 순서를 바꾸거나 다른 행으로 옮깁니다. 행당 최대 3개의 모듈을 배치할 수 있습니다.

    기존 모듈 편집

    모듈의 편집 아이콘을 클릭해 설정, 제목, 내용을 수정합니다. 현재 편집은 커스텀 모듈에서만 사용할 수 있습니다.

    모듈 제거

    모듈의 제거 아이콘을 클릭하면 홈 페이지에서 삭제됩니다. 기본 모듈은 언제든 다시 추가할 수 있으니 걱정하지 마세요.

    기본값으로 재설정

    조직의 기본 홈 페이지로 돌아가는 방법은 다음과 같습니다.

    1. 오른쪽 하단의 설정 아이콘을 클릭합니다
    2. "Reset to Default Home Page"를 선택합니다
    3. 개인 사용자 지정 내용을 제거할지 확인합니다

    개인 홈 페이지 템플릿이 삭제되고 조직 기본값으로 돌아갑니다.

    팁

    개인 홈 페이지가 있더라도 기본 홈 페이지의 모듈을 언제든 가져와 개인 뷰에 추가할 수 있습니다. 사용자 지정 내용을 유지하면서 조직 표준을 최신 상태로 따를 수 있습니다.

    기본 홈 페이지 구성

    MANAGE_HOME_PAGE_TEMPLATES 권한이 있는 사용자(기본적으로 관리자)는 모든 사용자가 처음 로그인할 때 보는 기본 홈 페이지를 사용자 지정할 수 있습니다.

    조직 기본값 편집

    조직의 기본 홈 페이지를 수정하는 방법은 다음과 같습니다.

    1. 홈 페이지 오른쪽 하단의 설정 아이콘을 클릭합니다
    2. "Edit Organization Default"를 선택합니다

    조직 기본값 편집 모드로 들어가면 현재 기본 템플릿이 표시됩니다. 여기에서 변경한 내용은 다음과 같이 적용됩니다.

    • 조직 기본값에 바로 저장: 기본 템플릿을 사용하는 모든 사용자에게 변경 사항이 즉시 적용됩니다
    • 새 사용자에게 표시: 홈 페이지를 사용자 지정하지 않은 모든 사람에게 업데이트가 표시됩니다
    • 개인 템플릿을 덮어쓰지 않음: 개인 홈 페이지를 만든 사용자는 계속 자신의 사용자 지정 버전을 봅니다

    기본 모듈 관리

    조직 기본값을 편집하는 관리자는 다음을 할 수 있습니다.

    • 조직의 대부분 사용자에게 유용한 모듈 추가
    • 팀 워크플로와 관련 없는 모듈 제거
    • 가장 중요한 정보를 우선하도록 모듈 재배치
    • 모듈 구성 업데이트(예: 표시할 도메인)

    기본 템플릿 모범 사례

    조직의 기본 홈 페이지를 구성할 때는 다음을 따르세요.

    • 폭넓게 유용한 모듈 포함: "Your Assets"와 "Domains"처럼 대부분의 사용자에게 유용한 모듈을 선택합니다
    • 조직 리소스 소개: Quick Link와 Documentation 모듈로 중요한 회사 리소스를 알립니다
    • 집중 유지: 복잡한 기본 페이지는 새 사용자에게 부담이 될 수 있으므로, 잘 선택한 3~6개의 모듈을 목표로 합니다
    • 정기적으로 업데이트: 기본 템플릿을 주기적으로 검토하고 새로 고쳐 관련성을 유지합니다

    참고

    관리자는 조직 기본값을 편집할 수 있으면서 자신의 개인 홈 페이지 사용자 지정도 유지할 수 있습니다. 둘은 서로 독립적입니다.

    다음 단계

    홈 페이지를 사용자 지정하는 방법을 이해했으니 이제 다음을 진행합니다.

    1. 작은 변경부터 시작: 기존 모듈을 재배치하거나 Quick Link를 추가해 인터페이스가 어떻게 동작하는지 확인합니다
    2. 모듈 실험: 모듈 유형마다 중요한 정보를 보여 주는 방식이 다릅니다
    3. 피드백 수집: 관리자라면 기본 홈 페이지에서 무엇이 가장 유용할지 사용자에게 묻습니다
    4. 시간을 두고 반복 개선: 팀과 데이터 환경이 변화하면 홈 페이지 요구 사항도 달라질 수 있습니다

    Home Page는 조직의 요구에 맞춰 성장하도록 설계되었으며, 개별 워크플로를 위한 유연성과 관리자가 중요한 리소스 및 모범 사례를 알리는 데 필요한 일관성을 모두 제공합니다.

    관련 API

    템플릿 Upsert

    템플릿은 홈 페이지에 표시되는 내용입니다. 행 목록을 포함하며, 각 행에는 모듈 URN 목록이 있습니다.

    mutation upsertPageTemplate {
  upsertPageTemplate(
    input: {
      rows: [{ modules: ["urn:li:dataHubPageModule:your_assets"] }]
      scope: GLOBAL
      surfaceType: HOME_PAGE
    }
  ) {
    urn
  }
}

    모듈 Upsert

    모듈은 홈 페이지에 표시되는 개별 "위젯"입니다. 모듈은 템플릿의 컨텍스트 안에 존재합니다.

    mutation upsertPageModule {
  upsertPageModule(
    input: {
      name: "My Custom Module"
      type: RICH_TEXT
      scope: PERSONAL
      params: {
        richTextParams: {
          content: "This is the content of my documentation module"
        }
      }
    }
  ) {
    urn
  }
}
