    DataHub Agent Registry 소개

    기능 제공 범위: DataHub Cloud 전용

    DataHub Cloud v2.1에 도입된 Agent Registry는 AI 에이전트, 에이전트가 채택하는 스킬, 에이전트가 호출하는 도구를 일급의 거버넌스 대상이자 버전 관리되는 메타데이터 엔터티로 카탈로그화합니다. 이들은 에이전트가 소비하는 데이터와 같은 리니지 그래프에 놓입니다. 덕분에 실행 중인 에이전트의 수, 각 에이전트가 다루는 데이터, 소유자 같은 질문에 이미 데이터에 사용 중인 카탈로그에서 답할 수 있습니다.

    에이전트가 데이터셋과 함께 그래프에 존재하므로, 데이터에 이미 적용 중인 거버넌스(소유권, 분류, 리니지, 인시던트, 변경 기록)가 별도 구성 없이 AI 계층까지 확장됩니다.

    참고: Agent Registry와 Agents의 차이

    이 가이드는 AI 에이전트를 메타데이터로 카탈로그화하는 방법, 즉 에이전트를 검색할 수 있고 소유자가 있으며 거버넌스를 적용할 수 있게 만드는 방법을 다룹니다. 일정에 따라 또는 이벤트에 반응해 작업을 자율적으로 실행하는 AI 에이전트를 구축하려면 Agents 가이드를 참고하세요. 두 기능은 상호 보완적입니다. 직접 구축한 에이전트를 여기에 카탈로그화할 수 있고, 여기에 카탈로그화된 에이전트에는 다른 자산처럼 거버넌스를 적용할 수 있습니다.

    개념

    Agent Registry는 두 가지 핵심 엔터티 유형을 도입하고, 에이전트의 도구에는 Service Catalog의 API 및 Service 엔터티를 재사용합니다.

    엔터티 나타내는 대상
    AI Agent 지침, 범위, 의존성을 갖춘 AI 에이전트입니다. 네이티브(DataHub 관리형), 시스템, 외부(카탈로그화됨) 유형이 있습니다.
    Skill git에 정의되어 에이전트가 채택하는 재사용 가능한 기능 묶음(프롬프트 + 도구 + 도메인 전문 지식)입니다.
    Tool 에이전트가 호출하는 기능입니다. 타입이 지정된 시그니처를 갖는 API 엔터티로 모델링합니다.
    MCP Server 에이전트의 도구를 노출하는 서버입니다. 하위 유형이 MCP인 Service 엔터티로 모델링합니다.

    에이전트의 의존성과 에이전트가 읽는 데이터는 모두 하나의 리니지 그래프로 연결됩니다.

    repository ─▶ service (MCP) ─▶ api (tool) ◀─invokes─ aiAgent ─adopts─▶ skill ─requires─▶ api (tool)
                                                        │
                                                        └─reads──▶ dataset (upstream lineage)

    설정, 사전 요구 사항, 권한

    AI 에이전트, 스킬, 도구는 다른 자산과 마찬가지로 수집을 통해 채우거나 SDK/API로 직접 내보냅니다. SDK, CLI, LangChain 및 Google ADK에서의 자동 등록은 API 튜토리얼을 참고하세요. 이들을 탐색하고 관리하려면 사용자에게 표준 엔터티 권한이 있어야 합니다.

    • View Entity Page: 에이전트, 스킬, 도구 프로필을 찾아 열 수 있습니다.
    • Edit Entity(및 관련 하위 권한): 소유권, 태그, 용어집 용어, 문서로 내용을 보강할 수 있습니다.

    조직에서 Agent Registry를 활성화하려면 DataHub 담당자에게 문의하세요.

    Agent Registry 사용하기

    에이전트 프로필

    FX Risk Scoring Agent 같은 에이전트를 열면 프로필을 볼 수 있습니다. 프로필에는 에이전트의 역할, 사용하는 스킬과 도구, BigQuery, Snowflake, dbt에 걸쳐 읽는 데이터, 평가 점수, 호출량, 지연 시간 같은 신뢰성 지표가 표시됩니다. 소유권은 팀(여기서는 Quant Risk Team)에 귀속되므로, 모든 에이전트에는 찾아서 책임을 물을 수 있는 소유자가 있습니다.

    의존성

    에이전트의 의존성은 명시적이며 클릭해서 확인할 수 있습니다. 에이전트가 채택하는 스킬, 호출하는 도구, 실행 기반이 되는 모델이 이에 해당합니다. 각각이 독립된 카탈로그 엔터티이므로, 새로운 팀은 에이전트를 처음부터 다시 만드는 대신 이들을 찾아 재사용할 수 있습니다.

    스킬

    스킬도 카탈로그 엔터티입니다. FX Risk Scoring skill 같은 스킬을 열면 정의, 신뢰할 수 있는 기준이 되는 사양, 필요한 도구를 정확히 확인할 수 있습니다. 스킬은 팀이 다시 구현하지 않고 채택하는, 재사용 가능하고 검증된 기능입니다.

    도구, 시그니처, 계약

    에이전트가 호출하는 모든 도구는 입력 매개변수와 출력 형태로 이루어진 타입 지정 시그니처를 갖는 API 엔터티이며, 데이터셋과 같은 스키마 컴포넌트로 렌더링됩니다. 이러한 도구를 노출하는 MCP 서버는 Service 엔터티로 카탈로그화되며, 각 서버는 전체 계약을 그래프에 담고 있습니다. 계약은 실시간 도구 목록으로, 입력과 출력을 JSON Schema로 표현하고 그 자리에서 버전을 관리합니다. (REST API 도구는 OpenAPI 사양을 같은 방식으로 렌더링합니다.) API, 서비스, 계약에 대한 전체 내용은 Service Catalog를 참고하세요.

    데이터까지 이어지는 리니지

    에이전트는 리니지 그래프에서 자신이 소비하는 BigQuery, Snowflake, dbt 테이블의 다운스트림에 위치합니다. 따라서 데이터 영향 분석에 사용하는 것과 같은 리니지 그래프에서 에이전트가 읽는 데이터를 추적할 수 있고, 리니지를 역방향으로 따라가 특정 테이블을 읽는 에이전트를 찾을 수도 있습니다.

    버전 관리와 변경 기록

    에이전트는 버전으로 관리됩니다. 서로 다른 버전이 프로덕션에서 나란히 실행되는 경우가 많으므로, 1.0부터 2.0까지의 버전은 버전 세트로 묶이고 최신 버전이 명확히 표시됩니다.

    또한 모든 변경 사항은 타임라인에 기록됩니다. 태그 변경, 소유권 업데이트, 평가 점수 상승, 새 문서, 버전 마일스톤 자체가 모두 포함됩니다. 데이터 품질 기록과 마찬가지로, 에이전트에 대해서도 신뢰할 수 있는 완전한 AI 감사 추적을 제공합니다.

    리니지 전반의 거버넌스

    에이전트가 리니지 그래프에 있으므로 거버넌스 자동화가 별도 설정 없이 에이전트까지 확장됩니다. Glossary Term Propagation 자동화를 켰다고 가정해 보겠습니다. 누군가 소스 테이블 fx-positions를 Highly Confidential로 분류합니다. FX Risk Scoring Agent는 이 테이블을 소비하므로, DataHub가 분류를 에이전트로 전파하고, 에이전트는 리니지를 통해 상속받은 동일한 Highly Confidential 레이블을 갖게 됩니다. 에이전트의 상태가 빨간색으로 바뀌고 검토를 위한 인시던트가 열립니다. 따라서 민감한 데이터가 AI 시스템에 도달하는 순간 이를 바로 확인할 수 있습니다.

    FAQ 및 문제 해결

    Agents 기능과 어떻게 다른가요?

    Agents 기능은 작업을 자율적으로 실행하는 AI 에이전트를 구축하는 기능입니다. Agent Registry는 (DataHub에서 구축했든 다른 곳에서 구축했든) AI 에이전트를 거버넌스 대상 메타데이터로 카탈로그화하는 기능입니다. 이를 통해 에이전트를 검색할 수 있고, 소유자를 지정하고, 버전을 관리하고, 에이전트가 다루는 데이터와 연결할 수 있습니다.

    에이전트의 "도구"는 메타데이터 모델에서 무엇에 해당하나요?

    도구는 API 엔터티입니다. Service Catalog가 REST 엔드포인트, gRPC 메서드, GraphQL 필드에 사용하는 것과 같은 엔터티입니다. 덕분에 "어떤 에이전트가 이 엔드포인트를 호출하는가"를 일반적인 영향 분석으로 답할 수 있습니다.

    DataHub 외부에서 구축한 에이전트도 카탈로그화할 수 있나요?

    예. 에이전트는 네이티브(DataHub 관리형), 시스템(부트스트랩), 외부(다른 플랫폼에서 카탈로그화) 유형이 될 수 있으며, 어떤 유형이든 프로필, 리니지, 버전 관리, 거버넌스는 동일하게 동작합니다.

    관련 기능

    • Service Catalog — 서비스, API, 리포지토리, 애플리케이션
    • Agents — 작업을 자율적으로 실행하는 AI 에이전트 구축
    • Lineage — 종단 간 의존성 추적과 영향 분석
    • Glossary Term Propagation — 리니지 전반의 자동 분류
