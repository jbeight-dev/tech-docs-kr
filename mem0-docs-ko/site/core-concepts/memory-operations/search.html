메모리 검색

강력한 시맨틱 검색과 필터 검색으로 Mem0에서 관련 메모리를 가져옵니다.

Mem0가 메모리를 검색하는 방식

Mem0의 검색 작업을 쓰면 에이전트가 자연어로 질문하고 가장 중요한 메모리를 돌려받을 수 있습니다. 유능한 사서처럼, 저장된 모든 내용 중에서 필요한 것을 정확히 찾아냅니다.

핵심 용어

  • 쿼리(Query): search에 전달하는 자연어 질문이나 문장입니다.
  • 필터(Filters): 사용자, 카테고리, 날짜 등으로 결과를 좁히는 JSON 로직(AND/OR, 비교 연산자)입니다.
  • top_k / threshold: 반환할 메모리 수와 최소 유사도 점수를 제어합니다.
  • 재순위화(Rerank): 리랭커가 구성되어 있을 때 정밀도를 높이는 선택적 2차 단계입니다.

아키텍처

  1. 쿼리 처리

    Mem0는 이후 임베딩 검색이 정확하도록 자연어 쿼리를 정리하고 보강합니다.

  2. 벡터 검색

    임베딩이 코사인 유사도를 사용해 범위가 지정된 데이터셋에서 가장 가까운 메모리를 찾습니다.

  3. 필터링과 재순위화

    논리 필터가 후보를 좁히고, 리랭커나 임곗값이 순서를 세밀하게 조정합니다.

  4. 결과 전달

    형식이 갖춰진 메모리(메타데이터와 타임스탬프 포함)가 에이전트나 호출 서비스로 반환됩니다.

이 파이프라인은 호스팅되는 Platform API와 OSS SDK에서 똑같이 실행됩니다.

어떻게 동작하나요?

검색은 자연어 질문을 벡터 임베딩으로 변환한 뒤 데이터베이스에서 임베딩이 비슷한 메모리를 찾습니다. 결과는 유사도 점수로 순위가 매겨지며, 필터나 재순위화로 더 다듬을 수 있습니다.

# Minimal example that shows the concept in action
# Platform API
client.search("What are Alice's hobbies?", filters={"user_id": "alice"})

# OSS
m.search("What are Alice's hobbies?", filters={"user_id": "alice"})
팁

올바른 사용자의 메모리로 검색 범위를 지정하도록 항상 user_id 필터를 하나 이상 지정하세요. 그래야 사용자 간에 메모리가 섞이지 않습니다.

언제 사용하나요?

  • 컨텍스트 조회 - 에이전트가 더 나은 응답을 생성하는 데 과거 컨텍스트가 필요할 때
  • 개인화 - 사용자 선호, 이력, 과거 상호작용을 떠올릴 때
  • 사실 확인 - 응답하기 전에 저장된 메모리와 대조해 정보를 검증할 때
  • 의사 결정 지원 - 에이전트가 결정을 내리는 데 관련 배경 정보가 필요할 때

Platform과 OSS 사용법 비교

기능Mem0 PlatformMem0 OSS
search / get_all의 엔터티 IDfilters={"user_id": "alice"} 내부filters={"user_id": "alice"} 내부(v3에서 Platform과 통일: 최상위 kwargs는 ValueError 발생)
필터 문법필드 수준 접근을 지원하는 논리 연산자(AND, OR, 비교)기본 필드 필터, Python 훅으로 확장
재순위화관리형 리랭커 카탈로그와 함께 rerank=True로 전환로컬 또는 서드파티 리랭커 구성 필요
임곗값요청 단위 구성(threshold, top_k)SDK 매개변수로 제어
응답 메타데이터신뢰도 점수, 타임스탬프, 대시보드 가시성 포함사용하는 스토리지 백엔드에 따라 결정

Mem0 Platform으로 검색

Python

from mem0 import MemoryClient

client = MemoryClient(api_key="your-api-key")

query = "What do you know about me?"
filters = {
   "OR": [
      {"user_id": "alice"},
      {"agent_id": {"in": ["travel-assistant", "customer-support"]}}
   ]
}

results = client.search(query, filters=filters)

JavaScript

import { MemoryClient } from "mem0ai";

const client = new MemoryClient({apiKey: "your-api-key"});

const query = "I'm craving some pizza. Any recommendations?";
const filters = {
  AND: [
    { user_id: "alice" }
  ]
};

const results = await client.search(query, {
  filters
});

Mem0 오픈소스로 검색

Python

from mem0 import Memory

m = Memory()

# Simple search: entity IDs go in `filters`
related_memories = m.search("Should I drink coffee or tea?", filters={"user_id": "alice"})

# Search with additional metadata filters (combine entity + metadata in the same dict)
memories = m.search(
    "food preferences",
    filters={"user_id": "alice", "categories": {"contains": "diet"}},
)

JavaScript

import { Memory } from 'mem0ai/oss';

const memory = new Memory();

// Simple search: entity IDs go inside `filters`
const relatedMemories = memory.search("Should I drink coffee or tea?", {
    filters: { userId: "alice" },
});

// Combine entity + metadata filters in the same filters object
const memories = memory.search("food preferences", {
    filters: { userId: "alice", categories: { contains: "diet" } },
});
안내

메모리 문서 배열이 반환됩니다. Platform 응답에는 벡터, 메타데이터, 타임스탬프가 포함되고, OSS는 저장된 스키마를 반환합니다.

참고

Mem0 Platform v3에서는 시간을 고려하는 쿼리가 내부적으로 시간 추론(Temporal Reasoning)을 사용하면서도 일반 검색 응답 형태를 유지합니다. 시간 추론을 참고하세요.

OSS 검색 점수 설명

OSS 검색은 시맨틱 유사도에 선택적 키워드 및 엔터티 신호를 결합합니다. 조회 품질을 조정하거나 메모리가 그 순위에 오른 이유를 디버깅할 때 explain=True를 전달하세요.

Python

results = m.search(
    "food preferences",
    filters={"user_id": "alice"},
    explain=True,
)

print(results["results"][0]["score_details"])

JavaScript

const results = await memory.search("food preferences", {
    filters: { user_id: "alice" },
    explain: true,
});

console.log(results.results[0].score_details);

각 결과에는 시맨틱 점수, 정규화된 BM25 점수, 엔터티 부스트, 결합 원점수, 가능한 최대 점수, 최종 점수, 필터링에 쓴 임곗값이 담긴 score_details가 포함됩니다. 이 필드는 explain을 활성화할 때만 포함되므로 기존 응답 형태는 바뀌지 않습니다.

필터 패턴

필터는 검색 결과를 좁히는 데 도움이 됩니다. 일반적인 사용 사례는 다음과 같습니다.

세션 컨텍스트로 필터링:

Platform API:

# Get memories from a specific agent session
client.search("query", filters={
    "AND": [
        {"user_id": "alice"},
        {"agent_id": "chatbot"},
        {"run_id": "session-123"}
    ]
})

OSS:

# Get memories from a specific agent session: entity IDs combined in filters
m.search("query", filters={
    "user_id": "alice",
    "agent_id": "chatbot",
    "run_id": "session-123",
})

날짜 범위로 필터링:

# Platform only - date filtering
client.search("recent memories", filters={
    "AND": [
        {"user_id": "alice"},
        {"created_at": {"gte": "2024-07-01"}}
    ]
})

카테고리로 필터링:

# Platform only - category filtering
client.search("preferences", filters={
    "AND": [
        {"user_id": "alice"},
        {"categories": {"contains": "food"}}
    ]
})

검색을 개선하는 팁

  • 자연어 사용: Mem0는 의도를 이해하므로 찾는 내용을 자연스럽게 설명하세요.
  • 사용자 ID로 범위 지정: 관련 메모리로 검색 범위를 좁히도록 항상 user_id를 지정하세요.
    • Platform API: filters={"user_id": "alice"}를 사용합니다.
    • OSS: filters={"user_id": "alice"}를 사용합니다(v3에서는 user_id를 최상위 kwarg로 전달하면 ValueError가 발생합니다).
  • 필터 결합: AND/OR 로직으로 정밀한 쿼리를 만듭니다(Platform).
  • 와일드카드 필터 고려: 더 넓게 일치시키려면 와일드카드 필터(예: run_id: "*")를 사용하세요.
  • 매개변수 조정: 결과 수는 top_k로, 관련성 기준은 threshold로 조정합니다.
  • 재순위화 활성화: 리랭커가 구성되어 있으면 rerank=True를 사용하세요(기본값은 False).
팁

MCP 대안: Mem0 MCP를 쓰면 AI 에이전트가 필요할 때 스스로 메모리를 검색할 수 있습니다.

자세한 내용

필터 로직, 비교 연산자, 선택적 검색 매개변수의 전체 목록은 메모리 검색 API 레퍼런스를 참고하세요.

실제로 적용하기

  • 메모리 추가 가이드를 다시 살펴보고, 나중에 조회할 컨텍스트가 제대로 저장되는지 확인하세요.
  • 정밀도를 높이려면 고급 조회에서 리랭커와 필터를 구성하세요.

실제 예시 보기

  • Mem0를 사용한 지원 수신함은 리랭커를 사용한 범위 지정 검색을 보여줍니다.
  • Mem0를 사용한 Tavily 검색은 하이브리드 검색의 실제 동작을 보여줍니다.
메모리 검색 API모든 필터 연산자와 매개변수를 담은 전체 API 레퍼런스입니다.
지원 수신함 쿡북범위 지정 검색과 재순위화로 완전한 지원 시스템을 구축합니다.
