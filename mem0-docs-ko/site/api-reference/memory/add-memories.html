메모리 추가

V3 추가 전용 파이프라인으로 사실, 메시지, 메타데이터를 사용자 메모리 저장소에 추가합니다. 비동기로 처리하고 이벤트로 추적합니다.

POST /v3/memories/add/

기본 URL: https://api.mem0.ai/

Add memories (V3)

Extract and store memories from a conversation using the V3 additive pipeline. Entity IDs (`user_id` / `agent_id` / `run_id`) are accepted at the top level. At least one entity ID is required so the memory is scoped to a session.

코드 예시

cURL

curl -X POST https://api.mem0.ai/v3/memories/add/ \
  -H "Authorization: Token <api-key>" \
  -H "Content-Type: application/json" \
  -d '{
    "messages": [
      {"role": "user", "content": "I just moved to San Francisco from New York."},
      {"role": "assistant", "content": "Got it, I\u0027ll update your location."}
    ],
    "user_id": "alice"
  }'

Python

from mem0 import MemoryClient

client = MemoryClient(api_key="your-api-key")

result = client.add(
    messages=[
        {"role": "user", "content": "I just moved to San Francisco from New York."},
        {"role": "assistant", "content": "Got it, I'll update your location."}
    ],
    user_id="alice",
)
print(result)

JavaScript

import MemoryClient from "mem0ai";

const client = new MemoryClient({ apiKey: "your-api-key" });

const result = await client.add(
  [
    { role: "user", content: "I just moved to San Francisco from New York." },
    { role: "assistant", content: "Got it, I'll update your location." },
  ],
  { userId: "alice" }
);
console.log(result);

V3 추가 전용 파이프라인을 사용해 대화에서 메모리를 추출하고 저장합니다. 이 엔드포인트는 단일 패스 ADD 전용 추출을 사용합니다. 즉, LLM을 한 번만 호출하며 UPDATE/DELETE는 없습니다. 메모리는 시간이 지나면서 쌓이고, 덮어쓰이지 않습니다.

엔드포인트

  • 메서드: POST
  • URL: /v3/memories/add/
  • Content-Type: application/json

처리는 비동기로 진행됩니다. 응답은 GET /v1/event/{event_id}/로 폴링할 수 있는 event_id를 반환합니다.

요청 본문

Mem0가 메모리를 추출할 대화 메시지를 제공합니다. 메모리를 세션 범위로 지정하려면 엔터티 ID(user_id, agent_id, app_id, run_id)가 하나 이상 있어야 합니다. 엔터티 ID는 최상위 수준에서 받습니다.

Basic request

{
  "user_id": "alice",
  "messages": [
    { "role": "user", "content": "I moved to Austin last month." }
  ],
  "metadata": {
    "source": "onboarding_form"
  }
}

공통 필드

필드타입필수설명
messagesarray예Mem0가 메모리를 추출할 대화 턴입니다. 각 객체에는 role과 content가 있어야 합니다.
user_idstring아니요*메모리를 사용자와 연결합니다.
agent_idstring아니요*메모리를 에이전트와 연결합니다.
run_idstring아니요*메모리를 실행과 연결합니다.
app_idstring아니요*메모리를 앱과 연결합니다.
metadataobject선택사용자 지정 키/값 메타데이터입니다(예: {"topic": "preferences"}).
inferboolean (기본값 true)선택false로 설정하면 추론을 건너뛰고 제공한 텍스트를 그대로 저장합니다.
expiration_datestring선택YYYY-MM-DD 형식의 날짜입니다. 메모리는 이 날짜까지 표시되고, 날짜가 지나면 기본적으로 숨겨집니다.

* 엔터티 ID(user_id, agent_id, app_id, run_id)가 하나 이상 필요합니다.

응답

요청은 백그라운드 처리 대기열에 들어갑니다. 응답에는 상태 추적용 event_id가 포함됩니다.

200 response

{
  "event_id": "evt-uuid",
  "status": "PENDING"
}

400 response

{
  "error": "400 Bad Request",
  "details": {
    "message": "Invalid input data. Please refer to the memory creation documentation at https://docs.mem0.ai/platform/quickstart#4-1-create-memories for correct formatting and required fields."
  }
}
안내

GET /v1/event/{event_id}/로 이벤트 상태를 폴링하세요. 처리가 끝나면 상태는 SUCCEEDED 또는 FAILED가 됩니다.

안내

expiration_date가 있는 메모리는 만료 후에도 저장된 상태로 남습니다. 검색과 전체 조회에서는 기본적으로 숨겨지며, 포함하려면 show_expired: true를 전달하세요.

안내

Python은 expiration_date를, TypeScript는 expirationDate를 사용합니다.
